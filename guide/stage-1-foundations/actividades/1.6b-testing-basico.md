**Duración:** ~50 min

## Por qué esta actividad

Has escrito un transformador de datos en TypeScript (Actividad 1.6). ¿Cómo sabes que funciona correctamente? Ahora lo verificas manualmente — ejecutas el código, miras la consola. Eso no escala. Cuando tu proyecto tenga 50 funciones, no puedes verificar todas a mano cada vez que cambias algo.

Un **test unitario** verifica automáticamente que una función produce el resultado esperado. Lo escribes una vez y lo puedes ejecutar miles de veces. Si mañana cambias tu transformador y un test falla, sabes exactamente qué se rompió — sin abrir el navegador.

|---|---|
| **Requiere** | Actividad 1.6 completada (proyecto TypeScript con funciones de transformación) |

## Antes de empezar

Necesitas tener completada la **Actividad 1.6** — un proyecto TypeScript con al menos una función que transforma datos (tu transformador).

Necesitas tener Node.js y npm funcionando (verificado en la Actividad 1.0). Si ejecutas `npm --version` en la terminal y ves un número de versión, estás listo.

Un **test unitario** es una función que:
1. Prepara datos de entrada (**Arrange**)
2. Ejecuta la función que quieres probar (**Act**)
3. Verifica que el resultado es el correcto (**Assert**)

## Práctica paso a paso

> **Pasos:** [1. Instalar Vitest](#paso-1--instalar-vitest) · [2. Primer test](#paso-2--escribir-tu-primer-test) · [3. Más tests](#paso-3--agregar-tests-para-casos-límite) · [4. Ejecutar](#paso-4--ejecutar-y-ver-resultados) · [5. Romper a propósito](#paso-5--romper-algo-y-ver-el-test-fallar)

### Paso 1 — Instalar Vitest

1. Abre la terminal en VS Code (`Ctrl+`` ` o **Terminal → New Terminal**)
2. Asegúrate de estar en la carpeta de tu proyecto de la Actividad 1.6
3. Ejecuta:
   ```bash
   npm install -D vitest
   ```
4. Abre `package.json` y agrega el script de test:
   ```json
   {
     "scripts": {
       "test": "vitest"
     }
   }
   ```

> 💡 **Nota:** `npm install -D` instala Vitest como **dependencia de desarrollo** — solo se usa para testear, no se envía al usuario.

### Paso 2 — Escribir tu primer test

1. Identifica una función pura de tu transformador — una función que recibe datos y retorna un resultado, sin efectos secundarios (sin `fetch`, sin `console.log`, sin modificar variables externas)
2. Crea un archivo de test junto a ella. Si tu función está en `src/transformar.ts`, crea `src/transformar.test.ts`
3. Escribe un test que verifica el caso más simple ("camino feliz"):

```typescript
// src/transformar.test.ts
import { describe, test, expect } from 'vitest';
import { transformar } from './transformar';

describe('transformar', () => {
  test('transforma los datos correctamente con input válido', () => {
    // Arrange — prepara los datos de entrada
    const input = { /* datos de ejemplo que tu función espera */ };

    // Act — ejecuta la función
    const resultado = transformar(input);

    // Assert — verifica el resultado
    expect(resultado).toEqual({ /* lo que esperas obtener */ });
  });
});
```

4. Reemplaza los placeholders con datos reales de tu transformador

### Paso 3 — Agregar tests para casos límite

Agrega al menos 3 tests más que cubran situaciones problemáticas:

```typescript
  test('retorna array vacío cuando no hay datos', () => {
    // Arrange
    const input = [];

    // Act
    const resultado = transformar(input);

    // Assert
    expect(resultado).toEqual([]);
  });

  test('maneja datos con campos faltantes sin crashear', () => {
    const input = { nombre: 'Test' }; // falta un campo esperado

    const resultado = transformar(input);

    expect(resultado).toBeDefined();
    // o expect(() => transformar(input)).not.toThrow();
  });

  test('filtra items inválidos del resultado', () => {
    const input = [
      { id: 1, nombre: 'Válido', precio: 10 },
      { id: 2, nombre: '', precio: -5 },  // inválido
    ];

    const resultado = transformar(input);

    expect(resultado).toHaveLength(1);
    expect(resultado[0].nombre).toBe('Válido');
  });
```

> 💡 **Nota:** Adapta estos ejemplos a tu transformador real. Lo importante es testear: entrada normal, entrada vacía, entrada con datos incorrectos.

### Paso 4 — Ejecutar y ver resultados

1. En la terminal, ejecuta:
   ```bash
   npm test
   ```
2. Vitest se ejecuta y muestra los resultados. Deberías ver algo como:
   ```
    ✓ src/transformar.test.ts (4 tests) 3ms
      ✓ transformar > transforma los datos correctamente con input válido
      ✓ transformar > retorna array vacío cuando no hay datos
      ✓ transformar > maneja datos con campos faltantes sin crashear
      ✓ transformar > filtra items inválidos del resultado

    Test Files  1 passed (1)
         Tests  4 passed (4)
   ```
3. Si algún test falla, Vitest te muestra exactamente qué se esperaba vs qué se obtuvo

### Paso 5 — Romper algo y ver el test fallar

Esto es crucial — necesitas ver un test fallido para entender el valor del testing:

1. Ve a tu función transformadora y **cambia algo a propósito** (por ejemplo, cambia un `>` por un `<`, o elimina un filtro)
2. Ejecuta `npm test` de nuevo
3. Observa cómo el test te dice exactamente qué se rompió:
   ```
    ✗ transformar > filtra items inválidos del resultado
      Expected: 1
      Received: 2
   ```
4. **Revierte tu cambio** — los tests deben pasar de nuevo
5. Esto es lo que los tests hacen por ti: si cambias algo y un test falla, sabes inmediatamente qué se rompió

## Qué puede salir mal

- **"Cannot find module 'vitest'"** → No instalaste Vitest o estás en la carpeta equivocada. Ejecuta `npm install -D vitest` en la carpeta de tu proyecto (donde está `package.json`).
- **"Cannot use import statement outside a module"** → Tu `package.json` necesita `"type": "module"` o tu `tsconfig.json` necesita `"module": "ESNext"`. Vitest maneja TypeScript automáticamente, pero la configuración del proyecto debe ser compatible.
- **El test pasa pero no estoy seguro de que sea correcto** → Haz el Paso 5: rompe algo a propósito. Si el test sigue pasando después de romper el código, tu assertion no está verificando lo correcto.

## Resultado esperado

Al terminar, tu proyecto tiene al menos un archivo `.test.ts` junto al código fuente, con 4+ tests que verifican automáticamente que tu transformador funciona. Ejecutas `npm test` y todos pasan en menos de 1 segundo.

**Criterios de aceptación:**
- [ ] Vitest instalado y `npm test` ejecuta sin errores
- [ ] Al menos 4 tests escritos siguiendo el patrón AAA (cada test tiene Arrange, Act, Assert claramente separados)
- [ ] Los tests cubren: caso feliz, entrada vacía, y al menos un caso límite
- [ ] Los tests se ejecutan en menos de 1 segundo (principio FIRST: Fast)
- [ ] Romper el código a propósito hace fallar al menos un test (los tests detectan errores reales)

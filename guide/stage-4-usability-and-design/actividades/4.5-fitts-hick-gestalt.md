## Por que esta actividad

Las heuristicas de Nielsen (Actividad 4.3) te dicen **que** buscar en una interfaz. Las leyes de Fitts, Hick y los principios Gestalt te explican **por que** ciertos disenos funcionan mejor que otros — son la ciencia detras de la usabilidad.

- **Ley de Fitts**: cuanto mas lejos y mas pequeno es un botón, mas tarda el usuario en hacer clic. Implicacion: las acciones frecuentes deben ser grandes y estar cerca del cursor.
- **Ley de Hick**: cuantas mas opciones ve el usuario, mas tarda en elegir. Implicacion: muestra 5 opciones, no 20. Usa progressive disclosure (revelar opciones gradualmente).
- **Principios Gestalt**: el cerebro agrupa elementos automáticamente por proximidad, similitud, continuidad y cierre. Implicacion: los elementos que estan juntos se perciben como relacionados — usa el espaciado para crear esos grupos.

Aplicar estas leyes al dashboard que construiste en la Actividad 4.4 lo transforma de "funcional" a "intuitivo".

| | |
|---|---|
| **Requiere** | Actividad 4.4 completada (dashboard responsivo) |
| **Aprenderas** | Aplicar la ley de Fitts para dimensionar y posicionar acciones, aplicar la ley de Hick con progressive disclosure, agrupar visualmente con principios Gestalt |
| **Al completar** | Tu dashboard tiene elementos relacionados agrupados visualmente, las acciones frecuentes son las mas accesibles, y las opciones se revelan progresivamente (max 2 niveles) |

## Antes de empezar

Necesitas haber completado la **Actividad 4.4** (dashboard responsivo). Vas a modificar ese dashboard aplicando las 3 leyes.

Un repaso rápido:

- **Fitts en la practica**: un botón de 44x44px a 500px de distancia del cursor es mas difícil de clicar que uno de 48x48px a 100px. Las esquinas y bordes de la pantalla son "infinitamente grandes" para el cursor (el cursor se detiene ahi) — por eso los menus se colocan en los bordes.
- **Hick en la practica**: un dropdown con 50 paises es abrumador. Un campo de busqueda con autocompletado que muestra 5 resultados es rápido. La técnica se llama **progressive disclosure**: mostrar lo minimo y revelar mas solo cuando el usuario lo pide.
- **Gestalt en la practica**: si dos tarjetas estan separadas por 8px y hay 32px hasta la siguiente sección, el cerebro agrupa las dos tarjetas juntas automáticamente. No necesitas un borde o un fondo — el espacio comunica la relación.

## Practica paso a paso

> **Pasos:** [1. Auditar Gestalt](#paso-1--auditar-agrupacion-gestalt) · [2. Aplicar Fitts](#paso-2--aplicar-ley-de-fitts) · [3. Aplicar Hick](#paso-3--aplicar-ley-de-hick) · [4. Verificar touch targets](#paso-4--verificar-touch-targets)

### Paso 1 — Auditar agrupacion (Gestalt)

1. Abre tu dashboard de la Actividad 4.4 en el navegador
2. Entrecierra los ojos (literal — esto difumina los detalles y te deja ver los "bloques" de contenido)
3. Preguntate:
   - ¿Las 4 tarjetas de metricas se perciben como un grupo? Deben tener el mismo `gap` entre ellas y un `gap` mayor respecto a la sección de graficos
   - ¿El grafico de barras y el grafico circular se perciben como un grupo separado de las metricas?
   - ¿Los items del menu lateral se perciben como un grupo?

4. Ajusta el espaciado en tu CSS para reforzar los grupos:

```css
/* Reforzar agrupacion Gestalt con espaciado */
.metrics {
  gap: var(--space-4);               /* 16px entre tarjetas del mismo grupo */
  margin-block-end: var(--space-8);  /* 32px entre secciones — el doble */
}

.charts {
  gap: var(--space-4);
  margin-block-end: var(--space-8);
}

/* Los items del menu son un grupo: espaciado uniforme */
.nav-list {
  display: flex;
  flex-direction: column;
  gap: var(--space-1);  /* 4px entre items — muy juntos = un grupo */
}
```

5. Aplica el principio de **similitud**: las 4 tarjetas de metricas deben verse identicas (misma estructura, mismos tamanos). Si una tarjeta tiene un tamaño o color diferente, se percibe como algo distinto:

```css
/* Similitud: todas las tarjetas de metricas iguales */
.metrics .card {
  display: flex;
  flex-direction: column;
  gap: var(--space-2);
}
```

### Paso 2 — Aplicar ley de Fitts

1. Identifica las **acciones mas frecuentes** en tu dashboard. En un dashboard típico:
   - Ver metricas (solo lectura — no requiere clic)
   - Navegar entre secciones (menu lateral)
   - Acciones como "Exportar", "Filtrar"

2. Las acciones frecuentes deben ser:
   - **Grandes**: minimo 44x44px, idealmente mas grandes para acciones primarias
   - **Cercanas**: colocadas donde el cursor/dedo ya esta

3. Agrega un botón de acción primaria en una posición accesible:

```text
<!-- HTML: agregar dentro de .topbar, despues del h1 -->
<div class="topbar-actions">
  <button class="btn btn--primary">Exportar</button>
</div>
```

```css
.topbar {
  justify-content: space-between; /* Empuja acciones a la derecha */
}

.topbar-actions {
  display: flex;
  gap: var(--space-3);
}

/* El boton de accion primaria es grande y visible */
.btn--primary {
  padding: var(--space-3) var(--space-6);
  min-height: 2.75rem;
  font-weight: var(--font-weight-medium);
}
```

4. El link activo del menu debe ser mas prominente que los demas (Fitts: el area efectiva es mas grande):

```css
.nav-link.active {
  padding-inline-start: var(--space-6);  /* Mas padding = area mas grande */
  font-weight: var(--font-weight-bold);
}
```

### Paso 3 — Aplicar ley de Hick

1. Si tu sidebar tiene mas de 7 items de navegación, agrupa los secundarios bajo un "Mas opciones" que se expande al hacer clic:

```text
<!-- HTML: reemplazar los links extras en el sidebar -->
<li>
  <button class="nav-link nav-expand" aria-expanded="false">
    Mas opciones
  </button>
  <ul class="nav-submenu" hidden>
    <li><a href="#" class="nav-link">Importar datos</a></li>
    <li><a href="#" class="nav-link">Logs</a></li>
    <li><a href="#" class="nav-link">API keys</a></li>
  </ul>
</li>
```

```css
.nav-submenu {
  list-style: none;
  padding-inline-start: var(--space-6);
}

.nav-expand {
  width: 100%;
  text-align: left;
  background: none;
  border: none;
  cursor: pointer;
}
```

```javascript
// Agregar al final de sidebar.js
document.querySelectorAll('.nav-expand').forEach((btn) => {
  btn.addEventListener('click', () => {
    const submenu = btn.nextElementSibling;
    const isExpanded = btn.getAttribute('aria-expanded') === 'true';
    btn.setAttribute('aria-expanded', String(!isExpanded));
    submenu.hidden = isExpanded;
  });
});
```

2. **Progressive disclosure en 2 niveles max**: el usuario ve las opciones principales. Si necesita mas, hace clic en "Mas opciones". No crees sub-sub-menus — 2 niveles es el maximo antes de que el usuario se pierda.

### Paso 4 — Verificar touch targets

1. En Chrome DevTools, usa el responsive mode (Ctrl+Shift+M)
2. Selecciona un dispositivo móvil (iPhone SE, por ejemplo)
3. Haz clic derecho en cada elemento interactivo → Inspect
4. En el panel de Computed, verifica que `height` y `width` son >= 44px
5. Si algun elemento es mas pequeno, agranda su `padding` o `min-height`

Puedes verificar todos los touch targets rapidamente con este snippet en la consola de DevTools:

```javascript
// Pegar en la consola de DevTools para verificar touch targets
document.querySelectorAll('a, button, input, select').forEach((el) => {
  const rect = el.getBoundingClientRect();
  if (rect.width < 44 || rect.height < 44) {
    el.style.outline = '3px solid red';
    console.warn('Touch target < 44px:', el, `${rect.width}x${rect.height}`);
  }
});
```

## Que puede salir mal

- **"No veo diferencia despues de ajustar el espaciado"** → Los cambios de espaciado son sutiles. Compara con una captura de pantalla de antes. El efecto acumulativo de un espaciado consistente se percibe como "se ve profesional" aunque no puedas senalar que cambio exactamente.
- **"El submenu no se abre al hacer clic en 'Mas opciones'"** → Verifica que el snippet de JavaScript esta al final de `sidebar.js` y que el archivo esta enlazado en el HTML. Revisa la consola para errores.
- **"Algunos touch targets siguen siendo menores de 44px"** → Recuerda que `min-height: 2.75rem` no garantiza 44px si el `font-size` base del navegador fue cambiado por el usuario. Usa `min-height: 44px` como fallback si necesitas garantia absoluta.

## Resultado esperado

Tu dashboard tiene un espaciado que crea grupos visuales claros: las metricas estan juntas, separadas de los graficos por un espacio mayor. Las acciones frecuentes (exportar, navegar) son grandes y accesibles. El menu lateral muestra solo las opciones principales, con las secundarias bajo "Mas opciones". En móvil, todos los elementos interactivos son facilmente tocables.

**Criterios de aceptacion:**
- [ ] Elementos relacionados agrupados visualmente con espaciado — las metricas tienen menor gap entre si que respecto a la siguiente sección
- [ ] Progressive disclosure implementado — max 2 niveles de navegación
- [ ] Las acciones frecuentes (botones primarios, links de nav) son las mas grandes y accesibles

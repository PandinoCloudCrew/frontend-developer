**Duracion:** ~60 min

## Por que esta actividad

En la Etapa 1 aprendiste CSS Grid y Flexbox para construir layouts. Ahora vas a aplicar esos conocimientos con una mentalidad de **usabilidad**: no basta con que el dashboard "se vea bien" en escritorio — tiene que ser **funcional** en cada tamaño de pantalla. Un dashboard que muestra una tabla de 6 columnas en un telefono de 320px es tecnicamente responsivo (se adapta al ancho) pero inutilizable (el usuario no puede leer nada).

Mobile-first significa disenar primero para la pantalla mas pequena y luego agregar complejidad conforme hay mas espacio. Los breakpoints no deben ser numeros magicos como 768px o 1024px — deben basarse en el **contenido**: "¿a que ancho esta tarjeta deja de ser legible?" ese es tu breakpoint.

| **Requiere** | Actividades 4.1-4.3 completadas. Saber CSS Grid y Flexbox (Etapa 1, Actividades 1.3 y 1.4) |
| **Aprenderas** | Disenar mobile-first con CSS, definir breakpoints basados en contenido, construir un dashboard con sidebar colapsable, asegurar touch targets de 44x44px en móvil |

## Antes de empezar

Necesitas haber completado las **Actividades 4.1-4.3**. Vas a reutilizar tu `tokens.css` (tipografia, color, espaciado).

Conceptos clave:

- **Mobile-first**: escribir el CSS base para móvil (sin media queries) y luego agregar `@media (min-width: ...)` para pantallas mas grandes. Lo opuesto (desktop-first con `max-width`) genera CSS mas complejo porque estas "quitando" cosas en vez de "agregando".
- **Breakpoints basados en contenido**: en lugar de usar 768px porque "es el tamaño de un iPad", redimensiona tu contenido y observa a que ancho se rompe o se ve mal — ese ancho es tu breakpoint. Podria ser 540px, 680px o 900px — depende de tu contenido.
- **Touch target**: el area tocable de un botón o link. Apple y Google recomiendan un minimo de 44x44px (Apple) o 48x48px (Material Design). En móvil, si el botón es mas pequeno, el usuario tocara el elemento equivocado.

### Paso 3 — Tarjetas con Grid

Las tarjetas de metricas ya estan en un grid de 1 columna (el comportamiento por defecto). Usamos `auto-fill` con `minmax` para que las tarjetas se reorganicen automáticamente:

Agrega al final de `styles.css`:

```css
/* Tarjetas auto-responsivas — sin media query */
.metrics {
  grid-template-columns: repeat(auto-fill, minmax(min(100%, 15rem), 1fr));
}
```

> 💡 **Nota:** `minmax(min(100%, 15rem), 1fr)` significa: cada tarjeta ocupa al menos 15rem, pero nunca mas del 100% del contenedor. Cuando el contenedor es mas ancho, caben mas tarjetas por fila. Esto es responsivo sin media queries.

### Paso 4 — Breakpoint tablet

1. Redimensiona tu navegador. Observa a que ancho las tarjetas se ven bien en 2 columnas y los graficos podrian estar lado a lado. Ese es tu breakpoint (probablemente alrededor de 40rem / 640px).
2. Agrega el media query:

```css
/* ========== Tablet: ~640px ========== */
@media (min-width: 40rem) {
  .charts {
    grid-template-columns: 2fr 1fr;
  }
}
```

### Paso 5 — Breakpoint escritorio

1. Sigue redimensionando. A que ancho tiene sentido mostrar el sidebar permanentemente? Probablemente alrededor de 64rem / 1024px.
2. Agrega:

```css
/* ========== Escritorio: ~1024px ========== */
@media (min-width: 64rem) {
  .layout {
    flex-direction: row;
  }

  .sidebar {
    position: static;
    transform: none;
    width: 16rem;
    flex-shrink: 0;
  }

  .sidebar-toggle {
    display: none; /* No se necesita toggle en escritorio */
  }

  .topbar .sidebar-toggle {
    display: none;
  }

  .main-content {
    flex: 1;
    min-width: 0; /* Evita overflow en flex children */
  }
}
```

### Paso 6 — Touch targets

Verifica que todos los elementos interactivos (botones, links, items del menu) tengan al menos 44x44px en móvil:

```css
/* Touch targets minimos — ya definidos arriba, pero verifica */
.nav-link,
.sidebar-toggle,
.btn {
  min-height: 2.75rem; /* 44px */
  min-width: 2.75rem;
}
```

### Paso 7 — Verificar responsividad

1. Crea `sidebar.js` para el toggle del sidebar en móvil:

```javascript
// sidebar.js — Toggle del sidebar en movil
const sidebar = document.getElementById('sidebar');
const openBtn = document.getElementById('sidebar-open');
const closeBtn = document.getElementById('sidebar-close');

openBtn.addEventListener('click', () => {
  sidebar.classList.add('open');
});

closeBtn.addEventListener('click', () => {
  sidebar.classList.remove('open');
});
```

2. Abre la página en el navegador
3. En DevTools, activa el **responsive mode** (Ctrl+Shift+M en Chrome, o el icono de dispositivos)
4. Redimensiona desde 320px hasta 1920px — la transición debe ser suave:
   - 320px: 1 columna, sidebar oculto, tabla con scroll horizontal
   - ~640px: tarjetas en 2 columnas, graficos lado a lado
   - ~1024px: sidebar permanente a la izquierda

## Que puede salir mal

- **"El sidebar no aparece cuando hago clic en el botón hamburguesa"** → Verifica que el archivo `sidebar.js` esta enlazado en el HTML y que el `id` del sidebar es exactamente `sidebar` (sin mayusculas ni guiones).
- **"La tabla se desborda del contenedor y genera scroll horizontal en toda la página"** → Asegurate de que `.table-wrapper` tiene `overflow-x: auto` y que la tabla esta dentro de ese wrapper. El scroll debe ser solo en la tabla, no en toda la página.
- **"Las tarjetas no se reorganizan al redimensionar"** → Verifica que `.metrics` tiene `grid-template-columns: repeat(auto-fill, minmax(...))`. Si usaste `auto-fit` en lugar de `auto-fill`, el comportamiento es diferente cuando hay pocas tarjetas.
- **"En móvil el sidebar cubre todo pero no puedo cerrarlo"** → El botón de cerrar (`sidebar-close`) debe estar visible dentro del sidebar cuando esta abierto. Verifica que tiene `min-height: 2.75rem` y que no esta oculto por CSS.

## Resultado esperado

Tu dashboard se adapta fluidamente a 3 tamanos de pantalla. En móvil, todo esta en una columna con un botón hamburguesa para el sidebar. En tablet, las tarjetas y graficos se reorganizan en multiples columnas. En escritorio, el sidebar es permanente. La tabla tiene scroll horizontal en móvil. Todos los elementos interactivos son facilmente tocables.

**Criterios de aceptacion:**
- [ ] Breakpoints basados en contenido (no en 768px/1024px exactos) — los valores reflejan cuando tu contenido necesita mas espacio
- [ ] Usable en cada ancho entre 320px y 1920px — redimensionar no rompe nada ni genera scroll horizontal en la página
- [ ] Todo touch target >= 44x44px en móvil — verificable en DevTools midiendo los elementos interactivos

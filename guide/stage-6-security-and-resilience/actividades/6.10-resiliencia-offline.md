## Por que esta actividad

Un usuario en el metro pierde conexion a mitad de un formulario. Otro en una zona rural tiene 2G intermitente. Si tu app depende al 100% de la red, todos ven una pantalla en blanco. La resiliencia offline no requiere que tu app funcione completamente sin internet — para la mayoria de las apps, basta con ser **offline-tolerant**: mostrar datos ya cargados desde cache y encolar acciones de escritura para cuando vuelva la conexion. En esta actividad vas a convertir tu app Angular en una PWA con Service Worker, configurar estrategias de caching para assets y datos, implementar una cola offline con IndexedDB, y verificar todo con el modo offline de DevTools.

## Antes de empezar

Necesitas tener completada la **Actividad 6.9** y tu app corriendo con `ng serve`.

**PWA (Progressive Web App)** es una app web que puede instalarse en el dispositivo y funcionar offline (parcial o totalmente). Angular soporta PWA a traves de `@angular/service-worker`.

**Service Worker** es un script que el navegador ejecuta en un hilo separado. Actua como un proxy entre tu app y la red: intercepta cada peticion HTTP y decide si responder desde cache o ir a la red.

**`ngsw-config.json`** es el archivo de configuracion del Service Worker de Angular. Define que cachear (assets y datos de API) y con que estrategia (prefetch, lazy, freshness, performance).

**IndexedDB** es una base de datos transaccional en el navegador. Es asincrona, soporta objetos JavaScript nativos, y puede manejar cientos de megabytes. La usaras para la cola offline.

**Importante:** El Service Worker solo funciona en **builds de produccion** (`ng build`), no con `ng serve`. Para probar, necesitas servir el build con un servidor HTTP.

### Paso 1 — Agregar soporte PWA

1. En la terminal, dentro de tu proyecto:
   ```bash
   ng add @angular/pwa
   ```
   Esto genera:
   - `ngsw-config.json` — configuracion del Service Worker
   - `manifest.webmanifest` — metadatos de la PWA (nombre, iconos, colores)
   - Iconos por defecto en `src/assets/icons/`
   - Registro del Service Worker en `app.config.ts`

2. Verifica que el Service Worker esta registrado en `src/app/app.config.ts`:
   ```typescript
   import { provideServiceWorker } from '@angular/service-worker';
   import { isDevMode } from '@angular/core';

   export const appConfig = {
     providers: [
       // ... tus providers existentes
       provideServiceWorker('ngsw-worker.js', {
         enabled: !isDevMode(),
         registrationStrategy: 'registerWhenStable:30000',
       }),
     ],
   };
   ```

> 💡 **Nota:** `enabled: !isDevMode()` desactiva el Service Worker en desarrollo. El caching agresivo haria que tus cambios de codigo no se reflejen al recargar. Solo se activa en builds de produccion.

### Paso 2 — Configurar caching de assets

1. Abre `ngsw-config.json` (en la raiz del proyecto). La configuracion por defecto ya incluye un `assetGroup` para el app shell:
   ```json
   {
     "$schema": "./node_modules/@angular/service-worker/config/schema.json",
     "index": "/index.html",
     "assetGroups": [
       {
         "name": "app",
         "installMode": "prefetch",
         "resources": {
           "files": [
             "/favicon.ico",
             "/index.html",
             "/manifest.webmanifest",
             "/*.css",
             "/*.js"
           ]
         }
       },
       {
         "name": "assets",
         "installMode": "lazy",
         "updateMode": "prefetch",
         "resources": {
           "files": [
             "/assets/**",
             "/*.(svg|cur|jpg|jpeg|png|apng|webp|avif|gif|otf|ttf|woff|woff2)"
           ]
         }
       }
     ]
   }
   ```
2. Entiende las dos estrategias:
   - **`"installMode": "prefetch"`** — descarga y cachea estos archivos inmediatamente al instalar el Service Worker. Ideal para archivos criticos (HTML, CSS, JS del app shell).
   - **`"installMode": "lazy"`** — cachea estos archivos solo cuando el usuario los solicita por primera vez. Ideal para imagenes y assets que no todas las paginas usan.

### Paso 3 — Configurar caching de datos de API

1. Agrega un `dataGroup` en `ngsw-config.json`, despues del array `assetGroups`:
   ```json
   {
     "assetGroups": [ ... ],
     "dataGroups": [
       {
         "name": "api-freshness",
         "urls": ["/api/**"],
         "cacheConfig": {
           "strategy": "freshness",
           "maxSize": 50,
           "maxAge": "1h",
           "timeout": "5s"
         }
       }
     ]
   }
   ```
2. Entiende la configuracion:
   - **`"strategy": "freshness"`** — network-first. Intenta la red; si no responde en `timeout` segundos, usa el cache. Ideal para datos que cambian frecuentemente.
   - **`"strategy": "performance"`** — cache-first. Sirve del cache; actualiza en background. Ideal para datos que cambian poco.
   - **`"maxAge": "1h"`** — los datos cacheados expiran despues de 1 hora.
   - **`"timeout": "5s"`** — si la red no responde en 5 segundos, usa el cache.
   - **`"maxSize": 50`** — maximo 50 entradas en el cache para este data group.

### Paso 4 — Implementar cola offline con IndexedDB

1. Instala la libreria `idb` para trabajar con IndexedDB:
   ```bash
   npm install idb
   ```
2. Genera el servicio de cola offline:
   ```bash
   ng generate service services/offline-queue
   ```
3. En `src/app/services/offline-queue.service.ts`:
   ```typescript
   import { Injectable, signal, inject } from '@angular/core';
   import { HttpClient } from '@angular/common/http';
   import { openDB, IDBPDatabase } from 'idb';
   import { firstValueFrom } from 'rxjs';

   interface QueuedAction {
     id: string;
     method: 'POST' | 'PUT' | 'DELETE';
     url: string;
     body?: unknown;
     timestamp: number;
   }

   @Injectable({ providedIn: 'root' })
   export class OfflineQueueService {
     private http = inject(HttpClient);
     private db!: IDBPDatabase;
     pendientes = signal(0);

     async inicializar(): Promise<void> {
       this.db = await openDB('offline-queue', 1, {
         upgrade(db) {
           db.createObjectStore('acciones', { keyPath: 'id' });
         },
       });
       await this.actualizarConteo();
     }

     async encolar(action: Omit<QueuedAction, 'id' | 'timestamp'>): Promise<void> {
       await this.db.put('acciones', {
         ...action,
         id: crypto.randomUUID(),
         timestamp: Date.now(),
       });
       await this.actualizarConteo();
     }

     async reproducir(): Promise<{ exitos: number; fallos: number }> {
       const acciones = await this.db.getAll('acciones');
       acciones.sort((a, b) => a.timestamp - b.timestamp);

       let exitos = 0;
       let fallos = 0;

       for (const accion of acciones) {
         try {
           await firstValueFrom(
             this.http.request(accion.method, accion.url, { body: accion.body })
           );
           await this.db.delete('acciones', accion.id);
           exitos++;
         } catch {
           fallos++;
           break; // Detener al primer fallo para mantener el orden
         }
       }

       await this.actualizarConteo();
       return { exitos, fallos };
     }

     private async actualizarConteo(): Promise<void> {
       const count = await this.db.count('acciones');
       this.pendientes.set(count);
     }
   }
   ```

> 💡 **Nota:** La cola se detiene al primer fallo (`break`) para mantener el orden de las operaciones. Si la accion 3 depende de que la accion 2 se haya ejecutado, no puedes saltar la 2 porque fallo.

### Paso 5 — Sincronizar al volver online

1. Genera un componente que muestre el estado de la conexion y la cola:
   ```bash
   ng generate component offline-status
   ```
2. En `src/app/offline-status/offline-status.component.ts`:
   ```typescript
   import { Component, inject, OnInit, OnDestroy, signal } from '@angular/core';
   import { OfflineQueueService } from '../services/offline-queue.service';

   @Component({
     selector: 'app-offline-status',
     standalone: true,
     template: `
       @if (!isOnline()) {
         <div class="offline-banner">
           Sin conexion — las acciones se guardaran localmente
           @if (queue.pendientes() > 0) {
             ({{ queue.pendientes() }} pendientes)
           }
         </div>
       }
       @if (isOnline() && queue.pendientes() > 0) {
         <div class="sync-banner">
           Conexion restaurada —
           <button (click)="sincronizar()">
             Sincronizar {{ queue.pendientes() }} acciones pendientes
           </button>
         </div>
       }
     `,
     styles: [`
       .offline-banner {
         background: #f59e0b; color: #1e1e1e;
         padding: 0.5rem 1rem; text-align: center; font-size: 0.875rem;
       }
       .sync-banner {
         background: #3b82f6; color: white;
         padding: 0.5rem 1rem; text-align: center; font-size: 0.875rem;
       }
       button {
         background: white; color: #3b82f6; border: none;
         padding: 0.25rem 0.75rem; border-radius: 4px; cursor: pointer;
         margin-left: 0.5rem;
       }
     `],
   })
   export class OfflineStatusComponent implements OnInit, OnDestroy {
     queue = inject(OfflineQueueService);
     isOnline = signal(navigator.onLine);

     private onlineHandler = () => this.isOnline.set(true);
     private offlineHandler = () => this.isOnline.set(false);

     ngOnInit() {
       this.queue.inicializar();
       window.addEventListener('online', this.onlineHandler);
       window.addEventListener('offline', this.offlineHandler);
     }

     ngOnDestroy() {
       window.removeEventListener('online', this.onlineHandler);
       window.removeEventListener('offline', this.offlineHandler);
     }

     async sincronizar() {
       const resultado = await this.queue.reproducir();
       if (resultado.fallos > 0) {
         console.warn(`Sincronizacion parcial: ${resultado.exitos} exitos, ${resultado.fallos} fallos`);
       }
     }
   }
   ```
3. Agrega `<app-offline-status />` al inicio del template de `app.component.ts` (antes del contenido principal). Importa `OfflineStatusComponent` en el array `imports`
4. Para usar la cola en tus servicios existentes, verifica la conexion antes de enviar:
   ```typescript
   // Ejemplo en un servicio que crea un post
   async crearPost(titulo: string, contenido: string): Promise<void> {
     const body = { titulo, contenido };

     if (navigator.onLine) {
       await firstValueFrom(this.http.post('/api/posts', body));
     } else {
       await this.offlineQueue.encolar({
         method: 'POST',
         url: '/api/posts',
         body,
       });
     }
   }
   ```

### Paso 6 — Probar en modo offline

El Service Worker solo funciona con un build de produccion. Sigue estos pasos:

1. Genera el build de produccion:
   ```bash
   ng build
   ```
2. Sirve el build con un servidor HTTP local:
   ```bash
   npx http-server dist/TU-PROYECTO/browser -p 4200
   ```
   (Reemplaza `TU-PROYECTO` con el nombre de tu proyecto Angular)
3. Abre `http://localhost:4200` en Chrome
4. Abre DevTools → Application → Service Workers
   - Verifica que el Service Worker esta registrado y activo
5. **Probar carga offline de assets:**
   - En DevTools → Network, marca la casilla **Offline**
   - Recarga la pagina (`Ctrl+R` / `Cmd+R`)
   - **La app debe cargar** — HTML, CSS y JS se sirven desde el cache del Service Worker
6. **Probar cola offline:**
   - Con el modo offline activo, ejecuta una accion que normalmente haria un POST (crear un post, guardar datos)
   - Verifica que aparece el banner "Sin conexion" y que la accion se encolo
   - Abre DevTools → Application → IndexedDB → `offline-queue` → `acciones`
   - Debes ver la accion encolada con su URL, method y timestamp
7. **Probar sincronizacion:**
   - Desmarca **Offline** en DevTools → Network
   - Debe aparecer el banner "Conexion restaurada" con el boton de sincronizar
   - Haz click en "Sincronizar"
   - Verifica en Network que las peticiones encoladas se envian
   - Verifica en IndexedDB que la tabla `acciones` esta vacia

## Que puede salir mal

- **"El Service Worker no se registra"** → El Service Worker solo funciona con `ng build`, no con `ng serve`. Verifica que estas sirviendo el build de produccion con `http-server` o similar, no con `ng serve`.
- **"La pagina no carga offline — dice 'No internet'"** → Necesitas haber visitado la pagina al menos una vez con conexion para que el Service Worker cache los assets. La primera visita siempre requiere red.
- **"IndexedDB no aparece en DevTools"** → Haz click en el icono de refresh en el panel de IndexedDB (DevTools → Application → IndexedDB → click en el icono circular). A veces no se actualiza automaticamente.
- **"Las acciones encoladas fallan al sincronizar"** → Si tu API no esta corriendo (porque `ng serve` esta apagado y solo tienes `http-server`), las peticiones a `/api/*` fallaran. Necesitas una API real o un `json-server` corriendo simultaneamente.

## Resultado esperado

Al terminar, tu app es una PWA que carga sin conexion (assets desde cache), muestra datos cacheados de la API, y encola acciones del usuario en IndexedDB cuando esta offline. Al volver la conexion, el usuario puede sincronizar las acciones pendientes. El Service Worker esta registrado y activo en DevTools.

**Criterios de aceptacion:**
- [ ] Service Worker registrado y activo (verificado en DevTools → Application → Service Workers)
- [ ] La app carga offline — HTML, CSS, JS servidos desde cache (verificado activando modo offline y recargando)
- [ ] Las acciones del usuario se encolan en IndexedDB cuando esta offline (verificado en DevTools → Application → IndexedDB)
- [ ] Las acciones encoladas se sincronizan al volver online (verificado desmarcando offline y haciendo click en "Sincronizar")

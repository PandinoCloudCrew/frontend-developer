## Por que esta actividad

La forma en que guardas los tokens de autenticación determina la seguridad de todos tus usuarios. Guardar un token en `localStorage` es como dejar la llave de tu casa debajo del tapete — cualquier script de terceros (analytics, ads, un paquete npm comprometido) puede leerlo. Un atacante con acceso al token puede hacer peticiones como si fuera el usuario: ver sus datos, cambiar su contrasena, hacer compras. **OAuth + PKCE** con tokens en memoria y cookies HttpOnly es el estandar actual de seguridad.

## Antes de empezar

Necesitas tener completada la **Actividad 6.2** y entender como Angular hace HTTP requests con `HttpClient`.

**Autenticación** es el proceso de verificar que un usuario es quien dice ser (login). **Autorizacion** es decidir que puede hacer ese usuario (permisos).

**OAuth** es un protocolo que permite que tu app deje la autenticación a un proveedor externo (Google, GitHub, Auth0). El usuario introduce su contrasena en el proveedor (nunca en tu app), y el proveedor te da un **token** que confirma la identidad.

**PKCE (Proof Key for Code Exchange)** es una extensión de OAuth disenada para SPAs (Single Page Applications). Sin PKCE, un atacante podria interceptar el código de autorizacion y usarlo para obtener un token. PKCE agrega un "secreto temporal" que solo tu app conoce.

**Access token:** un texto que tu app envia con cada petición HTTP para demostrar que el usuario esta autenticado. Dura poco (15-30 minutos).

**Refresh token:** un texto que permite obtener un nuevo access token sin que el usuario tenga que hacer login otra vez. Dura mas (dias/semanas).

**HttpOnly cookie:** una cookie que el navegador envia automáticamente con las peticiones pero que JavaScript **no puede leer**. Es invisible para scripts maliciosos.

### Paso 1 — Entender el flujo de autenticación

Antes de escribir código, entiende el flujo completo:

```
1. Usuario hace click en "Login"
2. Tu app redirige al proveedor OAuth (ej: Auth0, Google)
3. El usuario ingresa sus credenciales EN EL PROVEEDOR (nunca en tu app)
4. El proveedor redirige de vuelta a tu app con un "codigo de autorizacion"
5. Tu app intercambia ese codigo por un access token + refresh token
6. El access token se guarda EN MEMORIA (variable de JavaScript)
7. El refresh token se guarda en una COOKIE HttpOnly (el servidor lo configura)
8. Cada peticion HTTP lleva el access token en el header Authorization
9. Cuando el access token expira, el refresh token obtiene uno nuevo automaticamente
```

### Paso 2 — Crear el servicio de autenticación

1. Crea el servicio:
   ```bash
   ng generate service servicios/auth
   ```
2. Implementa el servicio de autenticacion:

::: code-group

```typescript [Angular]
// src/app/servicios/auth.service.ts
import { Injectable, signal, computed, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Router } from '@angular/router';
import { tap, catchError, of } from 'rxjs';

interface TokenResponse {
  access_token: string;
  expires_in: number;
}

@Injectable({ providedIn: 'root' })
export class AuthService {
  private http = inject(HttpClient);
  private router = inject(Router);

  // El access token se guarda en MEMORIA — no en localStorage
  private accessToken = signal<string | null>(null);
  private tokenExpiraEn = signal<number>(0);

  estaAutenticado = computed(() => {
    const token = this.accessToken();
    const ahora = Date.now();
    return token !== null && ahora < this.tokenExpiraEn();
  });

  obtenerToken(): string | null {
    return this.accessToken();
  }

  iniciarLogin() {
    const codeVerifier = this.generarCodeVerifier();
    sessionStorage.setItem('pkce_code_verifier', codeVerifier);

    const authUrl = new URL('https://tu-auth-provider.com/authorize');
    authUrl.searchParams.set('client_id', 'TU_CLIENT_ID');
    authUrl.searchParams.set('redirect_uri', window.location.origin + '/callback');
    authUrl.searchParams.set('response_type', 'code');
    authUrl.searchParams.set('scope', 'openid profile email');
    authUrl.searchParams.set('code_challenge', codeVerifier);
    authUrl.searchParams.set('code_challenge_method', 'S256');

    window.location.href = authUrl.toString();
  }

  manejarCallback(code: string) {
    const codeVerifier = sessionStorage.getItem('pkce_code_verifier') ?? '';
    sessionStorage.removeItem('pkce_code_verifier');

    return this.http.post<TokenResponse>('/api/auth/token', {
      code,
      code_verifier: codeVerifier,
      redirect_uri: window.location.origin + '/callback',
    }).pipe(
      tap(respuesta => {
        this.accessToken.set(respuesta.access_token);
        this.tokenExpiraEn.set(Date.now() + respuesta.expires_in * 1000);
        this.router.navigate(['/']);
      }),
    );
  }

  renovarToken() {
    return this.http.post<TokenResponse>('/api/auth/refresh', {}, {
      withCredentials: true,
    }).pipe(
      tap(respuesta => {
        this.accessToken.set(respuesta.access_token);
        this.tokenExpiraEn.set(Date.now() + respuesta.expires_in * 1000);
      }),
      catchError(() => {
        this.cerrarSesion();
        return of(null);
      }),
    );
  }

  cerrarSesion() {
    this.accessToken.set(null);
    this.tokenExpiraEn.set(0);
    this.router.navigate(['/login']);
  }

  private generarCodeVerifier(): string {
    const array = new Uint8Array(32);
    crypto.getRandomValues(array);
    return Array.from(array, byte =>
      byte.toString(36).padStart(2, '0')
    ).join('').substring(0, 43);
  }
}
```

### Paso 3 — Guardar el access token en memoria

El punto clave de seguridad ya esta en el código del Paso 2, pero entiende por que:

1. `private accessToken = signal<string | null>(null)` — es una variable de JavaScript, no un valor en localStorage
2. Si el usuario recarga la página, **el token se pierde** — eso es intencional
3. La renovacion automática (Paso 5) obtiene un token nuevo usando el refresh token que esta en la cookie HttpOnly
4. **Nunca hagas esto:**
   ```typescript
   // MAL — cualquier script puede leer esto
   localStorage.setItem('token', respuesta.access_token);

   // MAL — sessionStorage tambien es accesible por scripts
   sessionStorage.setItem('token', respuesta.access_token);
   ```

### Paso 4 — Crear un interceptor HTTP

Un interceptor agrega automáticamente el token a todas las peticiones HTTP:

1. Agrega el token a todas las peticiones HTTP automaticamente:

::: code-group

```typescript [Angular]
// src/app/servicios/auth.interceptor.ts
import { HttpInterceptorFn } from '@angular/common/http';
import { inject } from '@angular/core';
import { AuthService } from './auth.service';

export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const authService = inject(AuthService);
  const token = authService.obtenerToken();

  if (token) {
    const reqConAuth = req.clone({
      setHeaders: {
        Authorization: `Bearer ${token}`,
      },
    });
    return next(reqConAuth);
  }

  return next(req);
};

// En app.config.ts:
// provideHttpClient(withInterceptors([authInterceptor])),
```

```typescript [React]
// src/auth/fetchConAuth.ts — Wrapper de fetch que agrega el token
import { useAuth } from './AuthContext';

// Funcion wrapper para fetch
export function crearFetchConAuth(obtenerToken: () => string | null) {
  return async function fetchConAuth(
    url: string,
    options: RequestInit = {},
  ): Promise<Response> {
    const token = obtenerToken();
    const headers = new Headers(options.headers);
    if (token) {
      headers.set('Authorization', `Bearer ${token}`);
    }
    return fetch(url, { ...options, headers });
  };
}
```

### Paso 5 — Implementar renovacion automática

1. Crea un interceptor que detecte respuestas 401 y renueve el token automáticamente:
   ```typescript
   // src/app/servicios/token-refresh.interceptor.ts
   import { HttpInterceptorFn } from '@angular/common/http';
   import { inject } from '@angular/core';
   import { catchError, switchMap, throwError } from 'rxjs';
   import { AuthService } from './auth.service';

   export const tokenRefreshInterceptor: HttpInterceptorFn = (req, next) => {
     const authService = inject(AuthService);

     return next(req).pipe(
       catchError(error => {
         if (error.status === 401 && !req.url.includes('/auth/refresh')) {
           return authService.renovarToken().pipe(
             switchMap(() => {
               const nuevoToken = authService.obtenerToken();
               const reqRenovada = req.clone({
                 setHeaders: {
                   Authorization: `Bearer ${nuevoToken}`,
                 },
               });
               return next(reqRenovada);
             }),
           );
         }
         return throwError(() => error);
       }),
     );
   };
   ```
2. Registra este interceptor despues del `authInterceptor` en `app.config.ts`:
   ```typescript
   provideHttpClient(withInterceptors([authInterceptor, tokenRefreshInterceptor])),
   ```

### Paso 6 — Verificar que no hay tokens en storage

1. Haz login en tu app (o simula un login guardando un token en memoria)
2. Abre Chrome DevTools → Application
3. En el panel izquierdo, verifica:
   - **Local Storage:** haz click en tu dominio. **No debe haber ningun token** (ni `access_token`, ni `token`, ni `jwt`, ni `auth`)
   - **Session Storage:** igual, no debe haber tokens (el `pkce_code_verifier` es temporal y se elimina despues del callback)
   - **Cookies:** si hay una cookie de refresh token, verifica que tiene la bandera **HttpOnly** (no accesible por JavaScript)
4. Para verificar que JavaScript no puede acceder al refresh token:
   - En Console, escribe: `document.cookie`
   - Las cookies HttpOnly **no aparecen** en el resultado

## Que puede salir mal

- **"Despues de recargar la página, pierdo la sesion"** → Eso es correcto con tokens en memoria. La solución es la renovacion automática: al cargar la app, intenta renovar el token usando el refresh token en la cookie. Agrega una llamada a `renovarToken()` en el `AppComponent.ngOnInit()`.
- **"No puedo probar OAuth sin un servidor backend"** → Es correcto — OAuth requiere un backend que maneje los tokens. Para esta actividad, puedes simular el flujo guardando un token de prueba en el signal y verificando que NO esta en localStorage. En produccion, usa un servicio como Auth0 que provee el backend.
- **"La cookie no tiene la bandera HttpOnly"** → HttpOnly se configura **en el servidor**, no en el frontend. El header de respuesta debe incluir: `Set-Cookie: refresh_token=xxx; HttpOnly; Secure; SameSite=Strict`.

## Resultado esperado

Al terminar, tu app maneja autenticación con el patrón seguro: access token en memoria (no en storage), refresh token en cookie HttpOnly, y renovacion automática cuando el token expira. No hay tokens visibles en localStorage ni sessionStorage.

**Criterios de aceptacion:**
- [ ] Cero tokens visibles en localStorage/sessionStorage (verificado en DevTools → Application)
- [ ] Access token almacenado en una variable de JavaScript (signal/variable), no en storage
- [ ] Refresh token configurado como cookie HttpOnly (o documentado como requerimiento del backend)
- [ ] Renovacion automática: cuando el access token expira, se obtiene uno nuevo sin que el usuario haga login de nuevo

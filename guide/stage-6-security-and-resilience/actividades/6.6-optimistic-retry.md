## Por que esta actividad

Cuando un usuario da "like" a un post y tiene que esperar 2 segundos a que el servidor confirme, la app se siente lenta e insegura — el usuario no sabe si el click funciono. Con **optimistic updates**, la UI se actualiza inmediatamente como si todo hubiera salido bien, y si el servidor falla, se revierte al estado anterior. El usuario percibe velocidad instantanea. Pero optimismo sin plan de recuperacion es peor que no tenerlo: si la operación falla y el like desaparece sin explicacion, el usuario se confunde. Por otro lado, las redes fallan — pero muchas veces el fallo es temporal. Un **retry con exponential backoff** reintenta la petición automáticamente con intervalos crecientes (1s, 2s, 4s), dando tiempo al servidor para recuperarse sin bombardearlo con peticiones.

## Antes de empezar

Necesitas tener completada la **Actividad 6.5** y una app Angular con al menos un componente que haga peticiones HTTP.

**Optimistic update** significa actualizar la UI antes de que el servidor confirme. Es como cuando envias un mensaje en WhatsApp: aparece inmediatamente con un check gris (enviado localmente), y despues se confirma con doble check azul (confirmado por el servidor). Si falla, te avisa.

**Rollback** es revertir la UI al estado anterior cuando el servidor responde con error. Sin rollback, el usuario ve datos que no existen en el servidor — inconsistencia peligrosa.

**Exponential backoff** es una estrategia de retry donde cada reintento espera el doble que el anterior: 1 segundo, 2 segundos, 4 segundos. Esto evita saturar un servidor que ya esta con problemas (si 1000 usuarios reintentan al mismo tiempo cada 100ms, el servidor colapsa).

### Paso 1 — Crear el servicio de likes

1. Genera un servicio para manejar la lógica de likes:
   ```bash
   ng generate service services/like
   ```
2. En `src/app/services/like.service.ts`:
   ```typescript
   import { Injectable, inject } from '@angular/core';
   import { HttpClient } from '@angular/common/http';
   import { retry, timer } from 'rxjs';

   @Injectable({ providedIn: 'root' })
   export class LikeService {
     private http = inject(HttpClient);

     toggleLike(postId: string) {
       return this.http.post<{ liked: boolean }>(
         `/api/posts/${postId}/like`,
         {}
       );
     }
   }
   ```

### Paso 2 — Implementar optimistic update con rollback

1. Genera un componente para un post con botón de like:
   ```bash
   ng generate component post-card
   ```
2. En `src/app/post-card/post-card.component.ts`:
   ```typescript
   import { Component, input, signal, inject } from '@angular/core';
   import { LikeService } from '../services/like.service';

   @Component({
     selector: 'app-post-card',
     standalone: true,
     template: `
       <article class="post-card">
         <h3>{{ title() }}</h3>
         <p>{{ content() }}</p>
         <button
           (click)="toggleLike()"
           [class.liked]="liked()"
           [disabled]="loading()"
         >
           {{ liked() ? '❤️' : '🤍' }}
           {{ likeCount() }}
         </button>
         @if (error()) {
           <span class="error-inline">{{ error() }}</span>
         }
       </article>
     `,
     styles: [`
       .post-card { padding: 1rem; border: 1px solid #e2e8f0; border-radius: 8px; }
       button { cursor: pointer; border: none; background: none; font-size: 1.25rem; }
       button.liked { transform: scale(1.1); }
       button:disabled { opacity: 0.5; cursor: not-allowed; }
       .error-inline { color: #e74c3c; font-size: 0.875rem; margin-left: 0.5rem; }
     `],
   })
   export class PostCardComponent {
     private likeService = inject(LikeService);

     postId = input.required<string>();
     title = input.required<string>();
     content = input.required<string>();
     initialLiked = input<boolean>(false);
     initialLikeCount = input<number>(0);

     liked = signal(false);
     likeCount = signal(0);
     loading = signal(false);
     error = signal('');

     ngOnInit() {
       this.liked.set(this.initialLiked());
       this.likeCount.set(this.initialLikeCount());
     }

     toggleLike() {
       // 1. Guardar estado anterior (para rollback)
       const previousLiked = this.liked();
       const previousCount = this.likeCount();

       // 2. Optimistic update — actualizar UI inmediatamente
       const newLiked = !previousLiked;
       this.liked.set(newLiked);
       this.likeCount.set(previousCount + (newLiked ? 1 : -1));
       this.error.set('');
       this.loading.set(true);

       // 3. Enviar al servidor
       this.likeService.toggleLike(this.postId()).subscribe({
         next: () => {
           // Servidor confirmo — la UI ya esta actualizada
           this.loading.set(false);
         },
         error: () => {
           // 4. Rollback — revertir al estado anterior
           this.liked.set(previousLiked);
           this.likeCount.set(previousCount);
           this.loading.set(false);
           this.error.set('No se pudo guardar. Intenta de nuevo.');
         },
       });
     }
   }
   ```

> 💡 **Nota:** El patrón es siempre el mismo: (1) guardar estado anterior, (2) actualizar UI optimistamente, (3) enviar al servidor, (4) rollback si falla. El orden importa — la UI se actualiza ANTES de la petición HTTP.

### Paso 3 — Agregar toast de error

Un error inline es útil para un botón, pero para errores globales necesitas un **toast** (notificacion temporal que aparece y desaparece).

1. Genera un servicio de notificaciones:
   ```bash
   ng generate service services/toast
   ```
2. En `src/app/services/toast.service.ts`:
   ```typescript
   import { Injectable, signal } from '@angular/core';

   export interface ToastMessage {
     id: number;
     text: string;
     type: 'error' | 'success';
   }

   @Injectable({ providedIn: 'root' })
   export class ToastService {
     private nextId = 0;
     messages = signal<ToastMessage[]>([]);

     show(text: string, type: 'error' | 'success' = 'error') {
       const id = this.nextId++;
       this.messages.update(msgs => [...msgs, { id, text, type }]);

       // Desaparece automaticamente despues de 4 segundos
       setTimeout(() => this.dismiss(id), 4000);
     }

     dismiss(id: number) {
       this.messages.update(msgs => msgs.filter(m => m.id !== id));
     }
   }
   ```

3. Genera un componente para mostrar los toasts:
   ```bash
   ng generate component toast-container
   ```
4. En `src/app/toast-container/toast-container.component.ts`:
   ```typescript
   import { Component, inject } from '@angular/core';
   import { ToastService } from '../services/toast.service';

   @Component({
     selector: 'app-toast-container',
     standalone: true,
     template: `
       <div class="toast-container">
         @for (msg of toastService.messages(); track msg.id) {
           <div class="toast" [class]="msg.type">
             {{ msg.text }}
             <button (click)="toastService.dismiss(msg.id)">✕</button>
           </div>
         }
       </div>
     `,
     styles: [`
       .toast-container {
         position: fixed; bottom: 1rem; right: 1rem;
         display: flex; flex-direction: column; gap: 0.5rem;
         z-index: 1000;
       }
       .toast {
         padding: 0.75rem 1rem; border-radius: 8px;
         color: white; display: flex; align-items: center; gap: 0.5rem;
         animation: slideIn 0.3s ease;
       }
       .error { background: #e74c3c; }
       .success { background: #27ae60; }
       button { background: none; border: none; color: white; cursor: pointer; }
       @keyframes slideIn { from { transform: translateX(100%); opacity: 0; } }
     `],
   })
   export class ToastContainerComponent {
     toastService = inject(ToastService);
   }
   ```

5. Ahora conecta el toast al componente de like. En `post-card.component.ts`, agrega el servicio:
   ```typescript
   import { ToastService } from '../services/toast.service';

   // Dentro de la clase:
   private toastService = inject(ToastService);

   // En el bloque error del subscribe, despues del rollback:
   this.toastService.show('No se pudo guardar el like. Intenta de nuevo.', 'error');
   ```

6. Agrega `<app-toast-container />` en tu componente raiz (`app.component.ts`) para que aparezca en toda la app

### Paso 4 — Implementar retry con exponential backoff

1. Modifica `src/app/services/like.service.ts` para agregar retry con backoff:
   ```typescript
   import { Injectable, inject } from '@angular/core';
   import { HttpClient } from '@angular/common/http';
   import { retry, timer } from 'rxjs';

   @Injectable({ providedIn: 'root' })
   export class LikeService {
     private http = inject(HttpClient);

     toggleLike(postId: string) {
       return this.http.post<{ liked: boolean }>(
         `/api/posts/${postId}/like`,
         {}
       ).pipe(
         retry({
           count: 3,
           delay: (error, retryCount) => {
             // Exponential backoff: 1s, 2s, 4s
             const delayMs = Math.pow(2, retryCount - 1) * 1000;
             console.log(
               `Retry ${retryCount}/3 en ${delayMs}ms...`
             );
             return timer(delayMs);
           },
         })
       );
     }
   }
   ```

> 💡 **Nota:** `retry` de RxJS reintenta la petición HTTP automáticamente. La función `delay` recibe el número de reintento y retorna un Observable que controla cuanto esperar. `timer(1000)` espera 1 segundo. Con `Math.pow(2, retryCount - 1) * 1000`, los intervalos son 1000ms, 2000ms, 4000ms.

2. Verifica que el retry solo se aplique a errores de red (5xx, timeout), no a errores de negocio (4xx). Modifica el delay:
   ```typescript
   retry({
     count: 3,
     delay: (error, retryCount) => {
       // No reintentar errores del cliente (4xx) — son errores de negocio
       if (error.status >= 400 && error.status < 500) {
         throw error; // Propagar inmediatamente
       }
       const delayMs = Math.pow(2, retryCount - 1) * 1000;
       console.log(`Retry ${retryCount}/3 en ${delayMs}ms...`);
       return timer(delayMs);
     },
   })
   ```

### Paso 5 — Probar los fallos

1. Abre tu app en Chrome
2. Abre DevTools → Network
3. **Probar optimistic update + rollback:**
   - Haz click en "Block request URL" (click derecho sobre una petición → Block request URL) para la URL `/api/posts/*/like`
   - Haz click en el botón de like
   - Debes ver: el like aparece inmediatamente → despues de los reintentos (observa los tiempos en Network: ~1s, ~2s, ~4s) → el like se revierte → aparece el toast de error

4. **Probar los intervalos del retry:**
   - En la pestana Network, observa las peticiones fallidas
   - Los tiempos entre reintentos deben ser aproximadamente 1s, 2s, 4s (exponential backoff)
   - Despues de 3 reintentos, el error se muestra al usuario

5. **Probar el caso exitoso:**
   - Desbloquea la URL
   - Haz click en el botón de like
   - El like debe persistir — sin rollback, sin toast de error

## Que puede salir mal

- **"El like se revierte pero no aparece el toast"** → Verifica que inyectaste `ToastService` en tu `PostCardComponent` y que `<app-toast-container />` esta en `app.component`. El toast container debe estar fuera de la ruta para que persista en toda la app.
- **"Los reintentos no se ven en Network"** → Verifica que estas usando `retry` de `rxjs` (no de otro paquete). Abre la pestana Network y filtra por "like" para ver las peticiones. Los reintentos aparecen como peticiones individuales con status `(failed)`.
- **"El retry reintenta errores 400/401"** → Agrega la verificación de status en el `delay` del retry (Paso 4, punto 2). Los errores 4xx son errores de negocio (datos invalidos, no autorizado) que no se resuelven reintentando.
- **"No tengo una API real para probar"** → Usa `json-server` para crear una API local rápida: `npx json-server db.json`. Puedes simular fallos bloqueando la petición en DevTools → Network → Block request URL.

## Resultado esperado

Al terminar, tu app tiene un botón de like con optimistic update: se actualiza instantaneamente al hacer click. Si la API falla, el like se revierte visiblemente y aparece un toast de error. Las peticiones fallidas se reintentan automáticamente con intervalos crecientes (~1s, ~2s, ~4s) antes de mostrar el error.

**Criterios de aceptacion:**
- [ ] Optimistic update funciona — el like aparece inmediatamente sin esperar al servidor
- [ ] Rollback visible cuando la API falla — el like se revierte y aparece un toast de error
- [ ] Retry con exponential backoff — verificado en DevTools → Network con intervalos de ~1s, ~2s, ~4s entre reintentos
- [ ] Errores 4xx no se reintentan — solo errores de red y 5xx activan el retry

## Por que esta actividad

TLS/HTTPS protege los datos mientras viajan entre el navegador y el servidor. Pero hay capas adicionales que completan la defensa: HSTS fuerza HTTPS y previene ataques de downgrade, SRI verifica que los scripts externos no fueron manipulados, y request signing prueba que un request salio de tu app sin ser alterado. Estas protecciones son la diferencia entre una app que "usa HTTPS" y una app que tiene **defense in depth** — multiples capas independientes donde cada una cubre los puntos ciegos de las demas. En esta actividad vas a verificar y configurar cada capa.

## Antes de empezar

Necesitas tener completada la **Actividad 6.10** y entender como funcionan los interceptors HTTP en Angular (cubierto en la Actividad 6.3).

**HSTS (HTTP Strict Transport Security)** es un header que le dice al navegador "nunca uses HTTP con este dominio". Previene ataques de downgrade donde un atacante intercepta la primera conexion HTTP antes de que se redireccione a HTTPS.

**SRI (Subresource Integrity)** verifica que un script o stylesheet externo no fue modificado. Agregas un hash del contenido esperado al tag `<script>`, y el navegador rechaza el archivo si el hash no coincide.

**HMAC (Hash-based Message Authentication Code)** es una firma criptografica que prueba que un mensaje no fue alterado. En request signing, firmas el body + timestamp con una clave secreta, y el servidor verifica la firma.

**Web Crypto API** (`crypto.subtle`) es la interfaz del navegador para operaciones criptograficas seguras (AES, RSA, HMAC). Es codigo nativo del navegador — no uses librerias externas de criptografia en JavaScript.

### Paso 1 — Verificar HSTS

HSTS se configura en el servidor, no en el frontend. Tu responsabilidad es verificar que esta presente.

1. Abre tu app en Chrome (o la version desplegada si tienes una)
2. Abre DevTools → Network
3. Selecciona el documento HTML principal (la primera peticion, normalmente el nombre de tu dominio)
4. En la pestana **Headers**, busca **Response Headers**
5. Busca el header `Strict-Transport-Security`
6. Si esta presente, verifica las directivas:
   - `max-age=31536000` — recordar durante 1 anio
   - `includeSubDomains` — aplicar a todos los subdominios
   - `preload` — incluir en la lista de preload del navegador

7. **Si no esta presente** (comun en desarrollo con localhost), documenta el requerimiento:
   ```markdown
   ## HSTS — Requerimiento de servidor

   El servidor debe responder con:
   Strict-Transport-Security: max-age=31536000; includeSubDomains; preload

   Estado actual: No configurado (desarrollo local).
   Pendiente: Configurar en el servidor de produccion (nginx, Apache, o CDN).
   ```

> 💡 **Nota:** `localhost` esta exento de HTTPS — funciona sin certificado. HSTS y las verificaciones de HTTPS aplican al entorno de produccion. En desarrollo, lo importante es que tu codigo no contenga URLs con `http://` hardcodeadas.

### Paso 2 — Agregar SRI a scripts externos

Si tu app carga scripts de un CDN externo, necesitas SRI. Angular por defecto bundlea todo (no usa CDN), pero si tienes scripts de terceros:

1. Abre `src/index.html` y busca tags `<script>` que cargan desde URLs externas
2. Si tienes uno (por ejemplo, un script de analytics o una libreria externa), genera el hash SRI:
   ```bash
   curl -s https://cdn.ejemplo.com/lib.min.js | openssl dgst -sha384 -binary | openssl base64 -A
   ```
3. Agrega el atributo `integrity` y `crossorigin` al tag:
   ```text
   <!-- HTML: agrega integrity y crossorigin al script externo -->
   <script
     src="https://cdn.ejemplo.com/lib.min.js"
     integrity="sha384-HASH_GENERADO_AQUI"
     crossorigin="anonymous">
   </script>
   ```
4. **Si no tienes scripts externos**, crea un ejemplo de prueba para entender el mecanismo:
   ```text
   <!-- HTML: ejemplo de SRI — agrega temporalmente en index.html para probar -->
   <script
     src="https://cdn.jsdelivr.net/npm/lodash@4.17.21/lodash.min.js"
     integrity="sha384-HASH_INCORRECTO"
     crossorigin="anonymous">
   </script>
   ```
5. Recarga la pagina y abre DevTools → Console
6. Debes ver un error: `Failed to find a valid digest in the 'integrity' attribute`
7. Esto confirma que SRI funciona — el navegador rechazo el script porque el hash no coincide
8. Elimina el script de prueba cuando termines

> 💡 **Nota:** SRI solo funciona con `crossorigin="anonymous"`. Sin el atributo `crossorigin`, el navegador no aplica CORS al request y no puede verificar la integridad del contenido.

### Paso 3 — Verificar mixed content

1. Abre tu app en Chrome
2. Abre DevTools → Console
3. Busca warnings que digan **"Mixed Content"** — por ejemplo:
   ```
   Mixed Content: The page at 'https://...' was loaded over HTTPS, but requested
   an insecure resource 'http://...'. This request has been blocked.
   ```
4. Si encuentras warnings, identifica la fuente:
   - Busca en tu codigo URLs con `http://`:
     ```bash
     grep -r "http://" src/ --include="*.ts" --include="*.html" --include="*.css" | grep -v "localhost" | grep -v "node_modules"
     ```
   - Reemplaza cada `http://` por `https://` o usa URLs relativas (`/api/...`)
5. **Regla:** Toda URL en tu codigo debe ser `https://` o relativa. Las URLs relativas heredan el protocolo de la pagina — si la pagina es HTTPS, las URLs relativas tambien lo son
6. Recarga y verifica que no quedan warnings de mixed content

### Paso 4 — Implementar interceptor de firma HMAC

Un interceptor de request signing agrega una firma HMAC a cada peticion. El servidor puede verificar que el request no fue manipulado.

1. Crea el archivo `src/app/services/request-signing.interceptor.ts`:
   ```typescript
   import { HttpInterceptorFn } from '@angular/common/http';

   export const requestSigningInterceptor: HttpInterceptorFn = (req, next) => {
     // Solo firmar requests a nuestra API
     if (!req.url.startsWith('/api/')) {
       return next(req);
     }

     const timestamp = Date.now().toString();
     const body = req.body ? JSON.stringify(req.body) : '';
     const message = `${req.method}:${req.url}:${body}:${timestamp}`;

     // Firmar el mensaje con HMAC-SHA256
     return new Observable(subscriber => {
       signMessage(message).then(signature => {
         const signedReq = req.clone({
           setHeaders: {
             'X-Request-Timestamp': timestamp,
             'X-Request-Signature': signature,
           },
         });
         next(signedReq).subscribe(subscriber);
       }).catch(err => subscriber.error(err));
     });
   };

   async function signMessage(message: string): Promise<string> {
     // En produccion, esta clave vendria de una variable de entorno
     // o derivada de la sesion del usuario
     const secretKey = 'clave-compartida-con-el-servidor';

     const encoder = new TextEncoder();
     const keyData = encoder.encode(secretKey);
     const messageData = encoder.encode(message);

     const cryptoKey = await crypto.subtle.importKey(
       'raw',
       keyData,
       { name: 'HMAC', hash: 'SHA-256' },
       false,
       ['sign']
     );

     const signature = await crypto.subtle.sign('HMAC', cryptoKey, messageData);
     return Array.from(new Uint8Array(signature))
       .map(b => b.toString(16).padStart(2, '0'))
       .join('');
   }
   ```
2. Nota que el interceptor usa `Observable` de RxJS. Agrega el import al inicio del archivo:
   ```typescript
   import { Observable } from 'rxjs';
   ```
3. Registra el interceptor en `src/app/app.config.ts`:
   ```typescript
   import { requestSigningInterceptor } from './services/request-signing.interceptor';

   // En el array de interceptors:
   provideHttpClient(withInterceptors([
     // ... tus interceptors existentes
     requestSigningInterceptor,
   ])),
   ```
4. Haz una peticion desde tu app y verifica en DevTools → Network que los headers `X-Request-Timestamp` y `X-Request-Signature` estan presentes en el request
5. El servidor debe verificar la firma recalculando el HMAC con la misma clave y comparando

> 💡 **Nota:** Request signing agrega complejidad. Solo implementalo si tu threat model lo justifica (proxies corporativos que modifican requests, extensiones de navegador no confiables, APIs de alto valor). Para la mayoria de las apps, TLS es suficiente.

### Paso 5 — Encriptar/desencriptar con Web Crypto API

Este paso demuestra como usar Web Crypto API para encriptacion end-to-end (E2EE). Es un ejemplo educativo — solo implementa E2EE si el servidor no debe ver los datos.

1. Crea el archivo `src/app/services/crypto.service.ts`:
   ```typescript
   import { Injectable } from '@angular/core';

   @Injectable({ providedIn: 'root' })
   export class CryptoService {

     async generarClave(): Promise<CryptoKey> {
       return crypto.subtle.generateKey(
         { name: 'AES-GCM', length: 256 },
         true,
         ['encrypt', 'decrypt']
       );
     }

     async encriptar(clave: CryptoKey, texto: string): Promise<{ iv: string; datos: string }> {
       const iv = crypto.getRandomValues(new Uint8Array(12));
       const encoded = new TextEncoder().encode(texto);

       const encrypted = await crypto.subtle.encrypt(
         { name: 'AES-GCM', iv },
         clave,
         encoded
       );

       return {
         iv: this.bufferToHex(iv),
         datos: this.bufferToHex(new Uint8Array(encrypted)),
       };
     }

     async desencriptar(clave: CryptoKey, iv: string, datos: string): Promise<string> {
       const ivBuffer = this.hexToBuffer(iv);
       const datosBuffer = this.hexToBuffer(datos);

       const decrypted = await crypto.subtle.decrypt(
         { name: 'AES-GCM', iv: ivBuffer },
         clave,
         datosBuffer
       );

       return new TextDecoder().decode(decrypted);
     }

     private bufferToHex(buffer: Uint8Array): string {
       return Array.from(buffer)
         .map(b => b.toString(16).padStart(2, '0'))
         .join('');
     }

     private hexToBuffer(hex: string): Uint8Array {
       const bytes = hex.match(/.{2}/g)?.map(b => parseInt(b, 16)) ?? [];
       return new Uint8Array(bytes);
     }
   }
   ```
2. Prueba el servicio desde un componente o desde Console. En cualquier componente:
   ```typescript
   import { Component, inject } from '@angular/core';
   import { CryptoService } from '../services/crypto.service';

   @Component({
     selector: 'app-crypto-demo',
     standalone: true,
     template: `
       <button (click)="probar()">Probar encriptacion</button>
       <pre>{{ resultado }}</pre>
     `,
   })
   export class CryptoDemoComponent {
     private crypto = inject(CryptoService);
     resultado = '';

     async probar() {
       const clave = await this.crypto.generarClave();
       const original = 'Datos secretos del usuario';

       const { iv, datos } = await this.crypto.encriptar(clave, original);
       this.resultado = `Encriptado: ${datos.substring(0, 40)}...\n`;

       const desencriptado = await this.crypto.desencriptar(clave, iv, datos);
       this.resultado += `Desencriptado: ${desencriptado}\n`;
       this.resultado += `Coincide: ${desencriptado === original}`;
     }
   }
   ```
3. Haz click en "Probar encriptacion" y verifica que el texto se encripta y desencripta correctamente

## Que puede salir mal

- **"HSTS no aparece en los headers de respuesta"** → HSTS es un header del servidor, no del frontend. En desarrollo con `localhost` no estara presente. Documenta el requerimiento para produccion y sigue adelante.
- **"El hash SRI no coincide"** → Los hashes SRI son sensibles a versiones. Si la libreria del CDN se actualiza, el hash cambia y el navegador bloquea el archivo. Esto es intencional — es la proteccion que SRI ofrece. Actualiza el hash cuando actualices la libreria.
- **"crypto.subtle no esta disponible"** → `crypto.subtle` solo esta disponible en contextos seguros (HTTPS o `localhost`). Si estas probando en HTTP que no sea localhost, no funcionara.
- **"El interceptor HMAC falla con 'Cannot read properties of undefined'"** → Verifica que `req.body` se maneja correctamente para requests sin body (GET, DELETE). El interceptor debe usar un string vacio cuando no hay body.

## Resultado esperado

Al terminar, tu app tiene multiples capas de proteccion: HSTS verificado (o documentado), SRI comprobado en scripts externos, cero mixed content, un interceptor de firma HMAC que agrega autenticidad a los requests, y un ejemplo funcional de encriptacion E2EE con Web Crypto API. Cada capa es independiente — si una falla, las demas siguen protegiendo.

**Criterios de aceptacion:**
- [ ] HSTS verificado en Response Headers o documentado como requerimiento del servidor
- [ ] SRI verificado — el navegador rechaza un script con hash incorrecto (error visible en Console)
- [ ] Cero warnings de mixed content en Console (`grep` de `http://` en el codigo no encuentra URLs hardcodeadas)
- [ ] Interceptor HMAC agrega `X-Request-Timestamp` y `X-Request-Signature` a las peticiones (verificado en DevTools → Network)

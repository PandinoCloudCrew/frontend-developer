## Por que esta actividad

**XSS (Cross-Site Scripting)** es el ataque mas comun en aplicaciones web. Un atacante inyecta código JavaScript malicioso en tu página — por ejemplo, a traves de un campo de comentarios — y ese código se ejecuta en el navegador de otros usuarios. Puede robar cookies, redirigir a paginas falsas, o registrar todo lo que el usuario escribe (incluyendo contrasenas). Los frameworks modernos como Angular te protegen automáticamente con **auto-escaping**, pero si usas `innerHTML` o `bypassSecurityTrust*` sin saber lo que haces, desactivas esa protección.

## Antes de empezar

Necesitas tener completada la **Etapa 5** y entender como Angular renderiza templates.

**XSS (Cross-Site Scripting)** es un ataque donde un atacante logra que tu página ejecute JavaScript que no escribiste tu. Imagina un foro donde los usuarios publican comentarios. Si un atacante escribe como comentario `<script>document.cookie</script>` y tu página lo muestra tal cual, ese script se ejecuta en el navegador de todos los que ven el comentario.

**Auto-escaping (sanitizacion)** es la protección que Angular aplica automáticamente: convierte caracteres peligrosos como `<` en `<` para que se muestren como texto, no como HTML. `<script>` se convierte en `<script>` — visible en pantalla pero inofensivo.

**innerHTML** es una propiedad de JavaScript que inserta HTML sin sanitizar. Si le pasas contenido del usuario, es como dejar la puerta abierta. Angular te protege con `[innerHTML]` (sanitiza automáticamente), pero si usas `bypassSecurityTrustHtml()`, desactivas la protección.

### Paso 1 — Crear la app de practica con vulnerabilidades

1. Crea un componente que simule una página con contenido de usuarios:
   ```bash
   ng generate component seguridad-lab
   ```
2. Crea el componente con vulnerabilidades intencionales:

::: code-group

```typescript [Angular]
// src/app/seguridad-lab/seguridad-lab.component.ts
import { Component, signal, ElementRef, viewChild } from '@angular/core';
import { DomSanitizer, SafeHtml } from '@angular/platform-browser';

@Component({
  selector: 'app-seguridad-lab',
  standalone: true,
  template: `
    <h1>Lab de Seguridad XSS</h1>

    <!-- Vulnerabilidad 1: innerHTML directo con bypassSecurityTrustHtml -->
    <h2>Comentarios</h2>
    <div [innerHTML]="comentarioConfiado()"></div>
    <input #comentarioInput type="text" placeholder="Escribe un comentario" />
    <button (click)="agregarComentario(comentarioInput.value)">Publicar</button>

    <!-- Vulnerabilidad 2: URL sin sanitizar -->
    <h2>Enlace del perfil</h2>
    <input #urlInput type="text" placeholder="URL de tu sitio web" />
    <button (click)="guardarUrl(urlInput.value)">Guardar</button>
    <a [href]="urlPerfil()">Visitar mi sitio</a>

    <!-- Vulnerabilidad 3: eval -->
    <h2>Calculadora</h2>
    <input #calcInput type="text" placeholder="Ej: 2+2" />
    <button (click)="calcular(calcInput.value)">Calcular</button>
    <p>Resultado: {{ resultadoCalc() }}</p>

    <!-- Vulnerabilidad 4: template injection via document.write -->
    <h2>Saludo personalizado</h2>
    <input #nombreInput type="text" placeholder="Tu nombre" />
    <button (click)="saludar(nombreInput.value)">Saludar</button>
    <div #saludoContainer></div>

    <!-- Vulnerabilidad 5: stored XSS (contenido guardado sin sanitizar) -->
    <h2>Notas guardadas</h2>
    <input #notaInput type="text" placeholder="Nueva nota" />
    <button (click)="guardarNota(notaInput.value)">Guardar nota</button>
    <ul>
      @for (nota of notas(); track $index) {
        <li [innerHTML]="confiarHtml(nota)"></li>
      }
    </ul>
  `,
})
export class SeguridadLabComponent {
  private sanitizer: DomSanitizer;
  comentarioConfiado = signal<SafeHtml>('');
  urlPerfil = signal('');
  resultadoCalc = signal('');
  notas = signal<string[]>([]);
  saludoContainer = viewChild<ElementRef>('saludoContainer');

  constructor(sanitizer: DomSanitizer) {
    this.sanitizer = sanitizer;
  }

  // Vulnerabilidad 1: bypassSecurityTrustHtml con input del usuario
  agregarComentario(comentario: string) {
    this.comentarioConfiado.set(
      this.sanitizer.bypassSecurityTrustHtml(comentario)
    );
  }

  // Vulnerabilidad 2: URL sin validar (permite javascript:)
  guardarUrl(url: string) {
    this.urlPerfil.set(url);
  }

  // Vulnerabilidad 3: eval con input del usuario
  calcular(expresion: string) {
    try {
      this.resultadoCalc.set(String(eval(expresion)));
    } catch {
      this.resultadoCalc.set('Error');
    }
  }

  // Vulnerabilidad 4: innerHTML directo en el DOM
  saludar(nombre: string) {
    const container = this.saludoContainer();
    if (container) {
      container.nativeElement.innerHTML = `<p>Hola, ${nombre}!</p>`;
    }
  }

  // Vulnerabilidad 5: guardar y mostrar contenido sin sanitizar
  confiarHtml(contenido: string): SafeHtml {
    return this.sanitizer.bypassSecurityTrustHtml(contenido);
  }

  guardarNota(nota: string) {
    this.notas.update(n => [...n, nota]);
  }
}
```

3. Agrega una ruta para este componente y ejecuta `ng serve`

### Paso 2 — Encontrar las 5 vulnerabilidades

1. Abre la página en Chrome
2. En cada campo de input, escribe este payload de prueba:
   ```
   <img src=x onerror=alert(1)>
   ```
3. Haz click en el botón correspondiente
4. Si aparece un alert (cuadro de dialogo con "1"), la vulnerabilidad es real
5. Documenta cuales campos son vulnerables:
   - Comentarios: ¿sale alert?
   - URL: prueba con `javascript:alert(1)` y haz click en el link
   - Calculadora: prueba con `alert(1)`
   - Saludo: prueba con `<img src=x onerror=alert(1)>`
   - Notas: prueba con `<img src=x onerror=alert(1)>`

### Paso 3 — Corregir la vulnerabilidad de innerHTML

1. **Vulnerabilidad 1 (comentario con bypassSecurityTrustHtml):** Nunca uses `bypassSecurityTrustHtml` con contenido del usuario. Cambia a interpolacion normal:
   ```typescript
   // ANTES (VULNERABLE):
   comentarioConfiado = signal<SafeHtml>('');
   agregarComentario(comentario: string) {
     this.comentarioConfiado.set(
       this.sanitizer.bypassSecurityTrustHtml(comentario)
     );
   }

   // DESPUES (SEGURO):
   comentarioTexto = signal('');
   agregarComentario(comentario: string) {
     this.comentarioTexto.set(comentario);
   }
   // En el template: <p>{{ comentarioTexto() }}</p>
   // Angular escapa automaticamente el HTML
   ```

2. **Vulnerabilidad 4 (nativeElement.innerHTML):** Reemplaza la manipulación directa del DOM por binding de Angular:
   ```typescript
   // ANTES (VULNERABLE):
   saludar(nombre: string) {
     container.nativeElement.innerHTML = `<p>Hola, ${nombre}!</p>`;
   }

   // DESPUES (SEGURO):
   nombreSaludo = signal('');
   saludar(nombre: string) {
     this.nombreSaludo.set(nombre);
   }
   // En el template: <p>Hola, {{ nombreSaludo() }}!</p>
   ```

### Paso 4 — Corregir URL injection

**Vulnerabilidad 2:** Un usuario puede escribir `javascript:alert(document.cookie)` como URL. Valida que la URL empiece con `http://` o `https://`:

```typescript
// ANTES (VULNERABLE):
guardarUrl(url: string) {
  this.urlPerfil.set(url);
}

// DESPUES (SEGURO):
guardarUrl(url: string) {
  if (url.startsWith('http://') || url.startsWith('https://')) {
    this.urlPerfil.set(url);
  } else {
    this.urlPerfil.set('');
    console.warn('URL rechazada: solo se permiten URLs http/https');
  }
}
```

### Paso 5 — Corregir las vulnerabilidades restantes

1. **Vulnerabilidad 3 (eval):** Nunca uses `eval()` ni `new Function()` con input del usuario. Implementa la calculadora con lógica propia:
   ```typescript
   // ANTES (VULNERABLE):
   calcular(expresion: string) {
     this.resultadoCalc.set(String(eval(expresion)));
   }

   // DESPUES (SEGURO):
   calcular(expresion: string) {
     // Solo permitir numeros y operadores basicos
     const sanitizada = expresion.replace(/[^0-9+\-*/.() ]/g, '');
     if (sanitizada !== expresion) {
       this.resultadoCalc.set('Solo numeros y operadores permitidos');
       return;
     }
     try {
       // Usar Function con expresion sanitizada (sin acceso al scope)
       const resultado = new Function(`return (${sanitizada})`)();
       this.resultadoCalc.set(String(resultado));
     } catch {
       this.resultadoCalc.set('Expresion invalida');
     }
   }
   ```

2. **Vulnerabilidad 5 (stored XSS):** No uses `bypassSecurityTrustHtml` para mostrar notas. Usa interpolacion:
   ```typescript
   // ANTES (VULNERABLE):
   // <li [innerHTML]="confiarHtml(nota)"></li>

   // DESPUES (SEGURO):
   // <li>{{ nota }}</li>
   // Elimina el metodo confiarHtml() completamente
   ```

### Paso 6 — Verificar que todo esta seguro

1. Recarga la página
2. En **cada** campo de input, escribe:
   ```
   <img src=x onerror=alert(1)>
   ```
3. Haz click en el botón correspondiente
4. **Ningun alert debe aparecer** — el texto debe mostrarse como texto plano, no ejecutarse como HTML
5. Para la URL, prueba con `javascript:alert(1)` — el link no debe guardarse
6. Para la calculadora, prueba con `alert(1)` — debe rechazarse

## Que puede salir mal

- **"Despues de corregir, el comentario muestra las etiquetas HTML como texto"** → Eso es exactamente lo correcto. Cuando alguien escribe `<b>hola</b>`, debe verse literalmente `<b>hola</b>` en pantalla, no **hola** en negrita. Si necesitas permitir cierto formato, usa una libreria como DOMPurify que permite solo tags seguros.
- **"Angular no me deja usar [href] con una variable"** → Si Angular te muestra un warning de "unsafe URL", es Angular protegiendote. La solución no es usar `bypassSecurityTrustUrl()` — es validar la URL antes de guardarla (como en el Paso 4).
- **"Elimine bypassSecurityTrustHtml pero necesito mostrar HTML enriquecido (bold, italic)"** → Instala DOMPurify (`npm install dompurify @types/dompurify`) y sanitiza antes de usar `[innerHTML]`: `this.sanitizer.bypassSecurityTrustHtml(DOMPurify.sanitize(contenido))`.

## Resultado esperado

Al terminar, tu app de practica no tiene vulnerabilidades XSS. Has entendido que Angular te protege por defecto con auto-escaping, y que `bypassSecurityTrustHtml`, `eval`, `innerHTML` directo, y URLs sin validar son las puertas que abren vulnerabilidades.

**Criterios de aceptacion:**
- [ ] Cero XSS vulnerabilities restantes — `<img src=x onerror=alert(1)>` no ejecuta ningun alert en ningun campo
- [ ] Cero uso de `eval()` o `new Function()` con input no sanitizado del usuario
- [ ] Cada uso de `bypassSecurityTrustHtml` esta eliminado o justificado con DOMPurify

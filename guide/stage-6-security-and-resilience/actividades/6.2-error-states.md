## Por que esta actividad

La mayoria de las aplicaciones solo manejan el caso feliz: los datos llegan y se muestran. Pero en la realidad, la red falla, las APIs devuelven errores, y a veces simplemente no hay datos. Cuando un usuario ve una pantalla en blanco sin explicacion, no sabe si la app se rompio, si esta cargando, o si no hay resultados. Los 4 estados de una vista con datos — **loading**, **success**, **error**, **empty** — son la diferencia entre una app frustrante y una app profesional.

## Antes de empezar

Necesitas tener completada la **Actividad 6.1** y al menos un componente que obtiene datos de una API (con `HttpClient` o `fetch`).

Los **4 estados de una vista con datos** son:
1. **Loading (cargando):** los datos se estan descargando. El usuario necesita saber que algo esta pasando — no una pantalla en blanco. Un **skeleton** es un placeholder visual que imita la forma del contenido final.
2. **Success (exito):** los datos llegaron. Se muestran normalmente.
3. **Error:** la petición fallo (red caida, servidor error 500, timeout). El usuario necesita saber que paso y poder reintentar.
4. **Empty (vacio):** la petición fue exitosa pero no hay datos. "No tienes notificaciones" con una sugerencia de que hacer es mejor que una lista vacia sin explicacion.

Un **error boundary** es un componente que captura errores de sus hijos y muestra un fallback en lugar de crashear toda la app. Si una sección falla, solo esa sección muestra error — el resto de la página sigue funcionando.

### Paso 1 — Crear un servicio que obtiene datos

1. Crea un servicio para obtener datos:
   ```bash
   ng generate service servicios/usuarios
   ```
2. En `src/app/servicios/usuarios.service.ts`:
   ```typescript
   import { Injectable, inject } from '@angular/core';
   import { HttpClient } from '@angular/common/http';
   import { Observable } from 'rxjs';

   export interface Usuario {
     id: number;
     name: string;
     email: string;
   }

   @Injectable({ providedIn: 'root' })
   export class UsuariosService {
     private http = inject(HttpClient);

     obtenerUsuarios(): Observable<Usuario[]> {
       return this.http.get<Usuario[]>(
         'https://jsonplaceholder.typicode.com/users'
       );
     }
   }
   ```

### Paso 2 — Implementar estado loading con skeleton

1. Crea un componente para la lista de usuarios:
   ```bash
   ng generate component lista-usuarios
   ```
2. En `src/app/lista-usuarios/lista-usuarios.component.ts`:
   ```typescript
   import { Component, signal, inject, OnInit } from '@angular/core';
   import { UsuariosService, Usuario } from '../servicios/usuarios.service';

   type Estado = 'loading' | 'success' | 'error' | 'empty';

   @Component({
     selector: 'app-lista-usuarios',
     standalone: true,
     template: `
       @switch (estado()) {
         @case ('loading') {
           <div class="skeleton-list">
             @for (item of [1, 2, 3, 4, 5]; track item) {
               <div class="skeleton-item">
                 <div class="skeleton-line skeleton-name"></div>
                 <div class="skeleton-line skeleton-email"></div>
               </div>
             }
           </div>
         }
         @case ('success') {
           <ul>
             @for (usuario of usuarios(); track usuario.id) {
               <li>
                 <strong>{{ usuario.name }}</strong>
                 <span>{{ usuario.email }}</span>
               </li>
             }
           </ul>
         }
         @case ('error') {
           <div class="error-state">
             <p>No pudimos cargar los usuarios. Verifica tu conexion e intenta de nuevo.</p>
             <button (click)="cargar()">Reintentar</button>
           </div>
         }
         @case ('empty') {
           <div class="empty-state">
             <p>No hay usuarios registrados todavia.</p>
             <p>Cuando alguien se registre, aparecera aqui.</p>
           </div>
         }
       }
     `,
     styles: [`
       .skeleton-list { display: flex; flex-direction: column; gap: 1rem; }
       .skeleton-item { padding: 1rem; border: 1px solid #eee; border-radius: 0.5rem; }
       .skeleton-line {
         height: 1rem;
         background: linear-gradient(90deg, #eee 25%, #ddd 50%, #eee 75%);
         background-size: 200% 100%;
         animation: shimmer 1.5s infinite;
         border-radius: 0.25rem;
       }
       .skeleton-name { width: 60%; margin-bottom: 0.5rem; }
       .skeleton-email { width: 40%; }
       @keyframes shimmer {
         0% { background-position: 200% 0; }
         100% { background-position: -200% 0; }
       }
       .error-state, .empty-state {
         text-align: center;
         padding: 2rem;
         border: 1px dashed #ccc;
         border-radius: 0.5rem;
       }
       .error-state button {
         margin-top: 1rem;
         padding: 0.5rem 1rem;
         cursor: pointer;
       }
     `],
   })
   export class ListaUsuariosComponent implements OnInit {
     private usuariosService = inject(UsuariosService);

     estado = signal<Estado>('loading');
     usuarios = signal<Usuario[]>([]);

     ngOnInit() {
       this.cargar();
     }

     cargar() {
       this.estado.set('loading');
       this.usuariosService.obtenerUsuarios().subscribe({
         next: (datos) => {
           if (datos.length === 0) {
             this.estado.set('empty');
           } else {
             this.usuarios.set(datos);
             this.estado.set('success');
           }
         },
         error: () => {
           this.estado.set('error');
         },
       });
     }
   }
   ```

### Paso 3 — Implementar estado error con retry

El estado error ya esta implementado en el paso anterior. Verifica estos puntos:

1. El mensaje de error es **claro y accionable**: "No pudimos cargar los usuarios. Verifica tu conexión e intenta de nuevo." — no "Error 500" ni "Something went wrong"
2. El botón de retry llama a `cargar()` que:
   - Cambia el estado a `'loading'` (muestra skeleton de nuevo)
   - Hace la petición otra vez
   - Si tiene exito, muestra los datos
   - Si falla otra vez, vuelve a mostrar el error con retry

### Paso 4 — Implementar empty state

El empty state ya esta implementado en el Paso 2. Verifica estos puntos:

1. El mensaje explica **por que esta vacio**: "No hay usuarios registrados todavia"
2. Da **orientacion** sobre que hacer: "Cuando alguien se registre, aparecera aquí"
3. Un empty state NUNCA debe ser una lista vacia sin texto. Si la API devuelve `[]`, el usuario necesita saber que es normal

### Paso 5 — Simular fallos para verificar

1. Abre Chrome DevTools → Network
2. **Simular carga lenta:** Cambia el throttling a **Slow 3G** y recarga la página. Verifica que el skeleton aparece durante la carga
3. **Simular error de red:** En DevTools → Network, activa **Offline** (checkbox arriba a la izquierda o en el dropdown de throttling). Haz click en "Reintentar" — debe mostrar el estado de error
4. **Simular respuesta vacia:** Temporalmente modifica tu servicio para devolver un array vacio:
   ```typescript
   // Temporal — para probar el empty state
   import { of } from 'rxjs';

   obtenerUsuarios(): Observable<Usuario[]> {
     return of([]);  // Simula respuesta vacia
   }
   ```
   Recarga y verifica que el empty state aparece. Luego revierte el cambio
5. **Probar retry:** Desactiva offline, haz click en "Reintentar" — los datos deben cargar

### Paso 6 — Agregar error boundary

Un error boundary evita que un error en un componente hijo crashee toda la página.

1. Crea un componente error boundary:
   ```bash
   ng generate component error-boundary
   ```
2. En `src/app/error-boundary/error-boundary.component.ts`:
   ```typescript
   import { Component, signal, ErrorHandler, inject } from '@angular/core';

   @Component({
     selector: 'app-error-boundary',
     standalone: true,
     template: `
       @if (tieneError()) {
         <div class="error-boundary">
           <h3>Esta seccion tuvo un problema</h3>
           <p>El resto de la pagina sigue funcionando.</p>
           <button (click)="reiniciar()">Reiniciar seccion</button>
         </div>
       } @else {
         <ng-content />
       }
     `,
     styles: [`
       .error-boundary {
         padding: 1rem;
         border: 2px solid #e74c3c;
         border-radius: 0.5rem;
         text-align: center;
         background: #fdf0ef;
       }
     `],
   })
   export class ErrorBoundaryComponent {
     tieneError = signal(false);

     reiniciar() {
       this.tieneError.set(false);
     }
   }
   ```
3. Usa el error boundary para envolver secciones independientes de tu página:
   ```text
   <!-- HTML: en el template de la pagina principal -->
   <app-error-boundary>
     <app-lista-usuarios />
   </app-error-boundary>

   <app-error-boundary>
     <app-otra-seccion />
   </app-error-boundary>
   ```

> 💡 **Nota:** Angular no tiene error boundaries nativos como React. La implementación de arriba es básica. Para produccion, considera usar un `ErrorHandler` global que capture errores y active el error boundary correspondiente.

## Que puede salir mal

- **"El skeleton parpadea muy rápido y apenas se ve"** → Tu conexión es muy rápida. Usa DevTools → Network → Slow 3G para simular una red lenta y ver el skeleton durante 1-2 segundos.
- **"El botón de retry no hace nada"** → Verifica que `cargar()` cambia el estado a `'loading'` al inicio. Si no lo hace, el template sigue mostrando el error y no re-renderiza.
- **"Veo una pantalla en blanco en lugar del skeleton"** → Verifica que el estado inicial es `'loading'`, no `'success'`. Si el componente empieza en `'success'` antes de que lleguen datos, no hay nada que mostrar.

## Resultado esperado

Al terminar, toda vista con data fetching en tu app maneja los 4 estados: skeleton durante la carga, datos cuando llegan, error con retry cuando falla, y empty state cuando no hay datos. Las secciones independientes estan envueltas en error boundaries.

**Criterios de aceptacion:**
- [ ] Skeleton visible cuando la carga es lenta (verificado con Slow 3G)
- [ ] Error con botón reintentar funcional (verificado con modo offline → online)
- [ ] Empty state con orientacion al usuario (verificado con respuesta vacia)
- [ ] Error boundaries en secciones independientes (no solo un error boundary en la raiz)

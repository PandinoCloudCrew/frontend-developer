## Por que esta actividad

En la Actividad 6.3 implementaste autenticacion con OAuth + PKCE desde cero. Eso fue util para entender el flujo, pero en produccion **nunca implementas un cliente OIDC manualmente** — hay demasiados detalles sutiles (validacion de nonce, manejo de clock skew, rotacion de tokens) que una libreria certificada ya resuelve. OpenID Connect (OIDC) extiende OAuth con una capa de identidad: ademas de autorizar, te dice **quien** es el usuario. En esta actividad vas a instalar `angular-auth-oidc-client`, configurarla con un proveedor real, y ver como el flujo completo — login, logout, silent renew — funciona con unas pocas lineas de configuracion.

## Antes de empezar

Necesitas tener completada la **Actividad 6.7** (validacion integral) y entender el flujo OAuth + PKCE que implementaste en la **Actividad 6.3**.

**OIDC (OpenID Connect)** es una capa sobre OAuth 2.0 que agrega autenticacion. OAuth dice "esta app puede acceder a tus datos". OIDC dice "esta persona es Juan Perez y su email es juan@ejemplo.com". La diferencia practica es que OIDC te da un **ID Token** (un JWT con los datos del usuario) ademas del access token.

**`angular-auth-oidc-client`** es la libreria recomendada para OIDC en Angular. Maneja todo el flujo: redireccion al proveedor, intercambio de codigos, validacion de tokens, silent renew, y logout. Tu solo configuras y usas.

**Auth0** y **Keycloak** son proveedores de identidad que implementan el estandar OIDC. Auth0 es un servicio en la nube (tiene tier gratuito). Keycloak es open source y puedes correrlo localmente con Docker. Para esta actividad puedes usar cualquiera de los dos.

### Paso 1 — Crear cuenta en el proveedor

Elige una de las dos opciones:

**Opcion A — Auth0 (recomendada, sin Docker):**

1. Ve a [https://auth0.com](https://auth0.com) y crea una cuenta gratuita
2. En el dashboard, ve a **Applications → Create Application**
3. Selecciona **Single Page Application** y dale un nombre (por ejemplo, `mi-app-angular`)
4. En la pestana **Settings**, configura:
   - **Allowed Callback URLs:** `http://localhost:4200`
   - **Allowed Logout URLs:** `http://localhost:4200`
   - **Allowed Web Origins:** `http://localhost:4200`
5. Guarda los cambios. Copia el **Domain** y el **Client ID** — los necesitaras en el Paso 3

**Opcion B — Keycloak (local con Docker):**

1. Inicia Keycloak:
   ```bash
   docker run -p 8080:8080 -e KC_BOOTSTRAP_ADMIN_USERNAME=admin -e KC_BOOTSTRAP_ADMIN_PASSWORD=admin quay.io/keycloak/keycloak:latest start-dev
   ```
2. Abre `http://localhost:8080/admin` e inicia sesion con `admin`/`admin`
3. Crea un realm nuevo llamado `mi-app`
4. En **Clients → Create client**, crea un cliente con:
   - Client ID: `mi-app-angular`
   - Client type: `OpenID Connect`
   - Valid redirect URIs: `http://localhost:4200/*`
   - Web origins: `http://localhost:4200`
5. En **Users**, crea un usuario de prueba con nombre, email y contrasena

### Paso 2 — Instalar angular-auth-oidc-client

1. En la terminal, dentro de tu proyecto Angular:
   ```bash
   npm install angular-auth-oidc-client
   ```

### Paso 3 — Configurar OIDC en Angular

1. Abre `src/app/app.config.ts` y agrega la configuracion de OIDC:
   ```typescript
   import { provideAuth } from 'angular-auth-oidc-client';

   export const appConfig = {
     providers: [
       // ... tus providers existentes
       provideAuth({
         config: {
           // Para Auth0:
           authority: 'https://TU-TENANT.auth0.com',
           // Para Keycloak:
           // authority: 'http://localhost:8080/realms/mi-app',

           redirectUrl: window.location.origin,
           postLogoutRedirectUri: window.location.origin,
           clientId: 'TU-CLIENT-ID',
           scope: 'openid profile email',
           responseType: 'code',
           silentRenew: true,
           useRefreshToken: true,
         },
       }),
     ],
   };
   ```
2. Reemplaza `TU-TENANT` y `TU-CLIENT-ID` con los valores de tu proveedor (Paso 1)

> 💡 **Nota:** El `scope: 'openid profile email'` le dice al proveedor que quieres autenticacion (`openid`), datos del perfil (`profile`) y el email del usuario (`email`). Sin `openid`, el proveedor no devuelve un ID Token.

### Paso 4 — Implementar login/logout

1. Genera un componente para el estado de autenticacion:
   ```bash
   ng generate component auth-status
   ```
2. En `src/app/auth-status/auth-status.component.ts`:
   ```typescript
   import { Component, inject } from '@angular/core';
   import { OidcSecurityService } from 'angular-auth-oidc-client';
   import { toSignal } from '@angular/core/rxjs-interop';
   import { map } from 'rxjs';

   @Component({
     selector: 'app-auth-status',
     standalone: true,
     template: `
       @if (isAuthenticated()) {
         <div class="user-info">
           <p>Hola, {{ userData()?.name ?? 'usuario' }}</p>
           <p class="email">{{ userData()?.email }}</p>
           <button (click)="logout()">Cerrar sesion</button>
         </div>
       } @else {
         <button (click)="login()">Iniciar sesion</button>
       }
     `,
     styles: [`
       .user-info { display: flex; flex-direction: column; gap: 0.25rem; }
       .email { font-size: 0.875rem; color: #64748b; }
       button { cursor: pointer; padding: 0.5rem 1rem; border-radius: 4px; }
     `],
   })
   export class AuthStatusComponent {
     private oidc = inject(OidcSecurityService);

     isAuthenticated = toSignal(
       this.oidc.isAuthenticated$.pipe(map(result => result.isAuthenticated)),
       { initialValue: false }
     );

     userData = toSignal(this.oidc.userData$, { initialValue: null });

     login() {
       this.oidc.authorize();
     }

     logout() {
       this.oidc.logoff().subscribe();
     }
   }
   ```
3. Agrega `<app-auth-status />` en tu `app.component.ts` (importa `AuthStatusComponent` y agregalo al `imports` array)
4. Inicia la app con `ng serve` y haz click en "Iniciar sesion"
5. Debes ser redirigido al formulario de login del proveedor. Ingresa las credenciales del usuario de prueba
6. Al completar el login, debes volver a tu app y ver "Hola, [nombre]" con el email debajo

### Paso 5 — Inspeccionar el ID Token en DevTools

1. Con la sesion iniciada, abre DevTools → Application → Session Storage (o la tab donde la libreria almacena datos)
2. Busca una entrada que contenga el ID Token — es un string largo con dos puntos (formato JWT: `header.payload.signature`)
3. Copia el valor del ID Token
4. Abre [https://jwt.io](https://jwt.io) y pega el token en el campo "Encoded"
5. En el panel "Decoded", observa los claims:
   - `iss` — el emisor (tu proveedor: Auth0 o Keycloak)
   - `sub` — el identificador unico del usuario
   - `aud` — tu client ID (debe coincidir con lo que configuraste)
   - `exp` — cuando expira el token (timestamp Unix)
   - `email` — el email del usuario
   - `name` — el nombre del usuario
6. Verifica que `iss` coincide con tu `authority` y `aud` coincide con tu `clientId`

> 💡 **Nota:** El ID Token es para **tu frontend** — contiene la identidad del usuario. El access token es para **tu API** — nunca lo inspecciones en el frontend. La libreria valida automaticamente `iss`, `aud`, `exp` y `nonce` del ID Token.

### Paso 6 — Implementar silent renew

La configuracion del Paso 3 ya activo silent renew (`silentRenew: true` y `useRefreshToken: true`). Ahora verifica que funciona:

1. Agrega un componente que muestre cuando expira el token. En `auth-status.component.ts`, agrega al template:
   ```typescript
   // Dentro de la clase, agrega:
   tokenExpiration = toSignal(
     this.oidc.getAccessToken().pipe(
       map(token => {
         if (!token) return null;
         try {
           const payload = JSON.parse(atob(token.split('.')[1]));
           return new Date(payload.exp * 1000).toLocaleTimeString();
         } catch {
           return 'Token opaco';
         }
       })
     ),
     { initialValue: null }
   );
   ```
2. En el template, dentro del bloque `@if (isAuthenticated())`, agrega:
   ```text
   <p class="token-info">Token expira: {{ tokenExpiration() ?? 'desconocido' }}</p>
   ```
3. Observa que cuando el token esta por expirar, la libreria automaticamente obtiene uno nuevo sin interrumpir al usuario. En DevTools → Network, filtra por `token` para ver las peticiones de renovacion

> 💡 **Nota:** Algunos proveedores (como Auth0 en el tier gratuito) usan refresh tokens con rotacion — cada vez que se usa un refresh token, se emite uno nuevo y el anterior se invalida. Esto es una buena practica de seguridad.

## Que puede salir mal

- **"Despues del login me redirige pero no veo mis datos de usuario"** → Verifica que tu `redirectUrl` en la configuracion coincide exactamente con la URL que configuraste en el proveedor (Auth0: "Allowed Callback URLs", Keycloak: "Valid redirect URIs"). Un slash final de diferencia (`http://localhost:4200` vs `http://localhost:4200/`) causa el error.
- **"Error: CORS policy"** → Tu proveedor necesita tener `http://localhost:4200` en la lista de origenes permitidos. En Auth0 es "Allowed Web Origins", en Keycloak es "Web origins".
- **"El ID Token no tiene email o name"** → Verifica que el scope incluye `profile email` (no solo `openid`). En Auth0, tambien verifica que el usuario tiene un email verificado. En Keycloak, verifica que el usuario de prueba tiene nombre y email configurados.
- **"Silent renew no funciona — la sesion expira"** → En Auth0, ve a **Applications → Settings → Advanced Settings → Grant Types** y verifica que "Refresh Token" esta habilitado. En Keycloak, el refresh token esta habilitado por defecto.

## Resultado esperado

Al terminar, tu app tiene login/logout con OIDC a traves de un proveedor real. El usuario hace click en "Iniciar sesion", es redirigido al proveedor, ingresa sus credenciales, y vuelve a tu app donde ve su nombre y email. El token se renueva automaticamente. No escribiste ningun flujo OAuth manualmente — la libreria maneja todo.

**Criterios de aceptacion:**
- [ ] Login funciona — el usuario es redirigido al proveedor, se autentica, y vuelve a la app con sus datos visibles
- [ ] El ID Token tiene los claims correctos (`iss`, `aud`, `sub`, `email`) — verificado en jwt.io
- [ ] Logout funciona — al cerrar sesion, la app vuelve al estado no autenticado y la sesion se cierra en el proveedor
- [ ] Silent renew funciona — el token se renueva automaticamente sin intervencion del usuario (verificado en DevTools → Network)

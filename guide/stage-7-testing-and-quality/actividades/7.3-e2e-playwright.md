## Por qué esta actividad

Los tests unitarios verifican funciones. Los tests de componentes verifican que un componente se comporta bien. Pero ninguno verifica que el **flujo completo** funciona: que un usuario puede hacer login, buscar un producto, ver su detalle y agregarlo al carrito — todo en secuencia, como lo haría en la vida real.

Un **test end-to-end (E2E)** abre un navegador real, ejecuta tu aplicación completa y simula el camino que un usuario recorre. Si el flujo de compra se rompe en producción, pierdes dinero. Un test E2E del camino crítico te avisa antes de que eso pase.

> **Pilar de diseño:** Esta actividad ejercita **Mantenibilidad** — un test E2E del camino crítico te permite hacer deploy con confianza porque verificas el flujo más importante.

## Antes de empezar

Necesitas haber completado las **Actividades 7.1 y 7.2** — ya sabes testear componentes y mockear APIs.

Necesitas una aplicación Angular con al menos 2-3 páginas conectadas (por ejemplo: login, lista de productos, detalle de producto). Si no la tienes completa, puedes crear páginas simples con navegación básica.

**¿Qué es un test E2E?** E2E significa "end-to-end" (de principio a fin). Es un test que abre un navegador de verdad, navega por tu aplicación y verifica que todo funciona junto — como si un humano estuviera probando la aplicación, pero automáticamente.

**¿Qué es Playwright?** Es una herramienta creada por Microsoft para automatizar navegadores. Puede controlar Chrome, Firefox y Safari. Es más rápido y más estable que Selenium (la herramienta anterior) y tiene mejor soporte para aplicaciones modernas.

**¿Qué es el Page Object Model (POM)?** Es un patrón de organización. En lugar de escribir selectores directamente en tu test, creas una clase que representa una página y encapsula los selectores. Así, si un selector cambia, lo actualizas en un solo lugar.

### Paso 1 — Instalar Playwright

1. En la terminal de VS Code, ejecuta:
   ```bash
   npm init playwright@latest
   ```

2. El instalador te preguntará varias cosas. Responde:
   - **Where to put your end-to-end tests?** → `e2e`
   - **Add a GitHub Actions workflow?** → `Yes` (lo usarás en la Actividad 7.5)
   - **Install Playwright browsers?** → `Yes`

3. Esto crea la carpeta `e2e/` y el archivo `playwright.config.ts`. Abre `playwright.config.ts` y verifica que el `baseURL` apunta a tu aplicación:
   ```typescript
   import { defineConfig } from '@playwright/test';

   export default defineConfig({
     testDir: './e2e',
     use: {
       baseURL: 'http://localhost:4200',
     },
     webServer: {
       command: 'ng serve',
       url: 'http://localhost:4200',
       reuseExistingServer: !process.env['CI'],
     },
   });
   ```

> 💡 **Nota:** La sección `webServer` le dice a Playwright que arranque tu aplicación Angular automáticamente antes de correr los tests. En CI, siempre arranca un servidor nuevo.

### Paso 2 — Escribir un test simple

1. Crea `e2e/home.spec.ts`:
   ```typescript
   import { test, expect } from '@playwright/test';

   test('la página principal carga correctamente', async ({ page }) => {
     await page.goto('/');

     await expect(page.getByRole('heading', { level: 1 })).toBeVisible();
   });
   ```

2. Ejecuta el test:
   ```bash
   npx playwright test e2e/home.spec.ts
   ```

### Paso 3 — Crear Page Objects

En lugar de escribir selectores directamente en los tests, encapsúlalos en clases:

1. Crea `e2e/pages/login.page.ts`:
   ```typescript
   import { type Page, type Locator } from '@playwright/test';

   export class LoginPage {
     readonly emailInput: Locator;
     readonly passwordInput: Locator;
     readonly submitButton: Locator;

     constructor(private readonly page: Page) {
       this.emailInput = page.getByRole('textbox', { name: /email/i });
       this.passwordInput = page.getByLabel(/contraseña/i);
       this.submitButton = page.getByRole('button', { name: /iniciar sesión/i });
     }

     async goto(): Promise<void> {
       await this.page.goto('/login');
     }

     async login(email: string, password: string): Promise<void> {
       await this.emailInput.fill(email);
       await this.passwordInput.fill(password);
       await this.submitButton.click();
     }
   }
   ```

2. Crea `e2e/pages/search.page.ts`:
   ```typescript
   import { type Page, type Locator } from '@playwright/test';

   export class SearchPage {
     readonly searchInput: Locator;
     readonly searchButton: Locator;

     constructor(private readonly page: Page) {
       this.searchInput = page.getByRole('textbox', { name: /buscar/i });
       this.searchButton = page.getByRole('button', { name: /buscar/i });
     }

     async search(query: string): Promise<void> {
       await this.searchInput.fill(query);
       await this.searchButton.click();
     }

     getResultByName(name: string): Locator {
       return this.page.getByRole('link', { name });
     }
   }
   ```

> 💡 **Nota:** Los locators usan `getByRole` y `getByLabel` — igual que Testing Library. Si tu HTML no es accesible, los locators no encontrarán los elementos. Los tests E2E te fuerzan a tener HTML accesible.

### Paso 4 — Test del camino crítico completo

1. Crea `e2e/critical-path.spec.ts`:
   ```typescript
   import { test, expect } from '@playwright/test';
   import { LoginPage } from './pages/login.page';
   import { SearchPage } from './pages/search.page';

   test.describe('Camino crítico', () => {
     test('login -> buscar -> ver detalle -> agregar al carrito', async ({ page }) => {
       // 1. Login
       const loginPage = new LoginPage(page);
       await loginPage.goto();
       await loginPage.login('usuario@test.com', 'password123');
       await expect(page).toHaveURL('/dashboard');

       // 2. Buscar
       const searchPage = new SearchPage(page);
       await searchPage.search('laptop');
       await expect(searchPage.getResultByName(/laptop/i)).toBeVisible();

       // 3. Ver detalle
       await searchPage.getResultByName(/laptop/i).click();
       await expect(page.getByRole('heading', { name: /laptop/i })).toBeVisible();
       await expect(page.getByText(/\$999/)).toBeVisible();

       // 4. Agregar al carrito
       await page.getByRole('button', { name: /agregar al carrito/i }).click();
       await expect(page.getByRole('alert')).toContainText(/agregado/i);
     });
   });
   ```

### Paso 5 — Autenticación vía API

En tests E2E, hacer login vía la UI en cada test es lento. Mejor autenticar directamente vía API:

1. Crea `e2e/auth.setup.ts`:
   ```typescript
   import { test as setup, expect } from '@playwright/test';

   const AUTH_FILE = 'e2e/.auth/user.json';

   setup('autenticar vía API', async ({ request }) => {
     const response = await request.post('/api/auth/login', {
       data: {
         email: 'usuario@test.com',
         password: 'password123',
       },
     });
     expect(response.ok()).toBeTruthy();

     // Guarda el estado de autenticación para reusar en todos los tests
     await request.storageState({ path: AUTH_FILE });
   });
   ```

2. En `playwright.config.ts`, configura el proyecto para usar auth:
   ```typescript
   projects: [
     { name: 'setup', testMatch: /.*\.setup\.ts/ },
     {
       name: 'chromium',
       use: {
         ...devices['Desktop Chrome'],
         storageState: 'e2e/.auth/user.json',
       },
       dependencies: ['setup'],
     },
   ],
   ```

3. Agrega `e2e/.auth/` a tu `.gitignore`:
   ```
   e2e/.auth/
   ```

### Paso 6 — Ejecutar y verificar

1. Ejecuta todos los tests E2E:
   ```bash
   npx playwright test
   ```

2. Para ver el reporte visual:
   ```bash
   npx playwright show-report
   ```

3. Verifica que el test completa en menos de 30 segundos. Si es más lento, revisa que estás usando auth vía API (Paso 5) en lugar de login vía UI.

## Qué puede salir mal

- **"page.goto: Target page, context or browser has been closed"** → Tu aplicación Angular no arrancó. Verifica que `ng serve` funciona manualmente y que la URL en `playwright.config.ts` es correcta.
- **"Timeout waiting for selector"** → El elemento tarda más de lo esperado en aparecer. Aumenta el timeout en el test específico: `test('...', async ({ page }) => { test.setTimeout(60000); ... })`. Pero primero verifica si tu app es lenta — puede ser un bug de rendimiento real.
- **Los tests pasan localmente pero fallan en CI** → Es probable que falte la configuración de `webServer` en `playwright.config.ts`, o que los browsers de Playwright no estén instalados en CI. Agrega `npx playwright install --with-deps` como paso previo en tu pipeline.
- **El test es flaky (a veces pasa, a veces falla)** → Verifica que usas `await expect(...).toBeVisible()` en lugar de verificar inmediatamente. Playwright auto-espera, pero necesitas usar las assertions correctas.

## Resultado esperado

Tu aplicación tiene un test E2E que recorre el camino crítico completo. El test usa Page Object Model para organizar los selectores, locators accesibles (no CSS selectors), y auth vía API para ser rápido. Puedes ejecutarlo con un solo comando y sabes que el flujo principal funciona.

**Criterios de aceptación:**
- [ ] El test E2E completa el camino crítico en menos de 30 segundos
- [ ] Se usa Page Object Model (al menos 2 page objects)
- [ ] Los locators usan `getByRole`/`getByLabel`, no CSS selectors como `.btn-primary` o `#search`
- [ ] La autenticación se hace vía API, no repitiendo el flujo de login en la UI

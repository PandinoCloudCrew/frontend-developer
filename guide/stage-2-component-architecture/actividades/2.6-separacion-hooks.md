## Por que esta actividad

En la Actividad 2.3 extrajiste datos a un servicio, pero la lógica de filtrado y estado sigue viviendo en el componente. En aplicaciones reales, quieres que la lógica de negocio sea independiente de la UI: testeeable sin renderizar ningun componente, reutilizable en diferentes vistas, y reemplazable sin tocar la presentacion. Esta actividad te enseña a separar lógica de UI usando el equivalente Angular de hooks/composables: servicios con signals.

|---|---|
| **Requiere** | Actividades 2.3 y 2.4 completadas (servicios Angular, refactorizacion) |

## Antes de empezar

Necesitas haber completado las **Actividades 2.3 y 2.4** (refactorizacion de componentes y servicios).

**¿Que es un hook/composable en el contexto de Angular?** En React se llaman "hooks", en Vue "composables". En Angular, la abstraccion equivalente son **servicios con signals**. Un servicio encapsula lógica con estado (signals, computed values) y se inyecta en los componentes que lo necesitan. La diferencia clave: la lógica vive fuera del componente, es testeable de forma aislada y reutilizable.

**¿Que es el patrón controlled vs uncontrolled?** Un componente **controlled** recibe su estado desde el padre (via inputs) y notifica cambios (via outputs). El padre es la única fuente de verdad. Un componente **uncontrolled** gestiona su propio estado interno. El padre puede leer el estado bajo demanda pero no lo controla directamente.

**¿Que es dependency injection?** Es cuando Angular crea un servicio automáticamente y se lo entrega a los componentes que lo piden. Tu no escribes `new UserFilterService()` — Angular lo hace por ti. Esto hace que sea fácil reemplazar un servicio por un mock en tests.

### Paso 1 — Crear el servicio de filtrado

1. Genera el servicio:
   ```bash
   ng g service services/user-filter
   ```

2. Abre `src/app/services/user-filter.service.ts` y reemplaza por:
   ```typescript
   import { Injectable, signal, computed } from '@angular/core';
   import { User } from './user.service';

   @Injectable({
     providedIn: 'root',
   })
   export class UserFilterService {
     // Estado del filtrado
     private allUsers = signal<User[]>([]);
     searchTerm = signal('');
     selectedCity = signal('');
     selectedRole = signal('');
     sortField = signal<keyof User>('name');
     sortDirection = signal<'asc' | 'desc'>('asc');
     currentPage = signal(1);
     pageSize = signal(3);

     // Computed values
     cities = computed(() => {
       const allCities = this.allUsers().map(u => u.city);
       return [...new Set(allCities)].sort();
     });

     filteredUsers = computed(() => {
       let result = this.allUsers();

       if (this.searchTerm()) {
         const term = this.searchTerm().toLowerCase();
         result = result.filter(u =>
           u.name.toLowerCase().includes(term) ||
           u.email.toLowerCase().includes(term)
         );
       }

       if (this.selectedCity()) {
         result = result.filter(u => u.city === this.selectedCity());
       }

       if (this.selectedRole()) {
         result = result.filter(u => u.role === this.selectedRole());
       }

       return [...result].sort((a, b) => {
         const field = this.sortField();
         const dir = this.sortDirection() === 'asc' ? 1 : -1;
         if (a[field] < b[field]) return -1 * dir;
         if (a[field] > b[field]) return 1 * dir;
         return 0;
       });
     });

     paginatedUsers = computed(() => {
       const start = (this.currentPage() - 1) * this.pageSize();
       return this.filteredUsers().slice(start, start + this.pageSize());
     });

     totalPages = computed(() =>
       Math.ceil(this.filteredUsers().length / this.pageSize())
     );

     // Metodos publicos
     setUsers(users: User[]) {
       this.allUsers.set(users);
     }

     search(term: string) {
       this.searchTerm.set(term);
       this.currentPage.set(1);
     }

     filterByCity(city: string) {
       this.selectedCity.set(city);
       this.currentPage.set(1);
     }

     filterByRole(role: string) {
       this.selectedRole.set(role);
       this.currentPage.set(1);
     }

     sort(field: keyof User) {
       if (this.sortField() === field) {
         this.sortDirection.set(this.sortDirection() === 'asc' ? 'desc' : 'asc');
       } else {
         this.sortField.set(field);
         this.sortDirection.set('asc');
       }
     }

     goToPage(page: number) {
       this.currentPage.set(page);
     }

     reset() {
       this.searchTerm.set('');
       this.selectedCity.set('');
       this.selectedRole.set('');
       this.sortField.set('name');
       this.sortDirection.set('asc');
       this.currentPage.set(1);
     }
   }
   ```

> 💡 **Nota:** Toda la lógica de filtrado, ordenamiento y paginación vive ahora en el servicio. El componente solo necesita llamar a los metodos del servicio y leer sus computed values.

### Paso 2 — Simplificar el dashboard

1. Abre `src/app/user-dashboard/user-dashboard.component.ts` y reemplaza por:
   ```typescript
   import { Component, inject, OnInit } from '@angular/core';
   import { UserService } from '../services/user.service';
   import { UserFilterService } from '../services/user-filter.service';
   import { UserFiltersComponent } from '../user-filters/user-filters.component';
   import { UserTableComponent } from '../user-table/user-table.component';
   import { PaginationComponent } from '../pagination/pagination.component';

   @Component({
     selector: 'app-user-dashboard',
     standalone: true,
     imports: [UserFiltersComponent, UserTableComponent, PaginationComponent],
     templateUrl: './user-dashboard.component.html',
   })
   export class UserDashboardComponent implements OnInit {
     private userService = inject(UserService);
     filter = inject(UserFilterService);

     ngOnInit() {
       this.filter.setUsers(this.userService.getUsers()());
     }
   }
   ```

2. Abre `src/app/user-dashboard/user-dashboard.component.html` y reemplaza por:
   ```text
   <!-- HTML: dashboard simplificado -->
   <section class="dashboard">
     <h2>Panel de Usuarios</h2>

     <app-user-filters
       [cities]="filter.cities()"
       (searchChanged)="filter.search($event)"
       (cityChanged)="filter.filterByCity($event)"
       (roleChanged)="filter.filterByRole($event)"
     />

     <app-user-table
       [users]="filter.paginatedUsers()"
       (sortRequested)="filter.sort($event)"
     />

     <app-pagination
       [currentPage]="filter.currentPage()"
       [totalPages]="filter.totalPages()"
       (pageChanged)="filter.goToPage($event)"
     />

     <p>
       Mostrando {{ filter.paginatedUsers().length }} de {{ filter.filteredUsers().length }} usuarios
       (pagina {{ filter.currentPage() }} de {{ filter.totalPages() }})
     </p>
   </section>
   ```

> 💡 **Nota:** El componente dashboard ahora tiene ~15 lineas de TypeScript. Toda la lógica esta en el servicio. El componente solo hace dos cosas: inicializar los datos y conectar los sub-componentes con el servicio.

### Paso 3 — Crear un componente controlled

Un componente controlled recibe todo su estado desde afuera y nunca lo modifica internamente.

1. Genera el componente:
   ```bash
   ng g c text-input
   ```

2. Abre `src/app/text-input/text-input.component.ts` y reemplaza por:
   ```typescript
   import { Component, input, output } from '@angular/core';

   @Component({
     selector: 'app-text-input',
     standalone: true,
     template: `
       <label [for]="inputId()">{{ label() }}</label>
       <input
         [id]="inputId()"
         type="text"
         [value]="value()"
         (input)="onInput($event)"
       />
     `,
   })
   export class TextInputComponent {
     inputId = input.required<string>();
     label = input.required<string>();
     value = input.required<string>();
     valueChanged = output<string>();

     onInput(event: Event) {
       const target = event.target as HTMLInputElement;
       this.valueChanged.emit(target.value);
     }
   }
   ```

Este es un componente **controlled**: el padre le dice que valor mostrar (`value`) y el componente solo notifica cambios (`valueChanged`). El padre es la fuente de verdad.

### Paso 4 — Crear un componente uncontrolled

Un componente uncontrolled gestiona su propio estado interno.

1. Genera el componente:
   ```bash
   ng g c search-input
   ```

2. Abre `src/app/search-input/search-input.component.ts` y reemplaza por:
   ```typescript
   import { Component, input, output, signal } from '@angular/core';

   @Component({
     selector: 'app-search-input',
     standalone: true,
     template: `
       <label [for]="inputId()">{{ label() }}</label>
       <input
         [id]="inputId()"
         type="text"
         [value]="internalValue()"
         (input)="onInput($event)"
         [placeholder]="placeholder()"
       />
     `,
   })
   export class SearchInputComponent {
     inputId = input<string>('search');
     label = input<string>('Buscar');
     placeholder = input<string>('Escribe para buscar...');
     defaultValue = input<string>('');
     searched = output<string>();

     internalValue = signal('');

     onInput(event: Event) {
       const target = event.target as HTMLInputElement;
       this.internalValue.set(target.value);
       this.searched.emit(target.value);
     }
   }
   ```

Este es un componente **uncontrolled**: gestiona su propio estado (`internalValue`) y opcionalmente notifica al padre cuando algo cambia. El padre no controla el valor — solo lo recibe si quiere.

### Paso 5 — Testear el servicio sin UI

1. Abre `src/app/services/user-filter.service.spec.ts` (creado automáticamente por Angular CLI)
2. Reemplaza su contenido por:
   ```typescript
   import { TestBed } from '@angular/core/testing';
   import { UserFilterService } from './user-filter.service';
   import { User } from './user.service';

   describe('UserFilterService', () => {
     let service: UserFilterService;

     const mockUsers: User[] = [
       { id: 1, name: 'Ana Garcia', email: 'ana@mail.com', city: 'Madrid', role: 'admin', salary: 55000 },
       { id: 2, name: 'Carlos Lopez', email: 'carlos@mail.com', city: 'Barcelona', role: 'editor', salary: 42000 },
       { id: 3, name: 'Diana Ruiz', email: 'diana@mail.com', city: 'Madrid', role: 'viewer', salary: 38000 },
     ];

     beforeEach(() => {
       TestBed.configureTestingModule({});
       service = TestBed.inject(UserFilterService);
       service.setUsers(mockUsers);
     });

     it('should filter by search term', () => {
       service.search('ana');
       expect(service.filteredUsers().length).toBe(1);
       expect(service.filteredUsers()[0].name).toBe('Ana Garcia');
     });

     it('should filter by city', () => {
       service.filterByCity('Madrid');
       expect(service.filteredUsers().length).toBe(2);
     });

     it('should reset filters', () => {
       service.search('ana');
       service.filterByCity('Madrid');
       service.reset();
       expect(service.filteredUsers().length).toBe(3);
     });

     it('should paginate correctly', () => {
       service.pageSize.set(2);
       expect(service.paginatedUsers().length).toBe(2);
       expect(service.totalPages()).toBe(2);
     });
   });
   ```

3. En la terminal, ejecuta los tests:
   ```bash
   ng test --watch=false
   ```

4. Deberas ver que los 4 tests pasan. **Esto es lo importante:** probaste toda la lógica de filtrado sin renderizar ningun componente.

## Que puede salir mal

- **"Los tests fallan con 'NullInjectorError'"** → Asegurate de que `UserFilterService` tiene `providedIn: 'root'` y que estas usando `TestBed.inject(UserFilterService)` para obtener la instancia.
- **"El dashboard no muestra datos despues de refactorizar"** → Verifica que `ngOnInit()` llama a `this.filter.setUsers(...)` con los datos del `UserService`.
- **"No entiendo la diferencia entre controlled y uncontrolled"** → Controlled: el padre dice que mostrar (`[value]="algo"`). Uncontrolled: el componente decide que mostrar internamente. La pista: si el componente tiene un `signal` interno para el valor, es uncontrolled. Si recibe el valor como input, es controlled.

## Resultado esperado

El dashboard funciona igual que antes, pero la lógica de filtrado vive en `UserFilterService`. El componente `UserDashboardComponent` tiene ~15 lineas. Los tests del servicio pasan sin renderizar UI. Tienes un ejemplo de componente controlled (`TextInput`) y uno uncontrolled (`SearchInput`).

**Criterios de aceptacion:**
- [ ] La lógica de negocio (filtrado, paginación) vive en `UserFilterService`, no en componentes
- [ ] Los tests del servicio pasan sin renderizar ningun componente (`ng test --watch=false`)
- [ ] Existe al menos un componente controlled (`TextInput`) y uno uncontrolled (`SearchInput`)

**Pilares de diseño que ejercita esta actividad:**
- **Mantenibilidad** — la lógica separada de la UI es mas fácil de entender, testear y reutilizar
- **Observabilidad** — servicios con estado explícito (signals) hacen visible el flujo de datos

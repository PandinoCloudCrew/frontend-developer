## Por qué esta actividad

Los formularios son la forma principal en que los usuarios envían datos a tu aplicación. Pero gestionar su estado es sorprendentemente complejo: ¿cuándo muestras los errores? ¿Qué pasa si el usuario hace click en "Enviar" dos veces seguidas? ¿Cómo validas datos complejos como un RFC o una fecha de nacimiento válida? Si no resuelves esto bien, tu usuario verá errores confusos, enviará datos corruptos, o hará doble submit y se le cobrará dos veces.

## Antes de empezar

Necesitas tener completadas las **Actividades 3.1 y 3.2** — sabes crear componentes, consumir APIs, y manejar señales.

Los **Reactive Forms** de Angular son una forma de definir formularios en TypeScript (no en el template). Tú creas un objeto `FormGroup` con campos (`FormControl`), le asignas validaciones, y Angular se encarga de rastrear el estado de cada campo (¿fue tocado? ¿es válido? ¿cambió?).

**Zod** es una librería de validación basada en schemas. En lugar de escribir `if (nombre.length < 3)` en muchos lugares, defines un schema una vez (`z.string().min(3)`) y lo reutilizas en el frontend y el backend.

La **estrategia on-blur** significa mostrar errores de validación solo cuando el usuario sale de un campo (hace "blur"). Mostrar errores mientras el usuario todavía está escribiendo es molesto y confuso.

### Paso 1 — Instalar Zod

1. En la terminal de VS Code, dentro de la carpeta del proyecto, ejecuta:
   ```bash
   npm install zod
   ```

> 💡 **Nota:** Zod no tiene dependencias — es una librería pequeña (< 50 KB) que funciona en el navegador y en el servidor.

### Paso 2 — Crear el schema de validación

1. Crea el archivo `src/app/schemas/contact.schema.ts`
2. Escribe el schema:

```typescript
// src/app/schemas/contact.schema.ts
import { z } from 'zod';

export const contactSchema = z.object({
  name: z.string()
    .min(2, 'El nombre debe tener al menos 2 caracteres'),
  email: z.string()
    .email('Ingresa un correo electrónico válido'),
  subject: z.string()
    .min(5, 'El asunto debe tener al menos 5 caracteres'),
  message: z.string()
    .min(10, 'El mensaje debe tener al menos 10 caracteres')
    .max(500, 'El mensaje no puede superar 500 caracteres'),
});

export type ContactForm = z.infer<typeof contactSchema>;
```

> 💡 **Nota:** `z.infer<typeof contactSchema>` genera automáticamente el tipo TypeScript a partir del schema. No necesitas definir la interface por separado — el schema es la fuente de verdad tanto para la validación como para los tipos.

### Paso 3 — Crear el componente de formulario

1. Ejecuta en la terminal:
   ```bash
   ng generate component contact-form --standalone
   ```
2. Abre `src/app/contact-form/contact-form.component.ts`
3. Reemplaza su contenido por:

```typescript
// src/app/contact-form/contact-form.component.ts
import { Component, inject, signal } from '@angular/core';
import { ReactiveFormsModule, FormBuilder, Validators } from '@angular/forms';
import { contactSchema } from '../schemas/contact.schema';

type SubmitState = 'idle' | 'submitting' | 'success' | 'error';

@Component({
  selector: 'app-contact-form',
  standalone: true,
  imports: [ReactiveFormsModule],
  templateUrl: './contact-form.component.html',
  styleUrl: './contact-form.component.css'
})
export class ContactFormComponent {
  private fb = inject(FormBuilder);

  submitState = signal<SubmitState>('idle');
  fieldErrors = signal<Record<string, string>>({});

  form = this.fb.group({
    name: ['', Validators.required],
    email: ['', [Validators.required, Validators.email]],
    subject: ['', Validators.required],
    message: ['', Validators.required],
  });

  validateField(fieldName: string) {
    const value = this.form.getRawValue();
    const result = contactSchema.safeParse(value);

    if (!result.success) {
      const fieldError = result.error.issues.find(
        issue => issue.path[0] === fieldName
      );
      if (fieldError) {
        this.fieldErrors.update(errors => ({
          ...errors,
          [fieldName]: fieldError.message
        }));
      } else {
        // El campo es válido — limpiar el error
        this.fieldErrors.update(errors => {
          const { [fieldName]: _, ...rest } = errors;
          return rest;
        });
      }
    } else {
      // Todo el formulario es válido — limpiar el error del campo
      this.fieldErrors.update(errors => {
        const { [fieldName]: _, ...rest } = errors;
        return rest;
      });
    }
  }

  async onSubmit() {
    // Validar todo el formulario con Zod
    const result = contactSchema.safeParse(this.form.getRawValue());

    if (!result.success) {
      const errors: Record<string, string> = {};
      result.error.issues.forEach(issue => {
        const field = issue.path[0] as string;
        errors[field] = issue.message;
      });
      this.fieldErrors.set(errors);
      return;
    }

    // Prevenir double-submit
    if (this.submitState() === 'submitting') return;

    this.submitState.set('submitting');

    try {
      // Simular envío al servidor (2 segundos)
      await new Promise(resolve => setTimeout(resolve, 2000));
      this.submitState.set('success');
      this.form.reset();
      this.fieldErrors.set({});
    } catch {
      this.submitState.set('error');
    }
  }
}
```

### Paso 4 — Template con errores on-blur

1. Abre `src/app/contact-form/contact-form.component.html`
2. Reemplaza su contenido por:

```text
<!-- HTML: src/app/contact-form/contact-form.component.html -->
<form [formGroup]="form" (ngSubmit)="onSubmit()">
  <div class="field">
    <label for="name">Nombre</label>
    <input
      id="name"
      formControlName="name"
      (blur)="validateField('name')"
      [attr.aria-invalid]="fieldErrors()['name'] ? 'true' : null"
    />
    @if (fieldErrors()['name']) {
      <p class="error" role="alert">{{ fieldErrors()['name'] }}</p>
    }
  </div>

  <div class="field">
    <label for="email">Correo electrónico</label>
    <input
      id="email"
      type="email"
      formControlName="email"
      (blur)="validateField('email')"
      [attr.aria-invalid]="fieldErrors()['email'] ? 'true' : null"
    />
    @if (fieldErrors()['email']) {
      <p class="error" role="alert">{{ fieldErrors()['email'] }}</p>
    }
  </div>

  <div class="field">
    <label for="subject">Asunto</label>
    <input
      id="subject"
      formControlName="subject"
      (blur)="validateField('subject')"
      [attr.aria-invalid]="fieldErrors()['subject'] ? 'true' : null"
    />
    @if (fieldErrors()['subject']) {
      <p class="error" role="alert">{{ fieldErrors()['subject'] }}</p>
    }
  </div>

  <div class="field">
    <label for="message">Mensaje</label>
    <textarea
      id="message"
      formControlName="message"
      rows="5"
      (blur)="validateField('message')"
      [attr.aria-invalid]="fieldErrors()['message'] ? 'true' : null"
    ></textarea>
    @if (fieldErrors()['message']) {
      <p class="error" role="alert">{{ fieldErrors()['message'] }}</p>
    }
  </div>

  <button
    type="submit"
    [disabled]="submitState() === 'submitting'"
  >
    @if (submitState() === 'submitting') {
      Enviando...
    } @else {
      Enviar mensaje
    }
  </button>

  @if (submitState() === 'success') {
    <p class="success" role="status">¡Mensaje enviado correctamente!</p>
  }

  @if (submitState() === 'error') {
    <p class="error" role="alert">Error al enviar. Inténtalo de nuevo.</p>
  }
</form>
```

### Paso 5 — Prevenir double-submit

El mecanismo ya está implementado en el componente:

1. Cuando el usuario hace click en "Enviar", `submitState` cambia a `'submitting'`
2. El botón se deshabilita con `[disabled]="submitState() === 'submitting'"`
3. El texto cambia a "Enviando..."
4. Si el usuario intenta enviar otra vez, la línea `if (this.submitState() === 'submitting') return;` bloquea la ejecución

Para verificar que funciona:
1. Abre DevTools → Network → Throttling → "Slow 3G"
2. Llena el formulario correctamente
3. Haz click en "Enviar" — el botón debe cambiar a "Enviando..." y deshabilitarse
4. Intenta hacer click repetidamente — no debe enviar múltiples veces

### Paso 6 — Validar el comportamiento

1. **On-blur:** Haz click en el campo "Nombre", no escribas nada, haz click fuera del campo. Debe aparecer el error. No debe aparecer mientras escribes.
2. **Mensajes claros:** Escribe solo una letra en "Nombre". Al salir del campo, debe decir "El nombre debe tener al menos 2 caracteres", no un error genérico como "Campo inválido".
3. **Double-submit:** Con Slow 3G activado, envía el formulario y verifica que el botón se deshabilita inmediatamente.
4. **Éxito:** Llena todo correctamente y envía. Debe aparecer "¡Mensaje enviado correctamente!" y el formulario debe resetearse.

## Qué puede salir mal

- **"Los errores aparecen mientras escribo, no al salir del campo"** → Verifica que estás usando `(blur)="validateField('name')"` y no `(input)` o `(keyup)`. El evento `blur` se dispara solo cuando el cursor sale del campo.
- **"No se muestra ningún error"** → Verifica que importaste `ReactiveFormsModule` en el array `imports` del componente. Sin esto, Angular no entiende `[formGroup]` ni `formControlName`.
- **"El botón de enviar no se deshabilita"** → Verifica que el binding es `[disabled]="submitState() === 'submitting'"` con paréntesis en `submitState()` (es un signal, hay que llamarlo como función).
- **"Error: Cannot find module 'zod'"** → Ejecuta `npm install zod` en la carpeta del proyecto. Verifica que estás en la carpeta correcta (donde está `package.json`).

## Resultado esperado

Tu formulario valida campos al perder el foco (on-blur), muestra mensajes de error específicos por campo, y previene el envío múltiple. El schema Zod es la fuente de verdad para la validación.

**Criterios de aceptación:**
- [ ] Validación on-blur: los errores aparecen al salir del campo, no mientras se escribe
- [ ] Se usa Zod como schema de validación (la validación no está dispersa en el template)
- [ ] El botón de envío muestra "Enviando..." y se deshabilita durante el submit
- [ ] Al completar el envío, aparece un mensaje de éxito y el formulario se resetea

**Pilares de diseño ejercitados:**
- **Usabilidad** — Los errores no interrumpen al usuario mientras escribe. Los mensajes son específicos y accionables.
- **Resiliencia** — El double-submit está prevenido. El formulario maneja correctamente éxito y error.
- **Mantenibilidad** — El schema Zod centraliza las reglas de validación en un solo lugar.

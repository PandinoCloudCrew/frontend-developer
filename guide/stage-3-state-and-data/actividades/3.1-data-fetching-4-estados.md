## Por qué esta actividad

Cuando una aplicación obtiene datos de un servidor, la respuesta no llega al instante. Si no manejas ese tiempo de espera, el usuario ve una pantalla vacía y piensa que la app está rota. Peor aún: si la petición falla, no sabe qué pasó ni qué hacer. Los 4 estados de data fetching (loading, success, error, empty) son la diferencia entre una app que se siente profesional y una que se siente abandonada.

## Antes de empezar

Necesitas tener completada la **Etapa 2** — sabes crear componentes Angular standalone, usar signals, y renderizar condicionalmente con `@if`.

Necesitas tener un proyecto Angular funcionando. Si no lo tienes, ejecuta `ng new data-fetching-app --standalone` en la terminal.

Un **estado de UI** es la "cara" que tu aplicación le muestra al usuario en un momento dado. Cuando pides datos a un servidor, tu app pasa por estos momentos:
1. **Loading** — los datos aún no llegaron. Muestra un skeleton o spinner.
2. **Success** — los datos llegaron. Muestra el contenido.
3. **Error** — algo falló (sin internet, servidor caído). Muestra qué pasó y cómo reintentar.
4. **Empty** — la petición fue exitosa pero no hay datos. Muestra una guía útil, no una pantalla vacía.

Un **service** en Angular es una clase que se encarga de una tarea específica (como obtener datos de un servidor). Vive fuera de los componentes para que varios componentes puedan usarlo. Angular lo crea automáticamente y lo "inyecta" donde lo necesites.

### Paso 1 — Crear el servicio

1. En la terminal de VS Code, dentro de la carpeta del proyecto, ejecuta:
   ```bash
   ng generate service services/products
   ```
2. Abre el archivo `src/app/services/products.service.ts`
3. Reemplaza su contenido por:

```typescript
// src/app/services/products.service.ts
import { Injectable, inject } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable } from 'rxjs';

export interface Product {
  id: number;
  title: string;
  price: number;
  description: string;
}

@Injectable({ providedIn: 'root' })
export class ProductsService {
  private http = inject(HttpClient);
  private apiUrl = 'https://fakestoreapi.com/products';

  getProducts(): Observable<Product[]> {
    return this.http.get<Product[]>(this.apiUrl);
  }
}
```

> 💡 **Nota:** `@Injectable({ providedIn: 'root' })` le dice a Angular: "crea una sola instancia de este servicio y compártela con toda la app". `inject(HttpClient)` es la forma moderna de pedir a Angular que te dé acceso al servicio HTTP.

### Paso 2 — Definir el modelo de datos

1. Abre `src/app/app.config.ts`
2. Asegúrate de que `provideHttpClient()` esté en los providers:

```typescript
// src/app/app.config.ts
import { ApplicationConfig } from '@angular/core';
import { provideHttpClient } from '@angular/common/http';

export const appConfig: ApplicationConfig = {
  providers: [
    provideHttpClient()
  ]
};
```

> 💡 **Nota:** Sin `provideHttpClient()`, Angular no sabe cómo hacer peticiones HTTP y verás un error de inyección. Es como enchufar la manguera antes de abrir la llave.

### Paso 3 — Crear el componente con los 4 estados

1. Ejecuta en la terminal:
   ```bash
   ng generate component product-list --standalone
   ```
2. Abre `src/app/product-list/product-list.component.ts`
3. Reemplaza su contenido por:

```typescript
// src/app/product-list/product-list.component.ts
import { Component, inject, signal, OnInit } from '@angular/core';
import { ProductsService, Product } from '../services/products.service';

type UIState = 'loading' | 'success' | 'error' | 'empty';

@Component({
  selector: 'app-product-list',
  standalone: true,
  templateUrl: './product-list.component.html',
  styleUrl: './product-list.component.css'
})
export class ProductListComponent implements OnInit {
  private productsService = inject(ProductsService);

  state = signal<UIState>('loading');
  products = signal<Product[]>([]);
  errorMessage = signal('');

  ngOnInit() {
    this.loadProducts();
  }

  loadProducts() {
    this.state.set('loading');

    this.productsService.getProducts().subscribe({
      next: (data) => {
        if (data.length === 0) {
          this.state.set('empty');
        } else {
          this.products.set(data);
          this.state.set('success');
        }
      },
      error: (err) => {
        this.errorMessage.set('No pudimos cargar los productos. Verifica tu conexión.');
        this.state.set('error');
      }
    });
  }
}
```

> 💡 **Nota:** Usamos un signal de tipo `UIState` con solo 4 valores posibles. Esto hace que TypeScript te avise si olvidas manejar alguno. El método `loadProducts()` es separado de `ngOnInit()` para poder llamarlo de nuevo cuando el usuario quiera reintentar.

### Paso 4 — Template con los 4 estados

1. Abre `src/app/product-list/product-list.component.html`
2. Reemplaza su contenido por:

```text
<!-- HTML: src/app/product-list/product-list.component.html -->
@if (state() === 'loading') {
  <div class="skeleton-list">
    <div class="skeleton-card"></div>
    <div class="skeleton-card"></div>
    <div class="skeleton-card"></div>
  </div>
}

@if (state() === 'error') {
  <div class="error-state">
    <p>{{ errorMessage() }}</p>
    <button (click)="loadProducts()">Reintentar</button>
  </div>
}

@if (state() === 'empty') {
  <div class="empty-state">
    <h2>No hay productos todavía</h2>
    <p>Cuando se agreguen productos, aparecerán aquí.</p>
  </div>
}

@if (state() === 'success') {
  <ul class="product-list">
    @for (product of products(); track product.id) {
      <li class="product-card">
        <h3>{{ product.title }}</h3>
        <p class="price">$ {{ product.price }}</p>
      </li>
    }
  </ul>
}
```

### Paso 5 — Agregar reintentar

1. Abre `src/app/app.component.ts`
2. Importa y usa el componente:

```typescript
// src/app/app.component.ts
import { Component } from '@angular/core';
import { ProductListComponent } from './product-list/product-list.component';

@Component({
  selector: 'app-root',
  standalone: true,
  imports: [ProductListComponent],
  template: `
    <main>
      <h1>Tienda de Productos</h1>
      <app-product-list />
    </main>
  `
})
export class AppComponent {}
```

3. Ejecuta la app:
   ```bash
   ng serve
   ```
4. Abre `http://localhost:4200` en el navegador

### Paso 6 — Validar los 4 estados

1. **Loading:** Abre DevTools → Network → Throttling → selecciona "Slow 3G". Recarga la página. Deberías ver las tarjetas skeleton animándose mientras se cargan los datos.
2. **Success:** Cambia Throttling de vuelta a "No throttling". Recarga. Deberías ver la lista de productos.
3. **Error:** En DevTools → Network, activa "Offline" (el checkbox). Haz click en "Reintentar". Deberías ver el mensaje de error con el botón.
4. **Empty:** Para probar el estado vacío, cambia temporalmente la URL de la API en `products.service.ts` a una que devuelva un array vacío, o modifica el `next` callback para simular `data = []`.

## Qué puede salir mal

- **"NullInjectorError: No provider for HttpClient"** → Olvidaste agregar `provideHttpClient()` en `app.config.ts`. Angular no sabe hacer peticiones HTTP sin esto. Abre `src/app/app.config.ts` y agrega `provideHttpClient()` al array de `providers`.
- **"El skeleton aparece un instante y desaparece"** → Tu conexión es muy rápida. Usa DevTools → Network → Slow 3G para simular una conexión lenta y verificar que el skeleton se muestra. En producción, tus usuarios con conexiones móviles sí lo verán.
- **"No veo nada, la pantalla está en blanco"** → Verifica que `<app-product-list />` está en el template de `app.component.ts` y que importaste `ProductListComponent` en el array `imports`.

## Resultado esperado

Tu aplicación muestra correctamente los 4 estados dependiendo de la situación de la red y los datos. El skeleton se anima suavemente mientras carga, los productos aparecen en tarjetas cuando llegan, el error muestra un mensaje claro con un botón para reintentar, y el estado vacío guía al usuario.

**Criterios de aceptación:**
- [ ] Skeleton/spinner visible en conexión lenta (verificado con Slow 3G en DevTools)
- [ ] Error con botón "Reintentar" al activar modo Offline en DevTools
- [ ] Empty state descriptivo cuando la API devuelve un array vacío
- [ ] Sin flash de contenido entre estados (no se ve un parpadeo al cambiar de loading a success)

**Pilares de diseño ejercitados:**
- **Resiliencia** — ¿Qué pasa cuando la red falla? Muestras un error claro con acción de recuperación.
- **Usabilidad** — ¿El usuario sabe qué está pasando? El skeleton le dice "estamos cargando", no lo deja adivinando.

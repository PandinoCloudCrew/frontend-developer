## Por qué esta actividad

En la Actividad 3.5 construiste un wizard con `if`/`switch` para controlar los pasos. Funciona, pero tiene un problema: nada impide que tu código ponga el wizard en un estado imposible — por ejemplo, "en el paso de pago pero sin datos de envío". Con `if` anidados, cada nuevo estado requiere más condicionales y más posibilidades de bugs. Una **state machine** (máquina de estado) define exactamente qué estados existen y qué transiciones son válidas — los estados imposibles son literalmente imposibles por definición.

## Antes de empezar

Necesitas tener completada la **Actividad 3.5** — un wizard de checkout funcionando con 4 pasos.

Una **state machine** (máquina de estado) es un modelo que define:
1. **Estados** — las "situaciones" posibles (carrito, envío, pago, confirmación)
2. **Transiciones** — las "acciones" que te mueven de un estado a otro (NEXT, BACK)
3. **Guardas** — condiciones que deben cumplirse para que una transición ocurra (validación del paso actual)

La idea clave es: si una transición no está definida, no puede ocurrir. No necesitas escribir `if (currentStep !== 'cart') return;` — simplemente no defines esa transición y es imposible.

**XState** es la librería más popular para state machines en JavaScript/TypeScript. Define la máquina como un objeto declarativo que puedes visualizar como un diagrama.

### Paso 2 — Definir la máquina de checkout

1. Crea el archivo `src/app/machines/checkout.machine.ts`:

```typescript
// src/app/machines/checkout.machine.ts
import { setup } from 'xstate';

export interface CheckoutContext {
  cartValid: boolean;
  shippingValid: boolean;
  paymentValid: boolean;
}

export const checkoutMachine = setup({
  types: {
    context: {} as CheckoutContext,
    events: {} as
      | { type: 'NEXT' }
      | { type: 'BACK' }
      | { type: 'VALIDATE_CART'; valid: boolean }
      | { type: 'VALIDATE_SHIPPING'; valid: boolean }
      | { type: 'VALIDATE_PAYMENT'; valid: boolean }
      | { type: 'CONFIRM' }
      | { type: 'RESET' },
  },
  guards: {
    isCartValid: ({ context }) => context.cartValid,
    isShippingValid: ({ context }) => context.shippingValid,
    isPaymentValid: ({ context }) => context.paymentValid,
  },
}).createMachine({
  id: 'checkout',
  initial: 'cart',
  context: {
    cartValid: true,
    shippingValid: false,
    paymentValid: false,
  },
  states: {
    cart: {
      on: {
        NEXT: {
          target: 'shipping',
          guard: 'isCartValid',
        },
      },
    },
    shipping: {
      on: {
        NEXT: {
          target: 'payment',
          guard: 'isShippingValid',
        },
        BACK: { target: 'cart' },
        VALIDATE_SHIPPING: {
          actions: ({ context, event }) => {
            context.shippingValid = event.valid;
          },
        },
      },
    },
    payment: {
      on: {
        NEXT: {
          target: 'confirmation',
          guard: 'isPaymentValid',
        },
        BACK: { target: 'shipping' },
        VALIDATE_PAYMENT: {
          actions: ({ context, event }) => {
            context.paymentValid = event.valid;
          },
        },
      },
    },
    confirmation: {
      on: {
        BACK: { target: 'payment' },
        CONFIRM: { target: 'done' },
      },
    },
    done: {
      type: 'final',
    },
  },
});
```

> 💡 **Nota:** Observa que desde `cart` solo puedes ir a `shipping` (no a `payment`). Desde `confirmation` solo puedes volver a `payment` (no a `cart`). Estas restricciones están en la definición de la máquina — no son `if` que puedes olvidar.

### Paso 3 — Crear servicio que usa la máquina

1. Crea `src/app/services/checkout-machine.service.ts`:

::: code-group
```typescript [Angular]
// src/app/services/checkout-machine.service.ts
import { Injectable, signal, computed } from '@angular/core';
import { createActor } from 'xstate';
import { checkoutMachine } from '../machines/checkout.machine';

@Injectable({ providedIn: 'root' })
export class CheckoutMachineService {
  private actor = createActor(checkoutMachine);

  currentState = signal(this.actor.getSnapshot().value);

  stepNumber = computed(() => {
    const stateMap: Record<string, number> = {
      cart: 1,
      shipping: 2,
      payment: 3,
      confirmation: 4,
      done: 4,
    };
    return stateMap[this.currentState() as string] || 1;
  });

  constructor() {
    this.actor.subscribe(snapshot => {
      this.currentState.set(snapshot.value as string);
    });
    this.actor.start();
  }

  send(event: { type: string; [key: string]: unknown }) {
    this.actor.send(event as any);
  }

  next() {
    this.send({ type: 'NEXT' });
  }

  back() {
    this.send({ type: 'BACK' });
  }

  validateShipping(valid: boolean) {
    this.send({ type: 'VALIDATE_SHIPPING', valid });
  }

  validatePayment(valid: boolean) {
    this.send({ type: 'VALIDATE_PAYMENT', valid });
  }

  confirm() {
    this.send({ type: 'CONFIRM' });
  }

  reset() {
    this.actor.stop();
    this.actor = createActor(checkoutMachine);
    this.actor.subscribe(snapshot => {
      this.currentState.set(snapshot.value as string);
    });
    this.actor.start();
  }
}
```

### Paso 5 — Probar transiciones inválidas

1. Abre la consola del navegador (DevTools → Console)
2. Intenta enviar transiciones inválidas desde la consola o desde el código:
   - Desde el paso "carrito", intenta enviar `BACK` — no debe hacer nada (no hay transición `BACK` en el estado `cart`)
   - Desde "carrito", intenta enviar `CONFIRM` — no debe hacer nada (esa transición solo existe en `confirmation`)
   - Desde "confirmación", intenta enviar dos veces `BACK` seguidos y verifica que llegas a `payment`, no a `cart`

3. Verifica que la máquina impide saltar pasos:
   - Desde `cart`, no puedes llegar a `payment` directamente — necesitas pasar por `shipping`
   - Desde `confirmation`, no puedes volver a `cart` directamente — necesitas pasar por `payment` y luego `shipping`

## Qué puede salir mal

- **"Error: Cannot find module 'xstate'"** → Ejecuta `npm install xstate @xstate/angular` en la carpeta del proyecto.
- **"La máquina no avanza de estado"** → Verifica que la guarda del estado actual se cumple. Por ejemplo, si `isCartValid` retorna `false`, la transición `NEXT` desde `cart` no ocurre. Revisa el contexto de la máquina.
- **"El componente no se actualiza cuando cambia el estado"** → Verifica que estás suscrito al actor con `actor.subscribe()` y que actualizas el signal `currentState` en cada cambio.

## Resultado esperado

Tu wizard funciona igual que antes desde el punto de vista del usuario, pero la lógica de transiciones está formalizada en una state machine. Los estados imposibles son imposibles por definición, no por `if` dispersos en el código.

**Criterios de aceptación:**
- [ ] La máquina impide saltar de "carrito" a "pago" directamente (solo puede avanzar un paso a la vez)
- [ ] Los estados imposibles son imposibles por definición (no hay transición que los permita)
- [ ] Las transiciones que requieren validación (NEXT) tienen guardas que verifican el paso actual

**Pilares de diseño ejercitados:**
- **Mantenibilidad** — La lógica de estados está centralizada en un objeto declarativo, no dispersa en `if`/`switch` por los componentes.
- **Resiliencia** — Los bugs de "estado imposible" son eliminados por diseño, no por código defensivo.

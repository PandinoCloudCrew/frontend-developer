## Por qué esta actividad

Los principiantes meten todo en el mismo lugar: datos del servidor, estado de la UI, filtros, datos derivados. Todo son signals o variables en el componente. Esto funciona al principio, pero cuando la app crece, el componente se vuelve un monstruo de 300 líneas que nadie entiende. Separar estado por tipo (local, servidor, derivado, URL) te da claridad sobre dónde vive cada dato y quién lo actualiza — y te prepara para apps reales donde múltiples componentes comparten datos.

## Antes de empezar

Necesitas tener completadas las **Actividades 3.1 a 3.3** — tu aplicación ya consume una API, usa query params en la URL, y tiene un formulario.

El **estado** de una aplicación es toda la información que determina lo que el usuario ve en pantalla en un momento dado. No todo el estado es igual. Hay 4 tipos principales:

1. **Estado local** — solo le importa a un componente. Ejemplo: si un dropdown está abierto o cerrado, si un tooltip es visible.
2. **Estado del servidor** — datos que vienen de una API. Ejemplo: lista de productos, perfil del usuario. No lo creas tú, lo lees del servidor.
3. **Estado derivado** — se calcula a partir de otro estado. Ejemplo: "total del carrito" se calcula sumando los precios de los items. No necesita su propio signal.
4. **Estado de URL** — filtros, paginación, búsqueda. Ya lo trabajaste en la Actividad 3.2.

Un **servicio** en Angular es una clase decorada con `@Injectable()` que vive fuera de los componentes. Cuando varios componentes necesitan los mismos datos (por ejemplo, el carrito de compras), el servicio los almacena en un solo lugar. Angular se encarga de crear el servicio y darlo a quien lo pida — esto se llama **inyección de dependencias**.

### Paso 1 — Auditar el estado actual

1. Abre `src/app/product-list/product-list.component.ts`
2. Haz una lista de todos los signals y variables de estado. Para cada uno, clasifícalo:

| Signal/Variable | Tipo | ¿Dónde debería vivir? |
|---|---|---|
| `products` | Servidor | En un servicio (compartible) |
| `filteredProducts` | Derivado | Como `computed()` |
| `state` (loading/error...) | Local de UI | En el componente |
| `category`, `sortBy`, `page` | URL | En query params (ya está) |
| `errorMessage` | Local de UI | En el componente |

3. Identifica los problemas:
   - `filteredProducts` es estado derivado — se puede calcular a partir de `products`, `category`, `sortBy` y `page`. No necesita su propio signal que se actualiza manualmente.
   - `products` son datos del servidor — si otro componente los necesita, tendría que hacer otra petición HTTP.

### Paso 2 — Crear un servicio con cache

1. Abre `src/app/services/products.service.ts`
2. Agrega cache de datos con un signal:

```typescript
// src/app/services/products.service.ts
import { Injectable, inject, signal, computed } from '@angular/core';
import { HttpClient } from '@angular/common/http';
import { Observable, tap } from 'rxjs';

export interface Product {
  id: number;
  title: string;
  price: number;
  description: string;
  category: string;
}

@Injectable({ providedIn: 'root' })
export class ProductsService {
  private http = inject(HttpClient);
  private apiUrl = 'https://fakestoreapi.com/products';

  // Cache: los datos se guardan en un signal
  private productsCache = signal<Product[]>([]);
  private loaded = signal(false);

  // Exponer como solo-lectura
  readonly products = this.productsCache.asReadonly();
  readonly isLoaded = this.loaded.asReadonly();

  // Estado derivado: categorías únicas
  readonly categories = computed(() => {
    const cats = this.productsCache().map(p => p.category);
    return ['all', ...new Set(cats)];
  });

  loadProducts(): Observable<Product[]> {
    // Si ya tenemos datos, devolver del cache
    if (this.loaded()) {
      return new Observable(subscriber => {
        subscriber.next(this.productsCache());
        subscriber.complete();
      });
    }

    return this.http.get<Product[]>(this.apiUrl).pipe(
      tap(data => {
        this.productsCache.set(data);
        this.loaded.set(true);
      })
    );
  }
}
```

> 💡 **Nota:** El signal `productsCache` vive en el servicio y persiste mientras la app esté abierta. Si el usuario navega a otra página y vuelve, los datos ya están en memoria — no hace otra petición HTTP.

### Paso 3 — Reemplazar estado derivado por computed

1. Abre `src/app/product-list/product-list.component.ts`
2. Reemplaza `filteredProducts` de signal manual a `computed()`:

```typescript
// src/app/product-list/product-list.component.ts
import { Component, inject, signal, computed, OnInit } from '@angular/core';
import { ActivatedRoute, Router } from '@angular/router';
import { ProductsService } from '../services/products.service';

type UIState = 'loading' | 'success' | 'error' | 'empty';

@Component({
  selector: 'app-product-list',
  standalone: true,
  templateUrl: './product-list.component.html',
  styleUrl: './product-list.component.css'
})
export class ProductListComponent implements OnInit {
  private productsService = inject(ProductsService);
  private route = inject(ActivatedRoute);
  private router = inject(Router);

  // Estado local de UI
  state = signal<UIState>('loading');
  errorMessage = signal('');

  // Estado de URL (leído de query params)
  category = signal('all');
  sortBy = signal('default');
  page = signal(1);
  pageSize = 6;

  // Estado derivado — se calcula automáticamente
  filteredProducts = computed(() => {
    let result = [...this.productsService.products()];

    if (this.category() !== 'all') {
      result = result.filter(p => p.category === this.category());
    }

    if (this.sortBy() === 'price-asc') {
      result.sort((a, b) => a.price - b.price);
    } else if (this.sortBy() === 'price-desc') {
      result.sort((a, b) => b.price - a.price);
    }

    const start = (this.page() - 1) * this.pageSize;
    return result.slice(start, start + this.pageSize);
  });

  totalFiltered = computed(() => {
    let result = this.productsService.products();
    if (this.category() !== 'all') {
      result = result.filter(p => p.category === this.category());
    }
    return result.length;
  });

  ngOnInit() {
    this.route.queryParams.subscribe(params => {
      this.category.set(params['category'] || 'all');
      this.sortBy.set(params['sort'] || 'default');
      this.page.set(Number(params['page']) || 1);

      if (!this.productsService.isLoaded()) {
        this.loadProducts();
      } else {
        this.state.set(
          this.filteredProducts().length === 0 ? 'empty' : 'success'
        );
      }
    });
  }

  loadProducts() {
    this.state.set('loading');
    this.productsService.loadProducts().subscribe({
      next: () => {
        this.state.set(
          this.filteredProducts().length === 0 ? 'empty' : 'success'
        );
      },
      error: () => {
        this.errorMessage.set('No pudimos cargar los productos.');
        this.state.set('error');
      }
    });
  }

  updateFilters(category: string, sort: string, page: number) {
    this.router.navigate([], {
      queryParams: { category, sort, page },
      queryParamsHandling: 'merge'
    });
  }
}
```

> 💡 **Nota:** `computed()` se recalcula automáticamente cada vez que cambia alguno de los signals que lee. No necesitas llamar `applyFilters()` manualmente — Angular lo hace por ti. Esto es **estado derivado**: el resultado se calcula, no se almacena.

### Paso 4 — Limpiar el componente

Verifica que tu componente ahora cumple estas reglas:

1. **No almacena datos del servidor** — los productos viven en `ProductsService`, no en el componente.
2. **No almacena estado derivado como signal** — `filteredProducts` y `totalFiltered` son `computed()`.
3. **Solo tiene estado local** — `state`, `errorMessage` son específicos de este componente.
4. **Los filtros vienen de la URL** — `category`, `sortBy`, `page` se leen de query params.

### Paso 5 — Verificar la separación

1. **Cache funciona:** Navega a otra ruta y vuelve. Los productos deben aparecer instantáneamente sin un nuevo skeleton.
2. **computed funciona:** Cambia un filtro. `filteredProducts` debe actualizarse automáticamente sin llamar ningún método.
3. **Servicio compartible:** Si creas otro componente que inyecte `ProductsService`, debe ver los mismos datos sin hacer otra petición HTTP.

Para verificar el cache, abre DevTools → Network → pestaña Fetch/XHR. Navega entre páginas y observa que la petición a fakestoreapi.com solo se hace una vez.

## Qué puede salir mal

- **"Los datos se pierden al navegar"** → Verifica que `ProductsService` tiene `providedIn: 'root'`. Si no tiene esto, Angular crea una instancia nueva cada vez y se pierde el cache.
- **"computed() no se actualiza cuando cambio el filtro"** → Verifica que `filteredProducts` lee signals (con `()`) y no variables normales. `computed()` solo detecta cambios en signals.
- **"Veo dos peticiones HTTP en Network"** → Verifica que `loadProducts()` del servicio revisa `this.loaded()` antes de hacer la petición. Si no, cada componente que lo llame hará su propia petición.

## Resultado esperado

Tu componente es más simple y tiene responsabilidades claras. Los datos del servidor viven en el servicio con cache. Los datos derivados se calculan con `computed()`. El componente solo gestiona su estado de UI.

**Criterios de aceptación:**
- [ ] Ningún dato del servidor almacenado como signal en el componente (viven en el servicio)
- [ ] `filteredProducts` y `totalFiltered` son `computed()`, no signals actualizados manualmente
- [ ] El cache funciona: navegar ida y vuelta no produce una nueva petición HTTP (verificar en DevTools → Network)
- [ ] El componente tiene menos de 80 líneas de TypeScript

**Pilares de diseño ejercitados:**
- **Mantenibilidad** — Cada tipo de estado tiene un lugar claro. Sabes exactamente dónde buscar cuando algo falla.
- **Rendimiento** — El cache evita peticiones HTTP innecesarias. `computed()` solo recalcula cuando cambian sus dependencias.

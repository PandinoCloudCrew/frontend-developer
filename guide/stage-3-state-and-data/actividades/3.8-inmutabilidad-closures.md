## Por qué esta actividad

Los bugs más difíciles de rastrear en aplicaciones frontend son los de **estado invisible**: el usuario hace click 10 veces pero el contador muestra 7. La animación se congela cada 3 frames. El filtro muestra datos de hace 2 segundos. Estos bugs vienen de dos conceptos que los principiantes suelen ignorar: **closures que capturan valores obsoletos** y **mutaciones de estado que los frameworks no detectan**. En Angular, los signals resuelven muchos de estos problemas, pero necesitas entender por qué para no caer en las trampas cuando uses librerías de terceros o patrones avanzados.

## Antes de empezar

Necesitas tener completadas las **Actividades 3.1 a 3.5** — dominas signals, servicios, y estado en Angular.

Una **closure** es una función que "recuerda" las variables del contexto donde fue creada. Cuando haces `setTimeout(() => console.log(counter), 1000)`, esa arrow function captura el valor de `counter` en ese instante. Si `counter` cambia después, la función sigue viendo el valor viejo — esto es un **stale closure**.

La **inmutabilidad** significa nunca modificar un objeto directamente, sino crear una copia nueva con los cambios. En lugar de `obj.name = 'nuevo'`, haces `{ ...obj, name: 'nuevo' }`. Angular (y la mayoría de frameworks) detecta cambios comparando **referencias** — si mutas el objeto original, la referencia no cambia y el framework no se entera del cambio.

### Paso 1 — Demostrar un bug de stale closure

1. Crea un componente de prueba:
   ::: code-group
   ```bash [Angular]
   ng generate component stale-demo --standalone
   ```
   ```bash [React]
   touch src/components/StaleDemo.tsx
   ```
   :::
2. Abre `src/app/stale-demo/stale-demo.component.ts`:

::: code-group
```typescript [Angular]
// src/app/stale-demo/stale-demo.component.ts
import { Component, signal } from '@angular/core';

@Component({
  selector: 'app-stale-demo',
  standalone: true,
  template: `
    <h2>Demo: Stale Closure</h2>
    <p>Contador: {{ counter() }}</p>
    <button (click)="incrementBuggy()">+1 (buggy)</button>
    <button (click)="incrementFixed()">+1 (fixed)</button>
    <button (click)="reset()">Reset</button>
    <p class="hint">Haz click rápido 10 veces en cada botón y compara.</p>
  `,
  styles: [`
    button { margin: 0.5rem; padding: 0.5rem 1rem; }
    .hint { color: #666; font-size: 0.875rem; }
  `]
})
export class StaleDemoComponent {
  counter = signal(0);

  incrementBuggy() {
    // BUG: captura el valor actual en la closure
    const current = this.counter();
    setTimeout(() => {
      this.counter.set(current + 1);
    }, 100);
  }

  incrementFixed() {
    // CORRECTO: usa update() que siempre lee el valor más reciente
    setTimeout(() => {
      this.counter.update(c => c + 1);
    }, 100);
  }

  reset() {
    this.counter.set(0);
  }
}
```
<<< @/snippets/react/act-3.8-01.tsx [React]
:::

3. Navega al componente y prueba:
   - Haz click rápido 10 veces en "+1 (buggy)". El contador probablemente mostrará un número menor que 10.
   - Haz click en Reset.
   - Haz click rápido 10 veces en "+1 (fixed)". El contador debe mostrar exactamente 10.

> 💡 **Nota:** En `incrementBuggy()`, cada click lee `this.counter()` y guarda ese valor en `current`. Si haces click 10 veces en 100ms, los 10 clicks leen el mismo valor (por ejemplo, 0) y todos hacen `set(0 + 1)` = 1. Con `update(c => c + 1)`, cada callback lee el valor más reciente del signal.

### Paso 2 — Corregir con signals

La corrección ya está en `incrementFixed()`. La regla es:

- **`signal.set(value)`** — Usa esto cuando el nuevo valor no depende del anterior. Ejemplo: `counter.set(0)` para resetear.
- **`signal.update(fn)`** — Usa esto cuando el nuevo valor depende del anterior. Ejemplo: `counter.update(c => c + 1)` para incrementar.

La misma regla aplica para actualizar arrays y objetos:

::: code-group
```typescript [Angular]
// MAL — stale closure posible
const current = this.items();
this.items.set([...current, newItem]);

// BIEN — siempre lee el valor más reciente
this.items.update(items => [...items, newItem]);
```
```typescript [React]
// MAL — stale closure posible
const current = items;
setItems([...current, newItem]);

// BIEN — siempre lee el valor más reciente
setItems(items => [...items, newItem]);
```
:::

### Paso 3 — Demostrar una mutación invisible

1. Agrega este método al componente:

::: code-group
```typescript [Angular]
  // En stale-demo.component.ts, agrega estos signals y métodos:
  user = signal({ name: 'Ana', age: 25 });

  mutateBuggy() {
    // BUG: muta el objeto directamente
    const u = this.user();
    u.age = u.age + 1;
    // El template NO se actualiza porque la referencia no cambió
    console.log('Mutado:', u.age, '| Signal:', this.user().age);
  }

  mutateFixed() {
    // CORRECTO: crea un objeto nuevo
    this.user.update(u => ({ ...u, age: u.age + 1 }));
  }
```
<<< @/snippets/react/act-3.8-02.tsx [React]
:::

2. Agrega al template:

```text
    <h2>Demo: Mutación Invisible</h2>
    <p>{{ user().name }}, {{ user().age }} años</p>
    <button (click)="mutateBuggy()">+1 edad (buggy)</button>
    <button (click)="mutateFixed()">+1 edad (fixed)</button>
```

3. Prueba:
   - Haz click en "+1 edad (buggy)" varias veces. La edad en pantalla no cambia, pero en la consola ves que el objeto sí se modificó.
   - Haz click en "+1 edad (fixed)". La edad se actualiza en pantalla.

> 💡 **Nota:** Angular compara la referencia del signal para detectar cambios. Si mutas el objeto interno, la referencia sigue siendo la misma y Angular no re-renderiza. Crear un objeto nuevo con `{ ...u, age: u.age + 1 }` produce una referencia nueva que Angular detecta.

### Paso 4 — Medir el costo de spread

1. Agrega al componente:

```typescript
  measureSpread() {
    // Crear un objeto grande
    const bigObject: Record<string, number> = {};
    for (let i = 0; i < 10000; i++) {
      bigObject[`key_${i}`] = i;
    }

    // Medir el spread
    const start = performance.now();
    for (let i = 0; i < 1000; i++) {
      const copy = { ...bigObject, key_0: i };
    }
    const elapsed = performance.now() - start;

    console.log(`1000 spreads de objeto con 10,000 keys: ${elapsed.toFixed(1)}ms`);
    alert(`1000 spreads: ${elapsed.toFixed(1)}ms\n\nA 60fps necesitas <16.6ms por frame.\nSi haces spread en cada frame, ${elapsed.toFixed(1) > 16.6 ? 'TENDRÁS jank' : 'es aceptable'}.`);
  }
```

2. Agrega el botón al template:

```text
    <h2>Demo: Costo de Spread</h2>
    <button (click)="measureSpread()">Medir 1000 spreads de objeto grande</button>
```

3. Ejecuta y observa. En la mayoría de máquinas, 1000 spreads de un objeto con 10,000 keys toman más de 16.6ms, lo que significa que **no puedes hacer spread en cada frame de animación** sin causar jank (saltos visuales).

### Paso 5 — Alternativa para animaciones

Para valores que cambian 60 veces por segundo (animaciones, posición del mouse), los signals son demasiado costosos porque cada `set()` dispara detección de cambios. En estos casos, manipula el DOM directamente:

```typescript
  // Para animaciones de alta frecuencia:
  animationDemo() {
    const element = document.getElementById('animated-box');
    if (!element) return;

    let position = 0;

    const animate = () => {
      position += 2;
      element.style.transform = `translateX(${position}px)`;

      if (position < 300) {
        requestAnimationFrame(animate);
      }
    };

    requestAnimationFrame(animate);
  }
```

Agrega al template:

```text
    <h2>Demo: Animación sin Signals</h2>
    <div id="animated-box" style="width:50px;height:50px;background:#1976d2;border-radius:4px;"></div>
    <button (click)="animationDemo()">Animar</button>
    <p class="hint">La animación manipula el DOM directamente, sin pasar por signals ni detección de cambios.</p>
```

La regla es: **signals para estado de la aplicación, manipulación directa del DOM para animaciones de alta frecuencia**.

## Qué puede salir mal

- **"El botón buggy funciona bien"** → Estás haciendo click demasiado lento. Los 100ms del `setTimeout` terminan antes de tu siguiente click. Intenta hacer click 10 veces en menos de 100ms, o reduce el delay a 10ms para hacer la demo más obvia.
- **"No veo diferencia entre spread y mutación directa"** → Verifica que estás mirando el template, no la consola. La mutación directa cambia el objeto interno pero el template no se re-renderiza porque la referencia del signal no cambió.
- **"El test de spread me da 2ms"** → Tu máquina es rápida o el objeto no es lo suficientemente grande. Aumenta las keys a 100,000 o los spreads a 10,000.

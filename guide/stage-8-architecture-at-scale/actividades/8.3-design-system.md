**Duración:** ~60 min

## Por qué esta actividad

Si revisas tu proyecto, probablemente tienes el mismo botón implementado de 3 formas diferentes en 3 componentes. Mismo color pero con `#3b82f6` en uno, `rgb(59, 130, 246)` en otro, y `blue` en otro. Mismo espaciado pero con `16px`, `1rem` y `1em` mezclados. Cuando cambias el color principal de la marca, necesitas buscarlo en 47 archivos.

Un **design system** centraliza los componentes reutilizables y los "design tokens" (colores, tipografía, espaciado) en un solo paquete. Cambias el token de color una vez y se propaga a todos los componentes. Los diseñadores y los desarrolladores hablan el mismo lenguaje. Los nuevos desarrolladores no reinventan el botón.

> **Pilar de diseño:** Esta actividad ejercita **Mantenibilidad** — un design system elimina la duplicación de componentes UI y garantiza consistencia visual en toda la aplicación.

## Antes de empezar

Necesitas haber completado la **Actividad 8.1** — tu proyecto está organizado por features.

**¿Qué es un design system?** Es una colección de componentes reutilizables (botones, inputs, cards, modals) y reglas de diseño (colores, tipografía, espaciado) que aseguran que toda tu aplicación se ve y se comporta de forma consistente. Piensa en LEGO: en lugar de construir cada pieza desde cero, tienes un catálogo de piezas estándar que encajan entre sí.

**¿Qué son design tokens?** Son variables que almacenan los valores de diseño. En lugar de escribir `#3b82f6` directamente en tu CSS, creas un token `--color-primary: #3b82f6` y lo usas en todas partes. Si un día cambias el color de la marca, lo cambias en un solo lugar.

**¿Qué es Nx?** Es una herramienta para gestionar proyectos grandes. Permite tener múltiples aplicaciones y librerías en un mismo repositorio (monorepo), con compilación inteligente que solo re-compila lo que cambió. Para este ejercicio, lo usamos para crear una librería de design system separada de tu aplicación.

### Paso 1 — Identificar componentes duplicados

1. Busca componentes que se repiten en tu proyecto:
   ```bash
   grep -r "class=\"btn\|class=\"button" src/ --include="*.html" --include="*.ts" -l
   ```

2. Haz una lista de los 5 componentes más reutilizados:
   - `Button` — diferentes variantes (primary, secondary, danger)
   - `Input` — con label y validación
   - `Card` — contenedor con sombra y padding
   - `Badge` — etiquetas de estado (active, pending, error)
   - `Alert` — mensajes de feedback (success, warning, error)

### Paso 2 — Definir design tokens

1. Crea un archivo de tokens CSS. Crea `src/styles/tokens.css`:
   ```css
   :root {
     /* Colores */
     --color-primary: #3b82f6;
     --color-primary-hover: #2563eb;
     --color-secondary: #6b7280;
     --color-success: #22c55e;
     --color-warning: #f59e0b;
     --color-danger: #ef4444;
     --color-text: #1f2937;
     --color-text-muted: #6b7280;
     --color-background: #ffffff;
     --color-surface: #f9fafb;
     --color-border: #e5e7eb;

     /* Espaciado (basado en 4px) */
     --space-1: 0.25rem;  /* 4px */
     --space-2: 0.5rem;   /* 8px */
     --space-3: 0.75rem;  /* 12px */
     --space-4: 1rem;     /* 16px */
     --space-6: 1.5rem;   /* 24px */
     --space-8: 2rem;     /* 32px */

     /* Tipografía */
     --font-family: system-ui, -apple-system, sans-serif;
     --font-size-sm: 0.875rem;   /* 14px */
     --font-size-base: 1rem;     /* 16px */
     --font-size-lg: 1.125rem;   /* 18px */
     --font-size-xl: 1.25rem;    /* 20px */
     --font-size-2xl: 1.5rem;    /* 24px */

     /* Bordes */
     --radius-sm: 0.25rem;
     --radius-md: 0.375rem;
     --radius-lg: 0.5rem;

     /* Sombras */
     --shadow-sm: 0 1px 2px rgba(0, 0, 0, 0.05);
     --shadow-md: 0 4px 6px rgba(0, 0, 0, 0.07);
   }
   ```

2. Importa los tokens en tu `styles.css` global:
   ```css
   @import './styles/tokens.css';
   ```

### Paso 3 — Crear la librería de design system

**Opción A — Con Nx (recomendado para proyectos grandes):**
1. Si no tienes Nx, instálalo:
   ```bash
   npx nx init
   ```

2. Genera la librería:
   ```bash
   npx nx generate @nx/angular:library design-system --directory=libs/design-system --standalone --style=css
   ```

**Opción B — Sin Nx (más simple, suficiente para empezar):**
1. Crea la estructura manualmente:
   ```bash
   mkdir -p src/app/design-system/components
   mkdir -p src/app/design-system/tokens
   ```

2. Crea `src/app/design-system/index.ts` como punto de entrada:
   ```typescript
   // Componentes
   export { DsButtonComponent } from './components/ds-button/ds-button.component';
   export { DsInputComponent } from './components/ds-input/ds-input.component';
   export { DsCardComponent } from './components/ds-card/ds-card.component';
   export { DsBadgeComponent } from './components/ds-badge/ds-badge.component';
   export { DsAlertComponent } from './components/ds-alert/ds-alert.component';
   ```

> 💡 **Nota:** El prefijo `Ds` (Design System) distingue los componentes del design system de los componentes de la aplicación. Así sabes de un vistazo si un componente es genérico o específico de un feature.

### Paso 4 — Extraer componentes reutilizables

Crea cada componente usando design tokens. Ejemplo con Button:

1. Genera el componente:
   ```bash
   ng generate component design-system/components/ds-button --standalone
   ```

2. Implementa el componente Button del design system:

::: code-group

```typescript [Angular]
// src/app/design-system/components/ds-button/ds-button.component.ts
import { Component, input } from '@angular/core';

@Component({
  selector: 'ds-button',
  standalone: true,
  template: `
    <button
      [type]="type()"
      [class]="'ds-button ds-button--' + variant()"
      [disabled]="disabled()"
    >
      <ng-content />
    </button>
  `,
  styles: [`
    .ds-button {
      font-family: var(--font-family);
      font-size: var(--font-size-base);
      padding: var(--space-2) var(--space-4);
      border-radius: var(--radius-md);
      border: 1px solid transparent;
      cursor: pointer;
      transition: background-color 0.15s;
    }
    .ds-button--primary {
      background-color: var(--color-primary);
      color: white;
    }
    .ds-button--primary:hover {
      background-color: var(--color-primary-hover);
    }
    .ds-button--secondary {
      background-color: transparent;
      color: var(--color-text);
      border-color: var(--color-border);
    }
    .ds-button--danger {
      background-color: var(--color-danger);
      color: white;
    }

      opacity: 0.5;
      cursor: not-allowed;
    }
```

3. Repite para los otros 4 componentes (Input, Card, Badge, Alert), usando design tokens para todos los valores de color, espaciado y tipografía.

### Paso 5 — Consumir el design system desde la app

1. En tus componentes de features, importa desde el design system:
   ```typescript
   import { DsButtonComponent, DsCardComponent } from '../../design-system';

   @Component({
     selector: 'app-product-card',
     standalone: true,
     imports: [DsButtonComponent, DsCardComponent],
     template: `
       <ds-card>
         <h3>{{ product().name }}</h3>
         <p>{{ product().price | currency }}</p>
         <ds-button variant="primary" (click)="addToCart()">
           Agregar al carrito
         </ds-button>
       </ds-card>
     `,
   })
   export class ProductCardComponent { /* ... */ }
   ```

2. Elimina los estilos de botón hardcodeados que tenías antes en cada componente.

### Paso 6 — Verificar que un cambio de token se propaga

1. Abre `src/styles/tokens.css`
2. Cambia el color primary:
   ```css
   --color-primary: #8b5cf6;  /* de azul a violeta */
   ```
3. Recarga la aplicación (`ng serve` si ya está corriendo)
4. Verifica que **todos** los botones primary cambiaron de color — sin tocar un solo componente

5. Revierte el cambio al color original.

## Qué puede salir mal

- **"Los estilos del design system no se aplican"** → Verifica que `tokens.css` está importado en tu `styles.css` global. Los CSS custom properties (variables) deben estar definidas en `:root` para que sean accesibles globalmente.
- **"¿Cómo manejo dark mode?"** → Define otro set de tokens dentro de `@media (prefers-color-scheme: dark)` o dentro de una clase `[data-theme="dark"]`. Los componentes no cambian — solo cambian los valores de los tokens.
- **"El componente del design system necesita lógica específica de mi app"** → Eso es una señal de que no es un componente de design system. Los componentes del design system son genéricos — no conocen tu dominio de negocio. Si necesitas un `ProductButton`, es un componente de tu feature que usa `DsButton` internamente.
- **"Nx es muy complicado"** → Empieza con la Opción B (carpeta simple). Nx agrega valor cuando tienes múltiples aplicaciones que comparten el design system. Para una sola app, la carpeta es suficiente.

## Resultado esperado

Tu proyecto tiene un design system con 5 componentes reutilizables que usan design tokens para colores, tipografía y espaciado. Cambiar un token en un solo archivo actualiza la apariencia de todos los componentes que lo usan.

**Criterios de aceptación:**
- [ ] El design system tiene al menos 5 componentes reutilizables exportados desde un `index.ts`
- [ ] Todos los colores, espaciados y tipografías usan design tokens (CSS custom properties), no valores hardcodeados
- [ ] Cambiar un token de color en `tokens.css` se propaga a todos los componentes sin modificar código
- [ ] Los componentes del design system compilan independientemente (no dependen de lógica de negocio)

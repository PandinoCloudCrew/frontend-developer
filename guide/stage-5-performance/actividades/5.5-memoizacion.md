## Por que esta actividad

"Si algo es lento, memoizalo" es un consejo que suena lógico pero que genera mas problemas de los que resuelve. La **memoizacion** guarda el resultado de un calculo para no repetirlo — pero si memoizas algo que no es costoso, solo estas usando memoria extra sin beneficio. Peor aun: si no entiendes como funciona la comparacion por referencia, tu memoizacion puede romperse silenciosamente sin que lo sepas. Esta actividad te ensena a medir primero, memoizar despues, y verificar que la memoizacion realmente funciona.

## Antes de empezar

Necesitas tener completada la **Actividad 5.3** y entender signals (`signal()`, `computed()`) en Angular.

**Memoizacion** es una técnica que guarda el resultado de una función para no volver a calcularla si los mismos argumentos se repiten. Es como un cache: la primera vez calcula, las siguientes devuelve el resultado guardado.

En Angular, `computed()` es la forma principal de memoizacion: solo recalcula cuando los signals de los que depende cambian.

**Change detection** es el proceso por el cual Angular compara el estado anterior con el actual para saber que actualizar en pantalla. Con la estrategia **OnPush**, Angular solo revisa un componente cuando sus inputs cambian por referencia (no por valor).

**Comparacion por referencia** significa que Angular compara si dos objetos son literalmente el mismo objeto en memoria (usando `===`), no si tienen el mismo contenido. `{ a: 1 } === { a: 1 }` es `false` porque son dos objetos diferentes en memoria, aunque tengan el mismo contenido.

### Paso 1 — Crear un componente con calculo costoso

1. Crea un componente que simule un calculo pesado:
   ```bash
   ng generate component lista-productos
   ```
2. En `src/app/lista-productos/lista-productos.component.ts`:
   ```typescript
   import { Component, signal, computed } from '@angular/core';

   interface Producto {
     id: number;
     nombre: string;
     precio: number;
     categoria: string;
   }

   @Component({
     selector: 'app-lista-productos',
     standalone: true,
     template: `
       <div>
         <input
           type="text"
           placeholder="Buscar..."
           (input)="onBuscar($event)" />
         <p>Total filtrado: {{ totalFiltrado() }}</p>
         <ul>
           @for (producto of productosFiltrados(); track producto.id) {
             <li>{{ producto.nombre }} - \${{ producto.precio }}</li>
           }
         </ul>
         <button (click)="incrementarContador()">
           Clicks: {{ contador() }}
         </button>
       </div>
     `,
   })
   export class ListaProductosComponent {
     productos = signal<Producto[]>(this.generarProductos(5000));
     busqueda = signal('');
     contador = signal(0);

     // SIN memoizacion: se recalcula en cada change detection
     productosFiltrados(): Producto[] {
       console.log('Recalculando productosFiltrados...');
       const termino = this.busqueda().toLowerCase();
       return this.productos().filter(p =>
         p.nombre.toLowerCase().includes(termino)
       );
     }

     totalFiltrado(): number {
       return this.productosFiltrados().length;
     }

     onBuscar(event: Event) {
       const input = event.target as HTMLInputElement;
       this.busqueda.set(input.value);
     }

     incrementarContador() {
       this.contador.update(c => c + 1);
     }

     private generarProductos(cantidad: number): Producto[] {
       return Array.from({ length: cantidad }, (_, i) => ({
         id: i,
         nombre: `Producto ${i}`,
         precio: Math.round(Math.random() * 100),
         categoria: ['Electronica', 'Ropa', 'Hogar'][i % 3],
       }));
     }
   }
   ```
3. Ejecuta `ng serve` y abre la página

### Paso 2 — Medir el rendimiento sin memoizacion

1. Abre Chrome DevTools → Console
2. Haz click en el botón "Clicks" varias veces
3. Observa la consola: **cada click imprime "Recalculando productosFiltrados..."** aunque el click no tiene nada que ver con los productos — solo incrementa un contador
4. Esto demuestra el problema: `productosFiltrados()` se llama como método en el template, y Angular lo re-ejecuta en cada ciclo de change detection, sin importar que cambio
5. Anota cuantas veces se ejecuta `productosFiltrados` por cada click en el botón

### Paso 3 — Aplicar memoizacion con computed()

1. Modifica el componente para usar `computed()`:
   ```typescript
   // ANTES (metodo — se recalcula siempre):
   productosFiltrados(): Producto[] {
     console.log('Recalculando productosFiltrados...');
     // ...
   }

   // DESPUES (computed — se recalcula solo cuando busqueda o productos cambian):
   productosFiltrados = computed(() => {
     console.log('Recalculando productosFiltrados...');
     const termino = this.busqueda().toLowerCase();
     return this.productos().filter(p =>
       p.nombre.toLowerCase().includes(termino)
     );
   });

   totalFiltrado = computed(() => this.productosFiltrados().length);
   ```
2. Ejecuta de nuevo y haz click en el botón "Clicks"
3. Observa la consola: **ya no imprime "Recalculando"** al hacer click en el botón — `computed()` sabe que `busqueda` y `productos` no cambiaron, así que devuelve el resultado guardado
4. Escribe algo en el input de busqueda — ahora SI recalcula, porque `busqueda` cambio

### Paso 4 — Activar OnPush

1. Agrega `changeDetection: ChangeDetectionStrategy.OnPush` al componente:
   ```typescript
   import { Component, signal, computed, ChangeDetectionStrategy } from '@angular/core';

   @Component({
     selector: 'app-lista-productos',
     standalone: true,
     changeDetection: ChangeDetectionStrategy.OnPush,
     template: `...`,
   })
   ```
2. Con `OnPush`, Angular solo ejecuta change detection en este componente cuando:
   - Un input del componente cambia (por referencia)
   - Un evento del template se dispara (click, input, etc.)
   - Un signal que usa el template cambia
3. Esto reduce drasticamente el trabajo que Angular hace en cada ciclo

### Paso 5 — Demostrar como un inline object rompe la memoizacion

1. Crea un componente hijo que reciba un objeto como input:
   ```bash
   ng generate component detalle-producto
   ```
2. En `src/app/detalle-producto/detalle-producto.component.ts`:
   ```typescript
   import { Component, input, ChangeDetectionStrategy } from '@angular/core';

   @Component({
     selector: 'app-detalle-producto',
     standalone: true,
     changeDetection: ChangeDetectionStrategy.OnPush,
     template: `
       <div>{{ config().color }} - {{ config().tamano }}</div>
     `,
   })
   export class DetalleProductoComponent {
     config = input.required<{ color: string; tamano: string }>();

     constructor() {
       // Este log muestra cada vez que Angular ejecuta change detection en este componente
       console.log('DetalleProducto: change detection ejecutado');
     }
   }
   ```
3. En el componente padre, pasa un **objeto inline** al hijo:
   ```typescript
   // En el template del padre:
   // MAL: crea un objeto nuevo en cada render
   template: `
     <app-detalle-producto [config]="{ color: 'rojo', tamano: 'grande' }" />
     <button (click)="incrementarContador()">Clicks: {{ contador() }}</button>
   `
   ```
4. Haz click en el botón — observa que `DetalleProducto` ejecuta change detection cada vez, aunque el config no cambio. Esto pasa porque `{ color: 'rojo', tamano: 'grande' }` crea un **nuevo objeto** en cada render, y Angular compara por referencia
5. **La solución:** guarda el objeto en un signal:
   ```typescript
   // BIEN: mismo objeto en memoria
   readonly config = signal({ color: 'rojo', tamano: 'grande' });
   // En el template: [config]="config()"
   ```

## Que puede salir mal

- **"No veo ningun console.log de 'Recalculando'"** → Puede que la consola este filtrada. En DevTools → Console, asegurate de que el filtro dice "All levels" y no tiene texto en el campo de busqueda.
- **"Despues de cambiar a computed(), el template no se actualiza"** → Si usabas `productosFiltrados()` con parentesis en el template y ahora es un `computed`, recuerda que se accede igual con parentesis: `productosFiltrados()`. El `computed` es un signal y se lee con `()`.
- **"No entiendo la diferencia entre método y computed en el template"** → Un método se re-ejecuta en cada change detection (puede ser decenas de veces por segundo). Un `computed` se re-ejecuta solo cuando sus dependencias (signals) cambian.

## Resultado esperado

Al terminar, entiendes la diferencia entre un método en el template (se recalcula siempre) y un `computed()` (se recalcula solo cuando es necesario). Has demostrado con `console.log` que la memoizacion funciona. Sabes que un objeto inline rompe la memoizacion porque crea una nueva referencia cada vez.

**Criterios de aceptacion:**
- [ ] Cada memoizacion (`computed()`) tiene una justificacion medida (documentada con console.log o profiling)
- [ ] Se demuestra como un inline object rompe la optimización de OnPush
- [ ] "Podria ser lento" NO es justificacion aceptable — se midio antes de memoizar

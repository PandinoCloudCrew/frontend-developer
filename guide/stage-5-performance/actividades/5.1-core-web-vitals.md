## Por que esta actividad

Cuando una página tarda mas de 3 segundos en cargar, el 53% de los usuarios la abandona. Google mide la velocidad de tu página con tres metricas llamadas **Core Web Vitals** y las usa para decidir tu posición en los resultados de busqueda. Si tu página es lenta, menos personas la encuentran y menos personas la usan. Entender estas metricas es el primer paso para construir aplicaciones rapidas.

## Antes de empezar

Necesitas tener completada la **Etapa 4** y una aplicación web funcional que puedas servir localmente (con `ng serve`, `npm run dev`, o Live Server).

Necesitas Chrome instalado — Lighthouse viene integrado en Chrome DevTools.

Algunos conceptos clave:

- **Core Web Vitals** son 3 metricas que Google usa para medir la experiencia del usuario:
  - **LCP (Largest Contentful Paint):** cuanto tarda en aparecer el elemento mas grande visible (una imagen hero, un titulo grande). Bueno: < 2.5 segundos.
  - **CLS (Cumulative Layout Shift):** cuanto se mueve el contenido mientras carga (botones que saltan, texto que se desplaza). Bueno: 0 (nada se mueve).
  - **INP (Interaction to Next Paint):** cuanto tarda la página en responder despues de que el usuario hace click o teclea. Bueno: < 200 milisegundos.
- **Lighthouse** es una herramienta integrada en Chrome que analiza tu página y te da un puntaje de 0 a 100 con sugerencias especificas de mejora.

### Paso 1 — Servir la aplicación

1. Abre la terminal en VS Code y navega a la carpeta de tu proyecto
2. Inicia el servidor de desarrollo:
   - Si usas Angular: `ng serve`
   - Si usas otro framework: `npm run dev`
   - Si es HTML estatico: usa Live Server (click derecho en el archivo HTML > "Open with Live Server")
3. Abre Chrome y ve a `http://localhost:4200` (Angular) o la URL que te indique la terminal

### Paso 2 — Ejecutar Lighthouse

1. En Chrome, abre DevTools con `F12` o `Cmd+Option+I` (Mac) / `Ctrl+Shift+I` (Windows)
2. Ve a la pestana **Lighthouse** (si no la ves, haz click en `>>` para ver mas pestanas)
3. Configura el analisis:
   - **Mode:** Navigation
   - **Device:** Mobile (es mas exigente — si pasa en móvil, pasa en desktop)
   - **Categories:** marca solo **Performance**
4. Haz click en **Analyze page load**
5. Espera 15-30 segundos — Lighthouse carga tu página varias veces para medir

### Paso 3 — Interpretar el reporte

1. Anota tu puntaje de Performance (el número grande de 0 a 100)
2. Busca la sección **Diagnostics** — aquí Lighthouse lista los problemas especificos
3. Documenta los 3 problemas principales en un archivo `rendimiento-auditoria.md` en la raiz de tu proyecto:

```text
# Auditoria de Rendimiento

## Puntaje inicial: XX/100

## Problemas encontrados (priorizados por impacto)

1. **[Nombre del problema]** — Impacto: alto/medio/bajo
   - Que dice Lighthouse: ...
   - Donde esta el problema: ...
   - Plan de correccion: ...

2. ...

3. ...
```

4. Fijate en las metricas individuales:
   - **LCP:** el tiempo que tarda en aparecer el elemento mas grande. Si es > 2.5s, hay que optimizar
   - **CLS:** si es > 0, algo se esta moviendo mientras carga
   - **INP:** si es > 200ms, alguna interacción es lenta

### Paso 4 — Corregir LCP

El LCP lento generalmente se debe a imagenes grandes o recursos que bloquean el renderizado.

1. En el reporte de Lighthouse, busca **"Largest Contentful Paint element"** — te dice cual es el elemento
2. Si es una **imagen**:
   - Verifica que tenga dimensiones explicitas (`width` y `height` en el HTML)
   - Agrega `fetchpriority="high"` a la imagen hero (la primera imagen grande visible):
   ```text
   <!-- HTML: en tu imagen principal -->
   <img src="hero.webp" alt="Descripcion" width="800" height="400" fetchpriority="high">
   ```
   - Convierte la imagen a formato WebP si es JPEG o PNG (reduce el tamaño ~30%)
3. Si es **texto** que tarda en aparecer:
   - Busca si tienes fuentes personalizadas que bloquean el render
   - Agrega `font-display: swap` en tu `@font-face` o link de Google Fonts

### Paso 5 — Corregir CLS

CLS ocurre cuando elementos cambian de posición despues de que la página ya empezo a mostrarse.

1. En DevTools, ve a la pestana **Performance**
2. Haz click en el botón de grabar (circulo), recarga la página, y detiene la grabacion
3. Busca los indicadores rojos de "Layout Shift" en la linea de tiempo
4. Las causas mas comunes y sus soluciones:
   - **Imagenes sin dimensiones:** agrega `width` y `height` a todas las `<img>`
   ```text
   <!-- HTML: siempre especifica dimensiones -->
   <img src="foto.webp" alt="Descripcion" width="300" height="200">
   ```
   - **Fuentes que cambian de tamaño:** usa `font-display: swap` y `size-adjust`
   - **Contenido dinámico que empuja otros elementos:** reserva espacio con CSS (`min-height`)

### Paso 6 — Verificar las mejoras

1. Ejecuta Lighthouse de nuevo (Paso 2) con la misma configuración
2. Compara los resultados:
   - El puntaje debe ser >= 90
   - LCP debe ser < 2.5 segundos
   - CLS debe ser 0
3. Actualiza tu archivo `rendimiento-auditoria.md` con los resultados finales:

```text
## Puntaje final: XX/100

## Correcciones aplicadas
1. [Que hiciste] — Resultado: [metrica antes] -> [metrica despues]
2. ...
3. ...
```

## Que puede salir mal

- **"Mi puntaje sube y baja cada vez que ejecuto Lighthouse"** → Es normal que varie 5-10 puntos. Lighthouse simula condiciones de red y CPU, y cada ejecución es ligeramente diferente. Ejecuta 3 veces y usa el promedio.
- **"No encuentro la pestana Lighthouse en DevTools"** → Asegurate de usar Chrome (no Firefox ni Safari). Haz click en `>>` a la derecha de las pestanas para ver las ocultas. Si aun no aparece, actualiza Chrome.
- **"Mi LCP es una imagen pero ya tiene width y height"** → Verifica el tamaño del archivo. Una imagen de 5 MB va a ser lenta sin importar las dimensiones HTML. Comprimela con [squoosh.app](https://squoosh.app/) y convierte a WebP.
- **"Mi puntaje es 100 en desktop pero 60 en móvil"** → Lighthouse en móvil simula una CPU 4x mas lenta y red 4G. Es intencional — optimiza para móvil primero.

## Resultado esperado

Al terminar, tu aplicación tiene un puntaje de Lighthouse Performance >= 90 en modo móvil. Tienes un archivo `rendimiento-auditoria.md` documentando los problemas encontrados, las correcciones aplicadas, y la mejora medida.

**Criterios de aceptacion:**
- [ ] Lighthouse Performance >= 90 en modo móvil
- [ ] LCP < 2.5s en Slow 4G
- [ ] CLS = 0 (sin layout shifts)

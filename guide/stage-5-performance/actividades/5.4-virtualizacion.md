# 🟡 Actividad 5.4 — Construir una lista virtualizada de 10,000 elementos

**Duracion:** ~55 min

## Por que esta actividad

Imagina una tabla con 10,000 filas. Si el navegador crea 10,000 elementos en el DOM, la página se congela — el usuario no puede hacer scroll sin que todo se sienta lento (lo que se llama **jank**). La solución no es paginar (eso tiene sus propios problemas de UX); es **virtualizar**: solo renderizar los ~20 elementos visibles en pantalla y reciclarlos mientras el usuario hace scroll. Es como una ventana que se desliza sobre los datos.

## Antes de empezar

Necesitas tener completada la **Actividad 5.3** y entender como crear componentes en Angular.

**Virtualizacion** es una técnica que solo renderiza los elementos visibles en pantalla. Si tu lista tiene 10,000 items pero la pantalla muestra 20 a la vez, solo 20 elementos existen en el DOM. Cuando el usuario hace scroll, los elementos que salen de la pantalla se reciclan para mostrar los nuevos datos.

**DOM (Document Object Model)** es la representacion de tu HTML en memoria. Cada elemento (`<div>`, `<li>`, `<tr>`) es un nodo del DOM. Mas nodos = mas memoria y mas trabajo para el navegador.

**fps (frames per second)** mide que tan fluido se siente el scroll. 60 fps = fluido. Por debajo de 30 fps el usuario nota el "tartamudeo" (jank).

### Paso 1 — Crear la lista sin virtualizar

1. Crea un componente para la lista:
   ```bash
   ng generate component lista-grande
   ```
2. En `src/app/lista-grande/lista-grande.component.ts`, genera 10,000 items:
   ```typescript
   import { Component } from '@angular/core';

   @Component({
     selector: 'app-lista-grande',
     standalone: true,
     template: `
       <div class="container">
         @for (item of items; track item.id) {
           <div class="item">
             {{ item.id }} - {{ item.nombre }} - {{ item.email }}
           </div>
         }
       </div>
     `,
     styles: [`
       .container { height: 500px; overflow-y: auto; }
       .item { padding: 0.5rem 1rem; border-bottom: 1px solid #eee; height: 48px; }
     `],
   })
   export class ListaGrandeComponent {
     items = Array.from({ length: 10_000 }, (_, i) => ({
       id: i + 1,
       nombre: `Usuario ${i + 1}`,
       email: `usuario${i + 1}@example.com`,
     }));
   }
   ```
3. Agrega el componente a una ruta o directamente en `app.component.html` para probarlo
4. Ejecuta `ng serve` y abre la página en Chrome

### Paso 2 — Medir el rendimiento sin virtualizacion

1. En Chrome DevTools, ve a la pestana **Performance**
2. Haz click en el icono de engranaje (⚙) y activa **Screenshots**
3. Haz click en el botón de grabar (circulo rojo)
4. Haz scroll rápido arriba y abajo en la lista durante 5 segundos
5. Detiene la grabacion
6. Observa:
   - La linea de **FPS** en la parte superior — busca caidas (zonas rojas = jank)
   - El indicador de **frames** — los frames por encima de 16ms son problematicos
7. Anota el fps promedio durante el scroll

### Paso 3 — Instalar Angular CDK

1. En la terminal, instala Angular CDK (si no lo tienes):
   ```bash
   ng add @angular/cdk
   ```
   Si ya lo tienes instalado, este comando te lo dira

### Paso 4 — Implementar scroll virtualizado

1. Actualiza `src/app/lista-grande/lista-grande.component.ts`:
   ```typescript
   import { Component } from '@angular/core';
   import { ScrollingModule } from '@angular/cdk/scrolling';

   @Component({
     selector: 'app-lista-grande',
     standalone: true,
     imports: [ScrollingModule],
     template: `
       <cdk-virtual-scroll-viewport itemSize="48" class="viewport">
         <div *cdkVirtualFor="let item of items" class="item">
           {{ item.id }} - {{ item.nombre }} - {{ item.email }}
         </div>
       </cdk-virtual-scroll-viewport>
     `,
     styles: [`
       .viewport { height: 500px; }
       .item { padding: 0.5rem 1rem; border-bottom: 1px solid #eee; height: 48px; }
     `],
   })
   export class ListaGrandeComponent {
     items = Array.from({ length: 10_000 }, (_, i) => ({
       id: i + 1,
       nombre: `Usuario ${i + 1}`,
       email: `usuario${i + 1}@example.com`,
     }));
   }
   ```

2. Puntos clave del cambio:
   - `<cdk-virtual-scroll-viewport>` reemplaza al contenedor con scroll
   - `itemSize="48"` le dice al viewport la altura de cada item en pixeles — debe coincidir con la altura real del item en CSS
   - `*cdkVirtualFor` reemplaza a `@for` — funciona igual pero solo renderiza los elementos visibles

> 💡 **Nota:** `itemSize` debe coincidir con la altura CSS de cada item. Si dice `48` pero el item mide `60px`, el scroll se vera desalineado.

### Paso 5 — Medir el rendimiento con virtualizacion

1. Repite exactamente el Paso 2: graba performance mientras haces scroll rápido
2. Compara los resultados:
   - FPS deberia mantenerse en ~60 (linea verde constante)
   - No deberia haber frames rojos
   - El scroll deberia sentirse fluido

### Paso 6 — Comparar elementos en el DOM

1. Con la versión virtualizada corriendo, abre DevTools → Elements
2. Busca los `<div class="item">` dentro del viewport
3. Cuenta cuantos hay — deberian ser ~15-25 (los visibles + un buffer), **no** 10,000
4. Haz scroll y observa como los elementos se reciclan: los mismos `<div>` cambian su contenido

## Que puede salir mal

- **"El viewport aparece con altura 0 y no se ve nada"** → `<cdk-virtual-scroll-viewport>` necesita una altura explicita. Asegurate de tener `.viewport { height: 500px; }` (o cualquier valor fijo/relativo) en los estilos del componente.
- **"Los items se ven desalineados o hay espacios blancos al hacer scroll"** → El valor de `itemSize` no coincide con la altura real del item. Inspecciona un item en DevTools → Computed y verifica su altura total (incluyendo padding y border).
- **"Error: 'cdk-virtual-scroll-viewport' is not a known element"** → Falta importar `ScrollingModule` en el array `imports` del componente.

## Resultado esperado

Al terminar, tu lista de 10,000 elementos hace scroll fluido a ~60 fps. En DevTools → Elements solo hay ~20 elementos en el DOM, no 10,000. La diferencia de rendimiento con la versión sin virtualizar es evidente.

**Criterios de aceptacion:**
- [ ] Scroll a 60 fps con 10,000 elementos (verificado en DevTools Performance)
- [ ] Solo los elementos visibles se renderizan en el DOM (verificado en DevTools Elements)
- [ ] `itemSize` coincide con la altura CSS real de cada item

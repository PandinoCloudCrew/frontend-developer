## Por que esta actividad

Lighthouse te da un puntaje de rendimiento, pero lo mide en un entorno controlado: una computadora potente, una red simulada, sin extensiones del navegador. El rendimiento **real** de tus usuarios puede ser muy diferente: dispositivos viejos, redes inestables, extensiones que inyectan scripts. **RUM (Real User Monitoring)** captura lo que tus usuarios realmente experimentan. Un sitio con Lighthouse 95 puede tener un LCP de 5 segundos en un telefono Android de gama baja. Si solo mides con Lighthouse, estas ciego a la mitad del problema.

## Antes de empezar

Necesitas tener completadas las **Actividades 5.1-5.3** y entender que son LCP, CLS e INP.

**Metricas sinteticas** son las que Lighthouse mide en un entorno controlado. Son utiles para detectar problemas obvios, pero no reflejan la experiencia real del usuario.

**RUM (Real User Monitoring)** captura metricas directamente del navegador del usuario real. La libreria `web-vitals` de Google hace exactamente esto: mide LCP, CLS e INP en el navegador del usuario y te da los valores reales.

**Scripts de terceros** son scripts que no escribiste tu: analytics (Google Analytics), chat widgets (Intercom), ads (Google Ads), tracking pixels. Cada uno agrega peso al bundle y compite por CPU y red.

### Paso 1 — Instalar web-vitals

1. Abre la terminal en VS Code en la carpeta de tu proyecto
2. Instala la libreria:
   ```bash
   npm install web-vitals
   ```
3. Crea un archivo para la medicion. En Angular, abre `src/main.ts` y agrega al final:
   ```typescript
   // src/main.ts (agrega esto despues del bootstrapApplication)
   import { onLCP, onCLS, onINP } from 'web-vitals';

   function reportarMetrica(metrica: { name: string; value: number; rating: string }) {
     console.log(`[Web Vital] ${metrica.name}: ${metrica.value.toFixed(2)} (${metrica.rating})`);
   }

   onLCP(reportarMetrica);
   onCLS(reportarMetrica);
   onINP(reportarMetrica);
   ```
4. Este código se ejecuta en el navegador del usuario y reporta las metricas reales a la consola

> 💡 **Nota:** `rating` puede ser "good", "needs-improvement", o "poor". Es la clasificacion de Google para esa metrica.

### Paso 2 — Capturar metricas reales

1. Ejecuta `ng serve` y abre tu app en Chrome
2. Abre DevTools → Console
3. Navega por tu app normalmente: haz click en links, scroll, interactua con formularios
4. Observa los mensajes `[Web Vital]` en la consola:
   ```
   [Web Vital] LCP: 1234.56 (good)
   [Web Vital] CLS: 0.05 (good)
   [Web Vital] INP: 120.00 (good)
   ```
5. Anota estos valores — son tus metricas reales
6. Para simular un dispositivo lento:
   - En DevTools → Performance, haz click en el engranaje
   - En **CPU**, selecciona **4x slowdown**
   - En **Network**, selecciona **Slow 3G**
   - Recarga la página y observa las metricas — seran peores que sin throttling

### Paso 3 — Ejecutar Lighthouse para comparar

1. En Chrome DevTools → Lighthouse, ejecuta un analisis de Performance en modo Mobile (como en la Actividad 5.1)
2. Anota los valores de LCP, CLS e INP que Lighthouse reporta
3. Compara con los valores de `web-vitals` del paso anterior

### Paso 4 — Auditar scripts de terceros

1. En DevTools → Network, recarga la página
2. Ordena por **Size** (tamaño) de mayor a menor
3. Busca scripts que no son de tu dominio:
   - URLs con `google`, `facebook`, `analytics`, `intercom`, `hotjar`, etc.
   - Scripts cargados desde CDNs externos
4. Para cada script de tercero, anota:
   - URL del script
   - Tamaño (Size)
   - Tiempo de carga (Time)
5. Para medir el impacto real:
   - En DevTools → Network, haz click derecho en un script de tercero
   - Selecciona **Block request URL**
   - Recarga la página y ejecuta Lighthouse de nuevo
   - Compara el puntaje con y sin ese script

### Paso 5 — Documentar discrepancias

Crea un archivo `medicion-real-vs-sintetico.md` en la raiz de tu proyecto:

```text
# Medicion Real vs Sintetico

## Metricas sinteticas (Lighthouse)
- LCP: X.XXs
- CLS: X.XX
- INP: X.XXms
- Performance Score: XX/100

## Metricas reales (web-vitals)
- LCP: X.XXs
- CLS: X.XX
- INP: X.XXms

## Metricas reales con throttling (CPU 4x + Slow 3G)
- LCP: X.XXs
- CLS: X.XX
- INP: X.XXms

## Discrepancias encontradas
1. **[Metrica]:** Lighthouse dice X, web-vitals dice Y.
   - Causa probable: [explicacion]

## Scripts de terceros
| Script | Tamano | Impacto en score |
|--------|--------|-----------------|
| [url]  | XX KB  | -X puntos       |

## Conclusiones
- [Que aprendiste de la diferencia entre sintetico y real]
```

## Que puede salir mal

- **"No veo ningun mensaje [Web Vital] en la consola"** → Las metricas se reportan en momentos especificos: LCP se reporta cuando el elemento mas grande termina de renderizar, CLS se acumula durante toda la sesion, INP se reporta al interactuar. Navega la página, haz click en cosas, y espera unos segundos.
- **"Mis metricas de web-vitals son mejores que Lighthouse"** → Es normal si estas midiendo en tu computadora potente. Lighthouse simula un dispositivo móvil lento. Activa el throttling de CPU y red para una comparacion mas justa.
- **"No tengo scripts de terceros"** → Si tu app no tiene analytics ni widgets externos, documenta eso. Es una buena practica tener cero scripts de terceros en desarrollo. En produccion, agrega solo lo necesario y mide su impacto.

## Resultado esperado

Al terminar, entiendes que Lighthouse y las metricas reales pueden contar historias diferentes. Tienes `web-vitals` instalado para capturar metricas reales, y un documento que compara ambas mediciones con sus discrepancias explicadas.

**Criterios de aceptacion:**
- [ ] `web-vitals` instalado y reportando metricas en la consola
- [ ] Se identifican scripts de terceros y su impacto en el rendimiento
- [ ] Se documenta al menos una diferencia entre Lighthouse y RUM con su causa probable
